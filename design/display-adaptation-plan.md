# ClassNode 界面适配与显示优化设计提案

日期：2026-10-11。状态：待评审的设计提案，尚未修改应用代码。

本提案保留 `teacher-ui-system-v2.md` 的稳定工作台结构，调整字号、配色与宽度策略。当前教师候选采用暖灰与柔和蓝，少量辅助色点缀；学生端独立采用面向小学、初中学生的轻快学习界面。教师不增加显示模式。原 v2 文档暂不修改，待方案确定后同步。以下数值均为初始设计目标，需要浏览器与真实设备验证，不代表已经完成的视觉验收。

## 1. 现状与设计判断

本轮审查依据为源码和已有设计规范，未进行真实笔记本、iPad 或投影仪实测。

- 全局基础字号为 16px，但教师端导航约 14px，普通按钮和输入框为 14px，历史记录中的部分操作和说明约 11–13px；智能体配置中也存在 9–12px 的文字。基础字号不能代表最终显示字号。
- 学生端聊天正文目前约 16px，但消息操作约 11px、推荐问题约 12.5px；顶部导航在 860px 以下缩到 12px。学习单进度和保存状态约 12–12.5px。新增功能需要纳入同一套阅读规范。
- 教师端背景 `#F4F6F8`、次级表面 `#F8FAFB`、浅选中底 `#EDF2F6` 都接近白色。投屏时的层级丢失与用户反馈吻合，但设备、环境光与投屏方式的具体影响尚未实测。
- 教师主区域有 1484px 的最大宽度限制，折叠侧栏时另有 1464px 的内联限制；关于页和指南页还各有内容宽度。现有窄屏适配部分依赖覆盖内联样式，规则需要统一。
- CSS 像素、系统显示缩放、浏览器缩放、投屏输出和观看距离共同影响体验。不能仅根据设备物理分辨率放大，也不能仅凭屏幕英寸决定断点。

设计方向：清晰、温和的课堂工作台，暖灰与柔和蓝形成主要层级，少量辅助色点缀；学生端以 iPad 阅读和触控为主要目标。保留稳定的操作结构，降低高密度排布造成的阅读负担。

## 2. 教师端统一字号规范

教师端采用唯一的默认显示方案，兼顾笔记本操作和日常投屏。不增加显示模式、切换入口或偏好设置。通过默认字号、明暗层级和响应式排布提高可读性。

| 元素 | 默认目标 |
| --- | --- |
| 页面标题 | 28px |
| 分区标题、弹窗标题 | 20–22px |
| 正文、表格正文、字段标签 | 16px |
| 导航、按钮、输入文字 | 16px |
| 辅助说明、时间、分页 | 14px |
| 数量标签 | 14px |
| 关键统计数字 | 32–40px |
| 课堂码 | 64–80px |

- 需要阅读或操作的文字以 14px 为下限；12px 仅用于版本等非关键元信息。课堂中持续关注的学生姓名、核心状态和关键结果可使用 18–20px，按信息重要性区分，而非按显示模式区分。
- 正文行高 1.55–1.7，长说明 1.7–1.8；按钮行高约 1.25–1.4。正文保持正常字重，导航和按钮适当加粗到 500–600，标题 600–700。
- 按钮高度约 44px；输入框约 46px；表格行高约 52–56px，允许长内容自然增高。
- 弹窗、抽屉、Toast、图表轴标、图例、Markdown、题目预览及动态浮层统一应用字号角色，不能仅放大页面外层。
- 空间不足时优先减少卡片列数、工具栏换行、减少图表同时出现的标签，保留可读字号。
- 日常投屏纳入默认方案的真实设备验收；远距离观看的效果还受屏幕大小和观看距离影响，需在典型教学环境验证。

## 3. 教师端色彩与区域层级

当前候选依据最新反馈收敛为“暖灰底色 + 柔和蓝强调”。不使用偏绿的主题底色，撤回此前青绿、赭金、灰紫大面积并列配色。效果见 `display-mockups-v3/`；保留原有布局、字号和分区结构。

| 角色 | 统一方案候选 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#EEECE7` | 温和的暖灰，避免明显黄调 |
| 侧栏背景 | `#E5E7EA` | 中性灰，不带绿色 |
| 内容表面 | `#FFFFFF` | 承载表格、表单和长正文 |
| 标题栏、表头 | `#E1E8F0` | 浅蓝底配深色文字，替代深色实心标题栏 |
| 通用工具区 | `#ECEFF2` | 中性浅灰，与数据区区分 |
| 普通边框 | `#B8C3CE` | 保持可见区域边界 |
| 主文字 | `#293440` | 深色正文，不随背景一起调浅 |
| 次文字 | `#586574` | 说明和元信息保持清晰 |
| 主操作 | `#527495` | 柔和蓝，需验证白字对比度 |
| 辅助点缀 | 淡紫、浅沙色 | 少量图标、类别标识或图表系列，不铺满分区 |

- 同一页主要使用中性色与柔和蓝，不让每个区块都有独立大面积颜色。
- 表头和卡片标题栏统一浅色底、深色字；保留明确底色差、分隔线和间距，避免再次变成白色区域难以区分。
- 主要按钮仍用实色强调；次级操作使用描边或文字按钮。选中态保留清晰边框、底色与标记。
- 模块区别主要通过名称和图标表达，少量淡紫与沙色辅助识别；图表的不同系列可使用区分色，不强制全部蓝色。
- 绿色仅表示在线、成功等明确状态；橙色和红色继续表示需关注与危险，始终配合文字或图标。
- 独立业务区保持约 20–24px 间距；卡片内用标题、分隔线和 12–16px 间距组织信息，避免层层套卡。
- 保留教师全站统一默认界面，不增加显示模式。
- 候选色按最终实际组合校验对比度，普通文字至少 4.5:1，关键正文与数据以 7:1 为目标，并进行真实投屏验证。

## 4. 教师端宽度策略

外壳填满浏览器可用宽度，侧栏以外的主区域不再统一设置较小的宽度上限；内容是否限宽由页面用途决定。

| 页面类型 | 页面范围 | 宽度与排布 |
| --- | --- | --- |
| 管理与数据 | 课堂列表、班级、头像、学习单、探究空间、智能体、历史、安全、仪表盘 | 使用全部可用宽度；卡片列数按主内容区宽度及最小卡片宽度决定 |
| 课堂看板 | 实时课堂、统计、分析覆盖层 | 使用全部可用宽度；提供全屏；主内容与辅助面板能重排 |
| 创建与编辑 | 新建课堂、智能体配置、学习单编辑 | 常规表单约 960–1120px；学习单编辑使用宽工作区，必要时收起辅助面板 |
| 阅读 | 使用指南、关于 | 正文约 800–960px 居中；导航、目录及多栏说明可以更宽 |

- 教师视口以 1280–1536px 宽为主要设计区间，同时覆盖 1024px 和宽屏。侧栏约 224–240px，折叠态约 72px。
- 初始断点建议：1280px 及以上通常展开侧栏，1024–1279px 默认折叠，1024px 以下采用紧凑导航。用户手动选择可以在空间足够时优先保留。
- 卡片最小宽度建议约 320px，再依据内容长度与操作数量调整；列数由可用宽度决定，不固定所有页面的列数。
- 仪表盘统计可在空间充足时四列，空间不足变两列；业务卡片单独判断，避免强行套用同一断点。
- 页边距约 24px，窄屏约 16–20px。区块间距足以区分结构，同时避免大幅增加留白浪费显示面积。
- 表格在不足以展示全部列时隐藏次要列或在表格自身横向滚动；整页不应被长内容撑宽。姓名和主要操作保持容易定位。
- 工具栏允许换行；长标题允许换行；关键字段不能为了排成一行而持续缩字。
- 短窗高和浏览器放大后，弹窗内容可滚动且底部操作可达；抽屉不能遮住唯一主操作。

## 5. 学生端阅读与触控规范

### 独立视觉风格

学生端与教师端共享品牌和基本交互含义，分别设计视觉风格。面向小学、初中学生，采用轻快、友好、有探索感的学习界面。当前学习单候选见 `student-mockups-v4/`，替代 v3 学生稿作为最新评审方向。

- 基底为柔和米白，蓝色承担主要操作和选中态，浅紫与少量暖橙辅助模块辨识；教师端的配色收敛规则不直接套用学生端。
- 模块入口使用容易辨认的图标和明确标题，学习内容卡片采用约 18–22px 圆角，选项约 14–16px 圆角。
- 在课程标题、模块入口和空状态使用少量相关插画；题目正文区保持白底深字。插画不挤占读题和作答区域。
- 保持对初中生也合适的现代风格，用课程图形、工具和现有头像增加趣味，避免满屏幼儿化装饰。
- 通过清晰的作答选中、保存和提交反馈增强参与感，不因视觉改稿额外引入积分、排行榜或新奖励功能。
- 色彩、插画与动效服从阅读需求；保持下述字号和触控目标，并覆盖学生主页、学习单、探究空间、智能学伴及辅助状态。

### 阅读与触控

学生端默认即是舒适阅读规格，不依赖学生主动打开放大选项。桌面使用同一文字层级，主要改变列数和内容组织。

| 元素 | 默认目标 |
| --- | --- |
| 模块或页面标题 | 24–28px |
| 题干、选项、聊天正文 | 18px |
| 输入文字、操作按钮 | 18px |
| 导航、姓名、模块入口 | 16–18px |
| 提示、保存状态、进度说明 | 16px |
| 时间等非关键元信息 | 14px |

- 长阅读正文行高约 1.7–1.8，题干和选项约 1.55–1.7。长阅读区初始限宽约 760–880px，图形、表格和画布可以单独占用更宽空间。
- 常用触控目标至少 44×44 CSS px，主要操作建议 48px 高；相邻操作保持约 8px 以上间距。实际按钮图标可以小于点击区域。
- 顶部导航在 iPad 竖屏下改为两行：课堂及个人状态一行，三个学习模块一行；横屏空间充足时恢复单行。极窄分屏下模块导航可局部滚动，不能靠缩到 12px 保持单行。
- 姓名可截断并提供触控可达的完整信息；连接状态、保存失败和提交结果不依赖悬停提示。
- 竖屏题目优先单列；横屏在题目类型和内容长度适合时两列；长阅读和聊天不因桌面更宽而无限拉长。
- 学习单逐项覆盖选择、填空、排序、分类、表格、流程图、几何与绘画功能，以及奖励和提交弹窗。题目中的标签、工具条、图形节点和公式不能遗漏。
- 表格和画布空间不足时局部滚动或提供缩放；“适应画布”导致标签过小时，提供恢复可读比例的操作。不能只提高外部 CSS 字号却让画布变换再次缩小文字。
- 软键盘出现时保持输入区域与发送、保存或提交操作可达，不让固定底栏遮住输入位置。
- 尊重浏览器缩放，并保留现有 Safari 15 / 老 iPad 的兼容目标；新布局不能仅依赖该环境不支持的特性。

## 6. 覆盖范围与实施顺序

1. 建立师生各自的字号角色、表面颜色、控件尺寸和容器规则。共享组件按端区分显示语义，避免教师改动意外改变学生界面。
2. 教师侧栏、页首、按钮、输入框、表格、标签、Toast、弹窗和抽屉先统一；用班级管理、智能体配置、课堂看板验证密集列表、表单和实时数据三类场景。
3. 将统一配色和字号扩展至教师全部管理页、阅读页及登录、首次设置和密码修改状态；验证区块层级在日常投屏下仍然清晰。
4. 学生外壳和导航先重排，再覆盖主页、聊天、探究、学习单、头像、奖励、加入课堂、等待、暂停和错误等页面与状态。
5. 检查字体放大后的长内容、图表、第三方画布、Markdown、公式、附件、空状态、加载、错误与禁用状态；清理遗漏的小字号和局部颜色。

## 7. 验收矩阵

以下为 CSS 视口测试尺寸，并非设备物理分辨率或所有机型的固定尺寸。

- 教师：1024×768、1280×720、1366×768、1440×900、1536×864、1920×1080；统一默认方案分别在本机和投屏下检查，并测试浏览器 125%、150% 及 200% 缩放后的重排与操作可达性。
- 学生：768×1024、810×1080、820×1180，以及对应横屏；桌面 1280×1024、1366×768、1440×900、1920×1080；另外检查分屏和软键盘出现状态。
- 实机：Windows 笔记本 Edge / Chrome、MacBook Safari / Chrome、普通 iPad Safari；至少一种真实投影或大屏投屏，使用教室日常环境光和典型观看位置。
- 长内容：较长班级名、长姓名、长按钮说明、较长题干、较多列的表格、密集图表与节点标签。
- 可见性：常用文字达到设计下限；状态不只依赖颜色；重要区域在真实投屏上仍能区分；学生不需要手动放大才能读题和操作。
- 布局：页面外壳不出现非必要横向滚动；局部表格和画布的滚动可发现；关键按钮、输入和弹窗底部操作不被裁切；浏览器放大不丢失功能。
