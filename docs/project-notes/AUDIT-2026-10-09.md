## 优先问题

### 1. [P1] 桌面升级先删除旧列，导致分组智能体绑定无法迁移

位置：`src-tauri/src/lib.rs:340`、`:352`；`server/src/services/group-materials-migration.ts:49`；`server/src/index.ts:659`。

桌面壳在启动 Node 前执行最新 schema 的 `prisma db push`，遇到数据损失提示后自动带 `--accept-data-loss` 重试。旧版 `ClassroomGroup.agentId` 因此先被删除。随后 Node 的材料迁移按该列存在与否判断是否需要迁移，结果写入 `skipped`，旧组的智能体没有搬到 `ClassroomGroupMaterial`。这会让升级前有绑定的高级课堂失去智能体；安全备份存在，但不会自动恢复绑定。

临时真库复现：给分组添加旧 `agentId` 并清空材料表 → 按桌面顺序执行 db push → `ensureGroupMaterials` 返回 `skipped`，智能体材料行数为 0。建议先执行旧数据搬迁，再执行会删列的结构同步；加入覆盖整个桌面升级顺序的测试。

### 2. [P1] 新“移出班级”遗漏分组名册，新课堂仍带入已移出的学生

位置：`server/src/routes/classes.ts:252`；`server/src/routes/classroom.ts:480`、`:663`；`src/app/teacher/classes/page.tsx:2014`。

移出只把 `Student.classId` 置空，没有从 `ClassGroup.studentIds` JSON 中移除该 ID。创建普通分组课堂和高级课堂时，又只按成员 ID 查询 Student，没有限制其仍属于当前班级。移出后学生行仍存在，因此继续被写入新课堂的成员快照；分组管理的计数也保留这个看不见的成员。

临时真库与真实路由复现：移出返回 200，新建分组课堂返回 200，已移出学生的 `ClassroomGroupMember` 行数仍为 1。建议在事务中同时清理班级分组名册，并在两处创建课堂查询中添加 `classId` 条件；保留已创建课堂的历史快照。

### 3. [P1] 学生可绕过定向通知过滤，读取其他人的私信

位置：`server/src/index.ts:730`；`server/src/routes/classroom.ts:1817`。

学生 token 请求本课堂 `/notifications` 时，省略 `studentId` 会被权限门放行。路由只在该参数为字符串时追加接收人过滤，因此省略它会返回最近 100 条全班通知，包含定向给其他人的通知。应从已验证会话取得接收人 ID，而不是依赖可省略的查询参数；同时处理分组通知范围。

### 4. [P1] 托管教学网页可以使用教师登录态访问主服务 API

位置：`server/src/index.ts:101`；`server/src/middleware/auth.ts:22`；`src/lib/webapp-sandbox.ts:11`。

托管网页使用同主机的不同端口，并具有 `allow-scripts allow-same-origin`。cookie 不按端口隔离；主 API 的 CORS 又反射任意 Origin 并允许 credentials。教师登录后预览的教学网页可通过带凭据的 fetch 读取/修改主源 API。HttpOnly 只阻止脚本直接读取 cookie，不阻止浏览器携带它。该结论来自配置与访问链检查，本次未执行浏览器攻击演示。

建议允许明确的教师前端 Origin，拒绝托管网页 Origin 对教师 API 的访问，并为写操作增加来源校验；开发时保留实际前端端口。

### 5. [P1] “含附件”的备份遗漏教学网页文件

位置：`server/src/routes/export.ts:471`、`:632`；`server/src/services/webapp-host.ts:65`。

备份只打包数据库、chat/avatars/logos 和加密密钥，没有打包独立的 `webapps/` 目录；恢复也不处理它。迁移到新设备后，数据库里的网页记录和课堂关联仍存在，但网页文件不存在。建议把网页目录纳入备份、恢复和失败回滚流程，并验证跨目录恢复后的网页实际可访问。

### 6. [P1] 本机数据库尚未适配最新提交，移出操作会失败

位置：`server/prisma/schema.prisma` 的 Student；`server/src/routes/classes.ts:252`。

只读检查 `server/prisma/dev.db` 的 `PRAGMA table_info(Student)`：`classId.notnull = 1`，而最新代码写入 null。运行时自动对齐没有修改可空性的迁移，新功能在当前开发数据库上会报 500。最新提交说明已提示手动 db push，本次确认这一部署步骤仍未完成。

建议先备份再同步本机 schema，并给源码部署/启动流程提供可重复执行的迁移入口。本次没有为审计直接修改真实数据库。
