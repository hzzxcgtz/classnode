# 扣子低代码音频输入验证

日期：2026-10-23（Asia/Shanghai）。已完成真实 API 验证、录音试听界面，以及 Ogg/Opus 上传发送与文字回复链路。真实麦克风和学生设备仍需验收。

## 目标与结果

用户确认需要“用户直接录音并上传”，并选定本地配置中的“图语小伴”做测试。本地数据库确认其 platform 为 `coze`（扣子低代码），不是 `coze-agent`（扣子编程）。

**结果：已通过一次真实 API 验证。** 发送的用户消息只有音频引用，没有提供录音内容的文字副本。智能体正确回答了录音中的算术问题，也包含了指定词语。

## 测试内容

- 使用 macOS 合成无个人信息的中文测试语音，未录制用户或学生的麦克风。
- 文本：“这是语音输入测试。请回答七加八等于多少，并在回答中包含蓝色气球这四个字。”
- 文件：WAV，单声道、16000 Hz、16 位，约 8.16 秒，265230 字节。
- 凭据：复用项目当前凭据选择规则，在进程内读取与解密，未输出 Token。
- 使用随机独立 `user_id`，未指定现有 conversation，设置 `auto_save_history: false`；未写入本地课堂消息、未变更智能体配置。

## 实测链路

1. 后端 `POST https://api.coze.cn/v1/files/upload`，multipart 字段为 `file`，上传 WAV。
2. 收到 HTTP 200、`code: 0` 和 `data.id`。
3. `POST https://api.coze.cn/v3/chat`，设置目标 `bot_id`、独立 `user_id`、`stream: true`。
4. `additional_messages` 中发送 `role: user`、`type: question`、`content_type: object_string`，其中 `content` 为下述数组的 JSON 字符串：

```json
[{"type":"audio","file_id":"<上传接口返回的 data.id>"}]
```

5. 响应为 HTTP 200、`text/event-stream`，收到 `conversation.chat.completed`，无业务错误。

智能体文字回复：

> 7+8等于15，就像两个小朋友手拉手一起数，7个小糖果加上8个小糖果，最后得到的总数呀，就像天空中飘着的蓝色气球那样清晰，是15哦～

响应包括 49 个 `conversation.message.delta`、5 个 `conversation.message.completed`、99 个 `conversation.audio.delta`。除文字答案外还有追问建议。音频片段本轮仅统计，未解码或播放，因此尚未验证回复音频的播放效果。

接口返回用量：input_count 1769、output_count 49、token_count 1818；未查询具体账单金额。

上传请求排障 LogID：`202610232111011ECAEF5CAA35F38D9C13`。

## 测试过程中的无效样本

第一次 macOS 语音合成受到本机沙箱限制，生成了没有采样帧的 4096 字节 WAV 外壳。上传成功，但对话返回 failed，不能据此判断音频能力不支持。随后重新生成并确认有效采样帧，再完成上述成功测试。测试脚本已加入音频数据非空检查，以避免用空文件继续调用。

## 对 ClassNode 的实际含义

- **低代码路线无需让扣子直接访问 ClassNode 局域网 URL。** ClassNode 后端将本地音频上传到扣子，取得 file_id 后调用对话即可，不必为这条链路额外配置公网对象存储。
- 学生端可以直接发送音频，不必预先转写成文字供学生确认。该实测证明端到端理解有效，但不证明扣子内部采用原生音频模型还是先转写。
- 当前 `coze-bot/file.ts` 已有 WAV 上传能力；现有普通聊天多模态构造主要按图片处理，需专门增加 audio 类型，避免把语音标为 image。
- 当前 `coze-bot/chat.ts` 对 `conversation.audio.delta` 明确忽略。第一版可先显示文字回复，后续再增加语音播报。
- 本轮只验证该智能体和该 WAV 格式；其他智能体、浏览器录音格式、长音频及多人并发需单独验收。

## 已实现（第三步）

- 学生端仅为 `coze` 低代码智能体显示麦克风，可录音、停止、试听、下载、删除、重新录制和发送。
- 用户确定每次最多5分钟，这是 ClassNode 产品限制，非扣子平台限制。请求单声道、目标码率32 kbps，5分钟纯码流约1.2MB，含封装和实际编码波动会略有差异。
- 采用 `audio/ogg;codecs=opus`。浏览器原生支持时用 MediaRecorder；否则按需加载 opus-media-recorder 0.8.0，Worker 和 WASM 固定版本随网站本地发布，无 CDN、系统 FFmpeg 或公网文件存储依赖。
- 上传仍走学生会话鉴权 `/api/upload`，校验 Ogg/Opus 文件头，复用现有文件归属、课堂目录、20MB上限和孤儿文件清理；Socket附件白名单同步支持 `.ogg`，其他平台拒绝语音消息。
- 后端将文件上传扣子取得 file_id，构造 `type: audio` 的 object_string 消息，使用 stream=true。聊天记录中的 `(语音)` 是本地显示占位，不作为本轮文字指令发送。音频上传失败会终止调用，避免只发送占位文字。
- 发送语音保留输入框中的未发送文字/附件，录音关闭、切换身份/智能体/课堂或模块停用时取消未完成上传。学生及教师课堂消息支持播放录音。
- Express 的 Permissions-Policy 改为 `microphone=(self)`，允许同源页面申请麦克风。
- 本轮显示智能体文字回复，尚未实现回复语音播放。

## iPad 输入交互调整

用户确认主要问题是点击步骤多，希望按住说话、松开发送；主要设备为 iPad。

- 当前默认是文字输入，旁边的“语音”按钮可切换到直接录音发送，保留未发送文字和附件。语音模式下禁止自动聚焦隐藏输入框，以免 iPad 键盘打断录音。
- 按住录音，松开发送；向上移动64 CSS像素进入取消状态，移回可恢复发送意图。触摸取消、丢失捕获、后台、页面离开或窗口失焦均取消录制。指针正常松开后的隐式捕获释放不会误取消已经开始发送的音频。

- 使用 Pointer Capture，录音按钮局部设置 touch-action:none、禁止文本选择和长按菜单；其他区域仍可滚动。
- 浏览器以合成音源验证真实组件及Worker/WASM：按住1.5秒后发送计数从0变1；点按开始/发送后变2；轻点后仍为2并提示太短。没有录制真实麦克风，没有向智能体发送本次UI测试音频。

## 本地人声检测与流式错误保留（2026-10-24）

- 录音复用已授权的同一个 MediaStream，通过 `@ricky0123/vad-web@0.0.31` / Silero v5 判别人声，使用固定 `onnxruntime-web@1.22.0` 单线程 WASM。模型、worklet 和运行资源约13MB，位于 `public/vendor/silero-vad-0.0.31/`，包含许可证，检测不访问CDN或上传音频。
- 人声检测在录音开始前初始化，初始化最长等待8秒；失败、超时、数据不完整均放行。录音结束/取消后释放检测节点、AudioContext和原麦克风。权限仍由浏览器决定，不额外申请麦克风，也不保留麦克风以规避授权。
- Silero v5每帧32ms。仅当录音>=700ms、分析覆盖>=80%、没有任何帧人声概率>=0.08、至少95%帧概率<0.05时拦截，提示“没有听到你说话，请再试一次”。这不是识别内容意义，也不能区分本人、同学、电视的人声；不确定时优先放行。
- 扣子创建对话与提交工具流统一解析SSE；支持UTF-8跨块、CRLF、多行data和末尾无换行。`conversation.chat.failed` / `error` / HTTP200 JSON业务错误优先抛出CozeStreamError，保留code、msg、logid、conversationId、chatId；不再用“未返回完成事件”覆盖上游原因。
- 真正缺少完成事件时使用incomplete_stream，附带最后事件名及追踪编号。HTTP非2xx同时保留HTTP状态和原业务码。Proxy记录结构化诊断信息并将原错误码/原因传回本地调用方，不记录请求令牌、完整事件流或录音数据。
- 单元和模拟上游测试中的730001仅为合成测试码，不能当作扣子真实静音错误码；真实错误会在后续请求失败时被准确捕获，不根据“静音”主观猜测或替换所有失败原因。

依据：https://docs.vad.ricky0123.com/user-guide/api/ 、https://docs.vad.ricky0123.com/user-guide/browser/ 、https://docs.coze.cn/developer_guides_chat_v3 。
