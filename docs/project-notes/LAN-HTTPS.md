# 局域网 HTTPS 与 iPad 录音

实现日期：2026-10-24。功能默认关闭，不自动向任何设备安装或信任证书。

## 教师操作

1. 在“课堂管理”页进入“iPad 录音设置”（`/teacher/network/`）。
2. 点击“启用 HTTPS”。保持局域网访问开放，并保证学生与教师在同一局域网。
3. 先让一台 iPad 用系统相机扫描课堂二维码，再在 Safari 中进入 HTTPS 学生端，允许麦克风后试录。已经能正常录音的设备无需重复设置。若出现证书警告，先扫描安装引导二维码，下载 ClassNode.mobileconfig，设置中安装，然后在“通用 → 关于本机 → 证书信任设置”开启对应根证书的完全信任。
4. 核对教师端与安装页显示的 SHA-256 指纹。描述文件是未签名的配置容器，只含根证书，不含 MDM、VPN 或私钥。
5. 安装完成后用正常课堂二维码进入 HTTPS 学生端，再允许麦克风，录制短音频验收。之后再部署其他 iPad。学校管理设备可通过 MDM / Apple Configurator 批量配置。

原有 HTTP 教师和学生地址保持可用，HTTP 局域网网页仍不能调用麦克风。启用后正常课堂二维码优先使用 HTTPS。

## 实现与边界

- 普通主服务端口为 `PORT`（默认3001），探究空间为已有 `CLASSNODE_WEBAPP_PORT`（默认主端口+1）。新增 HTTPS 主端口默认为主端口+2，探究空间 HTTPS 为主端口+3；分别可用 CLASSNODE_HTTPS_PORT / CLASSNODE_WEBAPP_HTTPS_PORT 覆盖，四端口不得冲突。
- 当前开发环境为 HTTP4001/托管4002、HTTPS4003/托管4004，开发前端仍使用HTTP4000。HTTPS学生端由主服务同源提供 out/ 静态构建，需先 pnpm build。分发版使用已有 frontend/ 资源。
- HTTPS层转发原始 request/upgrade 对象给现有HTTP服务，不做loopback代理、不复制Socket.IO实例；保留真实远端IP、TLS属性、LAN访问门、教师/学生会话与实时广播。
- 来源检查按真实TLS连接辨别协议；HTTPS探究空间使用独立端口，并与HTTP托管源一样禁止访问主站API。HTTPS教师会话Cookie带Secure。API、上传和Socket在HTTPS学生页使用当前同源，避免mixed content。
- 学生课堂元数据新增webappHttpsPort，HTTPS课堂iframe使用该端口，HTTP课堂保持原端口。独立托管服务的安全隔离策略不变。
- 固定根证书保存在 CLASSNODE_DATA_DIR/lan-https；未设置时为 server/lan-https。根证书RSA3072、SHA256、约10年；服务证书RSA2048、SHA256、90天，含localhost与当前局域网IP的SAN和serverAuth用途。最低TLS1.2。
- 每30秒检查IP/续期条件，必要时只重签服务证书并热更新TLS上下文。根证书缺失、损坏或被运行中替换时，拒绝自动换根，避免悄悄使学生端信任失效。更换IP后学生仍需使用新地址/二维码。
- HTTPS配置与根证书位于用户数据目录，普通升级和课堂数据恢复不会覆盖它们。现有课堂备份不包含lan-https：迁移/重装教师机时请单独安全保留该文件夹，其中含CA私钥，不能分享给学生。根证书过期/更换后需重新部署信任。
- 对外只提供公开的mobileconfig和根证书；没有私钥下载接口。安装引导仍可通过HTTP打开，以免尚未信任证书时无法安装。请通过教师端核对指纹。
- TLS端口启动失败时回滚新增监听，不影响原有HTTP。HTTPS关闭会断开该入口上的连接；证书和配置身份保留。启用状态会在重启后恢复。

## 验证

- 证书/原生TLS集成测试：重复启动根身份不变；IP变化仅换服务证书；根损坏/丢失不重建；未信任的TLS客户端拒绝握手，显式信任测试CA后验证通过。
- 同一Socket.IO实例中的HTTP与HTTPS客户端相互广播通过；HTTPS探究空间独立服务通过，跨源API被拒；未授权教师管理请求被拒，HTTPS教师Cookie带Secure；公开profile不含私钥。
- 前端API同源回归、完整前后端测试、生产构建和Safari15静态兼容检查已执行，具体结果见本次工作记录。
- 真实iPad证书安装、系统信任和麦克风硬件仍需由用户验收。自动化测试不会安装系统根证书，也不会绕过浏览器安全警告。

## 设备反馈与界面调整（2026-10-24）

- 用户报告 iPhone 在 `https://192.168.6.130:4003/classroom/` 未手动安装证书、允许麦克风后可正常录音；是否曾出现证书警告不明确。仅记录当前设备的实际表现，尚不能推断 Safari 如何接受该证书，也不能推广至所有 iPad。麦克风权限与 TLS 信任是两项独立条件。
- 设置页改为先试录、遇证书问题再安装；证书指纹、下载、迁移及批量部署说明默认折叠。入口补充麦克风图标，保留原有页面路径与 HTTPS 管理逻辑。

## 设置入口导航（2026-10-24）

用户报告“iPad录音设置”需要点击两次。该新入口原来是普通a链接，已与课堂管理其他动作统一为Next客户端router.push；返回课堂管理也走同一跳转方式，保留教师布局及会话，避免整页重新加载。隔离应用中已验证一次点击进入设置页、一次点击返回；真实触屏设备需刷新加载新页面后复核。后续新增教师端内部入口优先沿用现有客户端导航方式。

## Safari 网站麦克风授权说明（2026-10-24）

教师设置页与学生安装引导均已补充：先用 Safari 打开 HTTPS 学生课堂，再通过地址栏“页面菜单”（旧版 aA，部分版本先进入更多）→ 网站设置 → 麦克风，将询问改为允许。设置对象应为实际课堂网站，不是 HTTP 安装引导页。更换访问地址后可能重新授权；安装根证书不等于授予麦克风权限。只说明当前网站设置，不引导全局允许所有网站。

官方依据：<https://support.apple.com/zh-cn/guide/ipad/ipad8ea0fc1a/ipados>，网站权限与特定网站例外说明。
