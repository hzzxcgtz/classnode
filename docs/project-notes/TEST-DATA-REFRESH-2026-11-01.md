## 验收顺序

1. 学生扫码登录新版课堂，检查已有录音草稿的试听、重录、删除、点按与按住录音；普通填空和表格分别检查，表格宽度不应随录音状态改变。
2. 点击提交。客观练习自动判分；调查题只收集；主观题及 AI 表达空自动评价。只评价不计分的题不能发放奖励。部分作答、偏题与静音录音须区别处理。
3. 等待真实个人评价成功，再从教师端生成全班分析。单纯预填或保存草稿不产生可用于班级汇总的个人评价；这不是分析接口故障。
4. 有个人评价后，验证作答与评价两个讲评标签页、放大缩小、每次滚轮最多 3 个百分点、图片移动、批注恢复、左右停靠及工具栏宽度。刷新后验证批注持久保存。新课堂不预填批注。
5. 使用个别学生的重新提交、补评检查匹配逻辑；更换智能体或修改标准作为独立场景，原有评价不能直接冒充新标准的评价。
6. 历史兼容继续用原有课堂（9782、1942、8470、3106、9962、2166、2167），不要把旧记录改写成新流程生成的评价。

旧种子脚本曾直接创建 `submitted` 评价快照；它们不表示外部 AI 已评价成功。此次不删除或篡改历史快照。原先“点一次全班分析即可逐生评分”的旧说明不再适用于新版验收流程。

## 重现与保护

脚本：`scripts/refresh-acceptance-data.mjs`。

```bash
# 仅检查与预演（创建完成后重跑会拒绝重复创建，以保护验收中的数据）
pnpm --filter classnode-server exec tsx ../scripts/refresh-acceptance-data.mjs
# 备份后生成；本机已执行，不要重复执行
pnpm --filter classnode-server exec tsx ../scripts/refresh-acceptance-data.mjs --apply
```

脚本限定本仓库 `server/prisma/dev.db` 和明确的旧验收样例，不自动选择生产数据目录。详细检查清单、创建 ID 和备份位置存于本机 `.dev/acceptance-current/manifest.json`。执行后已比对备份，原有 965 条作答、497 条评价及相关课堂、学习单、学生、智能体记录均保持一致。外部 AI 效果与真机录音需按上述步骤实际验收。
