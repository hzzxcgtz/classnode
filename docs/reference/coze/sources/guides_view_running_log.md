在扣子编程，你可以查看已部署的 AI 编程项目的运行日志、用户分析、运维监控和 Trace 详情，以便了解项目运行状况，并在出现问题时进行故障排查。本文介绍查看这些数据的方法。

:::tip 说明
在团队版和企业版中，企业超级管理员可以通过***功能访问控制​***和**空间资源可见性**，控制成员可见的功能入口和空间资源范围。如果你未看到预期的功能和资源，请联系企业超级管理员确认。更多信息，请参考[功能访问控制](/guides_team_config#hnd1HfjfQ)和[空间资源访问控制](/guides_team_config#hCId5unoV)。
:::

## **功能简介** {#d5034f91}

对于已经完成部署的 AI 编程项目，你可以进入**部署**模块查看以下线上运行信息：

* **日志**：查看项目的线上运行日志，并根据时间范围、日志级别和关键词筛选日志，开展问题排查和故障追溯。
* **分析数据**：查看项目的用户访问数据和运行指标。不同类型的项目支持的分析类别和指标可能不同：
   * **用户分析**：网页项目支持查看页面浏览量（PV）、独立访客数（UV）等访问数据。
   * **运维监控**：查看 CPU、内存、QPS、延迟和公网出流量等运行指标。
* **Trace 详情**：智能体和工作流类项目支持查看 Trace 数据，包括各节点的输入、输出和执行耗时等信息。你还可以将 Trace 数据导出为 Excel 文件保存到本地。

## **使用限制** {#0642c7c4}

日志保存时间、Trace 数据导出量、部署运维日志查询量等均存在限制。详情请参见[配额与限制](/guides/vibe_coding_limit)。

项目成功部署后才会产生线上运行日志和监控数据。项目刚完成部署或访问量较少时，部分指标可能暂时没有数据。

## 费用说明 {#80d18245}

Trace 日志的费用根据上报的日志存储量和存储时长计算。系统会自行在一段时间内上报一次 Trace 数据，并在上报时一次性收取费用。更多信息，请参考[Trace 日志费用（即将收费）](/coze_pro/trace_fee)。

:::notice 注意
自 2026 年 7 月 1 日起，扣子将对你上报的 Trace 日志收取相应费用。
:::

## 查看数据 {#88c1e508}

1. 打开[扣子编程](https://code.coze.cn/home?surl_token=FJvCs&zlink_code=FFKdE&utm_medium=docs&utm_source=docs&utm_content=landingpage&utm_id=&utm_campaign=&utm_term=docs&utm_source_platform=)，进入目标项目。
2. 在项目搭建页面右侧单击**部署**。
3. 根据需要选择以下页签：
   * **日志**：查看项目运行日志。
   * **分析**：查看用户分析和运维监控数据。
   * **Trace**：查看智能体或工作流的 Trace 数据。此页签仅在支持 Trace 的项目中展示。

:::notice 说明
不同项目类型展示的页签可能不同。例如，网页项目支持用户分析；Trace 主要适用于智能体和工作流类项目。
:::

## 看板和指标说明 {#caaec440}

### 日志 {#b6dfd700}

在**部署** > **日志**页面查看项目的线上运行日志。你可以使用以下条件筛选日志：

* **时间范围**：查看指定时间范围内产生的日志。
* **日志级别**：按 `Info`、`Warning`、`Error` 等级筛选日志。
* **关键词**：搜索日志内容中包含指定关键词的记录。

当项目运行失败或出现异常时，可以按以下步骤排查：

1. 选择异常发生的时间范围。
2. 选择 `Error` 日志级别，或搜索日志中包含的 `error`、接口路径、错误码等关键词。
3. 查看错误日志前后的相关记录，确认异常发生的时间和上下文。
4. 复制完整错误信息，在项目搭建页面通过对话让扣子 AI 协助分析和修复。
5. 修复并重新部署项目后，再次访问项目并检查日志，确认问题是否解决。

:::notice 说明
`Warning` 日志表示项目可能存在需要关注的问题，但不一定会导致项目运行失败。
:::

### 分析 {#9a1c49aa}

在**部署** > **分析**页面查看项目的线上运行数据。

分析页面根据项目类型展示以下一个或多个分析类别：

* **用户分析**：查看项目的页面访问情况，主要适用于网页项目。
* **运维监控**：查看项目实例的资源占用、请求压力和响应性能。

你可以选择**昨天**、**今天**、**过去 3 天**、**过去 7 天**或**过去 30 天**等时间范围。页面提供指标卡和趋势图：指标卡用于展示当前值或所选时间范围内的汇总数据，趋势图用于展示指标随时间的变化情况。

不同项目类型支持的指标可能不同，请以页面实际展示为准。

目前支持的主要指标如下：

<!-- @cols-width: 100,168,529 -->
| **类别**  | **指标**  | **说明**  |
| --- | --- | --- |
| 用户分析  | 页面浏览量（PV）  | 网页项目页面被访问的总次数。同一用户多次访问或刷新页面，都会重复计入 PV。  |
|^^| 独立访客数（UV）  | 在所选时间范围内访问网页项目的去重访客数量。通常同一访客在同一时间范围内只计为 1 个 UV。  |
| 运维监控  | 当前 CPU 使用率  | 当前时刻项目实例的 CPU 资源占用比例，用于反映实时计算资源使用情况。  |
|^^| 当前内存使用率  | 当前时刻项目实例的内存占用比例，用于反映实时内存使用情况。  |
|^^| 当前 QPS  | 当前每秒处理的请求总数，用于反映项目当前的请求压力。  |
|^^| 执行 QPS  | 所选时间范围内，项目每秒实际执行并返回结果的请求数量，用于反映服务的处理能力。  |
|^^| 错误 QPS  | 所选时间范围内，项目每秒产生的错误请求数量。例如错误 QPS 为 50，表示平均每秒有 50 个请求处理失败。  |
|^^| 延迟  | 线上请求的响应延迟，单位为毫秒（ms）。数值越低，通常表示响应越快。  |
|^^| CPU 使用率  | 所选时间范围内项目实例的 CPU 资源使用趋势，用于判断项目负载变化。  |
|^^| 内存使用率  | 所选时间范围内项目实例的内存使用趋势，用于判断是否存在持续的内存压力。  |
|^^| 公网出流量  | 所选时间范围内项目实例向公网发送的数据量，用于反映项目的对外数据传输情况。  |
|^^| 实例并发请求量  | 所选时间范围内单个实例同时处理的请求数量，用于反映实例的并发承载能力。  |
|^^| 请求数  | 所选时间范围内所有实例的请求总数。  |

:::notice 说明
监控数据上报和聚合可能存在一定延迟。项目刚完成部署、没有收到访问请求或处于暂停状态时，部分指标可能显示为 `0` 或暂无数据。
:::

### Trace {#c30c3414}

Trace 详细记录了智能体和工作流每次请求的执行过程，以及各节点的输入、输出和执行耗时。借助 Trace 看板，你可以跟踪请求的完整执行链路，定位发生异常的节点。

在**部署** > **Trace**页面查看智能体和工作流的 Trace 数据。你可以在页面左上角选择时间范围，并在页面右上角批量下载 Trace 数据。

![Image=683x375](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/a0636cf3d05a42dda6edd7bc9486a20b~tplv-goo7wpa0wc-topic.webp)

Trace 看板各指标说明如下：

<!-- @cols-width: 165,518 -->
| **指标**  | **说明**  |
| --- | --- |
| Trace ID  | Trace 记录的唯一标识，可用于定位一条 Trace。  |
| Log ID  | 扣子编程的日志 ID。需要联系扣子团队排查问题时，可以提供此 ID。  |
| Hash Version  | 产生本次请求的部署版本哈希值。  |
| 输入  | 用户输入的消息内容。  |
| 输出  | 智能体或工作流输出的消息内容。  |
| Input Tokens  | 用户输入内容的 Token 数量。该数据为估算值，仅供参考。  |
| Output Tokens  | 智能体或工作流输出内容的 Token 数量。该数据为估算值，仅供参考。  |
| Latency  | 请求从开始到结束的总耗时，单位为秒（s）。  |
| LatencyFirstResp  | 从用户发起请求到智能体或工作流返回第一个 Token 的耗时，单位为毫秒（ms）。如果希望工作流尽早返回首个 Token，可以配置输出节点。  |

## 管理 Trace 上报 {#31f95d43}

### 关闭 Trace 上报 {#b88ed6f1}

Trace 日志上报开关默认开启。工作空间所有者或管理员可以按需关闭该开关。关闭后，当前工作空间内所有成员将停止上报新的 Trace 数据，已上报的历史数据不受影响。

1. 在 AI 编程项目的**部署** > **Trace**页面，单击**成员 Trace 设置**。
   ![Image=505x181](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/ca434fecba7c4c97b71b36b88c68476d~tplv-goo7wpa0wc-topic.webp)
2. 关闭**允许全部成员上报 Trace**开关。
   ![Image=502x132](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/85dd2f219d08495498fb27890c2a1d63~tplv-goo7wpa0wc-topic.webp)   


### 设置 Trace 存储时长 {#c798f203}

Trace 存储时长默认为当前订阅套餐支持的最大默认时长，例如企业旗舰版为 180 天。工作空间所有者或管理员可以修改存储时长。修改后，当前工作空间内所有新上报的 Trace 数据均按照所设置的时长存储。

1. 在 AI 编程项目的**部署** > **Trace**页面，单击**成员 Trace 设置**。
   ![Image=505x181](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/ca434fecba7c4c97b71b36b88c68476d~tplv-goo7wpa0wc-topic.webp)
2. 设置 **Trace 最大存储时长**。
   ![Image=509x285](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/939445c862484d33bac0bc42e3e8bbc1~tplv-goo7wpa0wc-topic.webp)
