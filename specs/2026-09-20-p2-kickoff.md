## 4. P2 的任务分解（上一会话已摸清，可直接用）

用户选择**不拆子里程、一路到底**。注意：这不等于「一大坨没人验」——SDD 流程本身就是**每个任务一次独立审查**，少的只是中途的验收停顿点。

| | 任务 | 要点 |
|---|---|---|
| T1 | `dev.sh` 端口管理 + 独立源托管服务 | `CLASSNODE_WEBAPP_PORT`（默认 = server port + 1 = **4002**）；第二个 Express 只服务 `/webapps/` 静态与 SDK，**不挂任何 API、不带任何 cookie**；该端口故障不影响主服务。⚠️ **Tauri 侧也要做端口占用检查** |
| T2 | 上传与存储 | 复用 `server/src/services/upload-security.ts` 的 `safeExtractZip`；ZIP 与多选文件两条路径（首个 `.html` 作入口）；存 `CLASSNODE_DATA_DIR/webapps/<uuid>/`；校验：必须含入口 HTML、扩展名白名单、**拒绝任何服务端脚本**（php/jsp/asp/cgi）、单文件/总大小/文件数三项上限 |
| T3 | 外部依赖自检 | 扫 HTML/CSS/JS 里的外部 URL，发现即提示「本网页依赖 N 个外部资源，离线可能无法使用」。**不阻断上传，仅提醒** |
| T4 | SDK 本体 + 注入 | 托管服务返回 HTML 时在 `</head>` 前注入 `<script src="/__classnode/sdk.js">`，**教师无需改自己的网页**。能力：握手 / 事件采集 / 截图 / 挂起协议 / `ClassNode.report()`。⚠️ **隐私红线（不可放宽）**：事件采集**默认不采集输入框内容**，只记「在某输入框输入、长度 N」。需采集具体内容必须由教师网页显式调用 `report()` |
| T5 | 实时监控链路 | `iframe(SDK) →postMessage→ 学生端父页面 →socket.io→ 服务端内存 →socket.io→ 教师看板`。服务端**只存内存不落盘**、课堂结束释放；**按需推流**（教师看板订阅数归零即通知学生停推）；缩略图只留最新一帧（40 人 ≈600KB）；截图超 300ms 自动降档（5s→10s→20s）、`document.hidden` 时完全停发。**唯一落盘项**：课堂结束时一条汇总记录 |
| T6 | 学生端「探究助手」面板 | 把占位换成真的：iframe 挂载 + sandbox 集合、`active` → onPause/onResume。**这里才真正验证 P0 容器** |
| T7 | 教师端管理页 + 看板 | `/teacher/webapps/` 沿用 `agents/page.tsx` 的模式（卡片网格 + 表单弹窗 + 在线预览 + 使用量守卫 `GET /:id/usage`）；新建课堂时勾选关联；看板图墙 + 点开看详情 |
| T8 | 验收清单（控制器自己写） | 照抄 `acceptance.html` 的格式 |

**sandbox 集合**（§5.1）：`allow-scripts allow-same-origin allow-forms allow-pointer-lock allow-downloads`
**故意不给**：`allow-top-navigation`（防网页跳走整个页面）、`allow-modals`（防 `alert` 卡死老 iPad）

## 6. 流程教训（**血换来的，新会话必须遵守**）

这些不在 specs 里，是四个里程碑攒下来的。**每一条都至少被违反过一次并付出代价。**

1. **派发前必须先 `git status` 与 `git rev-parse HEAD` 现查。** 系统给的 gitStatus 快照是**会话开始时**的、不会更新 —— M1b-3 T2b 的实施者就因为信了它而**漏报了一处既有的未提交改动**。
2. **同一时刻只允许一个 `pnpm build` / `pnpm test`**（它们写 `dist/`、`.next/`、`out/`）。
3. **跑 `pnpm build` 前先 `./dev.sh stop`，跑完 `./dev.sh start`，最后 `./dev.sh status` 复核 4000/4001 都在。** 这条被踩过**三次**：`pnpm build` 覆盖 `.next` 会把正在跑的 dev server 打成 500（症状是 `ENOENT .next/routes-manifest.json` 或 `Cannot find module './129.js'`）。**实施者因此拿到过假的绿灯。**
4. **不要用 `reset-password` 造教师数据** —— 它内部会 `revokeAllTeacherSessions()`，**把用户可能开着的教师标签页登出**。走 `verify-password`，或造别的方式。
5. **测试若改数据库，必须逐表还原**，并在报告里给出还原证据。
6. **派发前做「冲突扫描」**：逐对检查共享文件或接口的任务，把「两个任务各删一半必然互踩」之类找出来并当场裁定。M1b-3 靠这一步抓出三处真冲突。
7. **实施者必须用 `grep` 自己枚举依赖，不得信任任何清单（含计划本身）。** 该条生效过五次。
8. **审查者必须独立验证，不能停在推理上。** 有效的做法包括：**反事实实验**（把 `position: relative` 改成 `static`，看角标是否横飞 228px）、**真实浏览器逐帧采样**（验证 `useLayoutEffect` 到底修不修得掉那个 bug）、**把后端杀掉看徽章多久翻**、**双向差集**（抽出 CSS 全部类定义与全部 `styles.X` 取差，验证 DEAD=∅/DANGLING=∅）。
9. **删东西最容易留下悬空引用** —— 已犯多次：奖励提示让学生「点击姓名旁的⭐」而 ⭐ 已被删；两条注释仍在指向被删掉的面板头部。**纯删除任务必须专门查这个。**
10. **「散文声称了一个不存在的机制」已犯 8 次**，`tsc`/测试/构建/浏览器**一个都抓不到**，只有读代码的人能发现。同类病还有一个变体：**把「肉眼不可分辨」写成「量测上相同」**（数字精度上的同类错误）。
