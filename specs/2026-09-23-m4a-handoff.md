## 3. 🔴 这个项目的操作纪律（血换来的，逐条都违反过）

1. **绝不 `prisma db push` 打在真实库上**（`server/prisma/dev.db`）。
   需要 DDL 就复制 schema 到 `/tmp`、**`DATABASE_URL` 必须显式给** —— 不给的话 Prisma 会读
   `server/.env` 的 `file:./dev.db`，上次只是**靠相对路径按 schema 目录解析**才侥幸没打中真实库。
   ⇒ 「复制 schema」本身**不构成隔离**，`DATABASE_URL="file:/tmp/…"` 才是。
2. **只允许一个 `pnpm build` / `pnpm test`**。并发会污染门禁数字，**而且会污染抖动诊断**。
3. **跑根 `pnpm build` 前先 `./dev.sh stop`**，跑完 `start`，最后 `status` 复核 —— 它会覆盖 `.next`，
   打断用户开着的浏览器验收。
4. 🔴 **提交时不要用 `git add -A`**，只 `git add` 点名的文件。派给子 agent 的任务**天然会在工作区
   留下未提交的改动**，`-A` 会无差别吞掉它们**且不报错** —— 本轮真发生过一次（已拆掉重建）。
5. 🔴 **`brief` 是派生件，不许手改**：改需求请改计划、再重新生成 brief。直接改 brief 会在下一次
   生成时被**静默抹掉**（本轮真发生过，还导致一条「提交信息声称的改动」在磁盘上不存在）。
   生成脚本见 ledger 里的记录；生成时**只剥尾部的 `---` 分隔符**，不要按第一个 `---` 截断（那会切掉节尾的裁定块）。
6. 🔴 **反证是唯一能区分「通过」与「碰巧通过」的手段**（Global Constraint 14）：
   任何「修好了 / 挡住了」都要把判据反转一次、观测到具名的那几条变红。
   ⚠️ **名册要当观测验，不能凭推演写** —— 本轮有一位实施者**凭推演**写了句「⚠️ 如实记」，
   写完就以为交代完了，**没再去核对漏网**，而真正红掉的那条就在那里。
7. **审计前先 `file` 一下你要 grep 的文件**（本项目有过裸 NUL 字节让 `grep` 整个跳过承载学生端
   全部鉴权的文件的先例）；**对 `.superpowers/` 用绝对路径**（见本文件抬头）。

## 4. 服务端已经交付的东西（D/E/F 组都要用）

`server/src/services/worksheet-questions.ts`
- `QUESTION_TYPES` **8 个**：`single-choice` `true-false` `multi-choice` `fill-blank` `short-answer`
  `order` `match` `categorize`
- `QuestionPoints {full, half}` · `DEFAULT_POINTS {full:1, half:0}` · `POINTS_MAX = 99`
- `isUsablePointValue` · `normalizePointValue` · `normalizePoints`（**返回 `undefined` = 留空 = 继承学习单级**）
- `QuestionNode.points?: QuestionPoints` —— **在题目节点上，不在 `data` 里**
- `ANSWER_KEYS`（含 `correctOrder` / `pairs` / `placement`）· `stripAnswers`（**递归剥**，含 `blanks[*].answers`）
- `GradeState = 'correct' | 'partial' | 'incorrect'` · `GradeResult {state, score}`
- `grade(node, value, points): GradeResult | null` —— **`null` = 该题型不参与判分**（问答题），
  与 `{state:'incorrect', score:0}` 是**两件事**
- `pointsFromSettings(settings)` · `resolvePoints(node, fallback)` · `VALIDATORS: Record<QuestionType, …>`

`WorksheetAnswer` 两列：`gradeState String?` · `score REAL?`（⚠️ 是 `REAL`，不是 `DOUBLE PRECISION` —— 见 ledger）。
**`isCorrect` 只增不改**：它是协议字段，全仓 8 个文件、21 行代码在读它；改名 ⇒ 前端静默不画奖励。
线缆上的形状：`{ isCorrect, gradeState, score }`（提交响应 / 两条读端点 / socket 广播）。

学习单级两档：`settings.rewardStep` / `settings.halfStep`，
半对档的域是 **`HALF_STEPS = [0,1,2,3,5]`（含 0）**，与 `rewardStep` 的 `[1,2,3,5]` **不同**
（`0` 在半对档是**合法值** = 这单不给部分分），两侧各存一份、注释互相指向。

**编辑器侧**：`newQuestion` 的初始 `data` **只给非答案内容占位，答案键一律留空**（教师点保存会被 400
指名道姓地拦下）。**臆造答案键会让一道没配答案的题静默判分** —— 那是 M3 立下、有 🔴 用例钉着的纪律。
