# M4b · Canvas 手写层与绘图题 · 实现计划

> **给实施者**：本计划逐任务执行。规格是**权威**（`specs/2026-09-23-p1-worksheet.md` §12 的
> 「M4b 的设计裁定」6 条 + 「M4 的范围」表 + 「M4 拆两批」段），
> 本计划若与规格冲突，以规格为准并**当场报告冲突**，不要自行裁定。
> 与 M4a 一样，实施者有义务自己 grep 枚举，**不照抄清单** —— M3 的 brief 里有 6 处不存在的命令。

**目标**：把 M4 的最后两块补上 —— **Canvas 手写层**（笔迹 + 撤销 + 清空）与 **绘图题**。
交付物是**一条**能力：一份**矢量笔迹**（归一化坐标的笔画 JSON），它在两处被渲染
（学生的作答画布、教师抽屉的「原答案」），在两条路上被搬运（HTTP + `localStorage` 离线队列），
**一处都不判分**。

| 名字 | 是什么 | 谁的作答值 | 组件 |
|---|---|---|---|
| **`drawing`**（★ M4b 新增的第 9 个题型） | **题型**：一道题的全部内容就是学生画的图 | `{ format: 'drawing/v1', … }` | `ink-body.tsx` |
| **手写笔迹** | **输入方式**（不是题型）：一道**问答题**的作答方式选「手写」 | `{ format: 'ink/v1', … }` | 同一个 |

⚠️ **两个数字别混**（M4a 已经把这两个口径钉过一次，这里沿用，别再造新的）：

| 口径 | 数 | 明细 |
|---|---|---|
| M4a 交付后 `QUESTION_TYPES` 的**条目数** | **8** | 单选 / 判断 / 多选 / 填空 / 问答 / 排序 / 连线 / 归类 |
| M4b 交付后同一条目数 | **9** | 上面 8 个 + **`drawing`** |
| M4b 要交付的**件数** | **2** | Canvas 手写层（一个能力）+ 绘图题（一个新题型） |

**架构**：笔迹的形状与全部可判定的逻辑落 `src/lib/worksheet-ink.ts`（纯函数，`node --test` 直接跑）
—— 上限（400 笔 / 2000 点）、归一化、撤销 / 清空、坐标换算**全在里面**。
pointer 那半（`setPointerCapture` / `touch-action` / 收尾）进组件、**只能真机验**。
服务端**不共用**这份实现也不共用判分：`drawing` 与 ink 值在 `grade()` 里**恒回 `null`**，
另有一份**体积校验**把守写入口（前端拦不住手搓请求）。

**技术栈**：Next.js 15 静态导出 · React 19 · Express + Prisma/SQLite · Node 内置 test runner
（**无 vitest / jest / jsdom / testing-library**，前端只能测纯逻辑）。
**不新增任何依赖** —— 画布与笔迹全手写（Global Constraint 2）。

**规格**：`specs/2026-09-23-p1-worksheet.md` §12「M4 的范围」「M4 拆两批」「M4b 的设计裁定」。

> `assert.equal(formatAnswer(fill, { format: 'ink/v1', strokes: [] }), null)` **必须一起改**

15. 🔴 **写散文时，「源材料里没有的成分」不许凭合理性补 —— 那是假话的高发位点。**
    一句话的语法所要求的成分（主语、位置、数量、限定条件）**常常比源材料给的多**；
    缺的那些槽位若按「最合理的填法」补，产出的句子**读起来像从代码里抄的**，
    于是不会被人重查 —— 假话的破坏力恰好来自它「像真的」。
    ⇒ **下列四类词出现时，必须挂一条命令或一个 `file:line`；挂不上就写「未核」，不要写成断言。**
    · **主语**（谁做的 / 谁看到的）· **位置**（学生端 / 教师端 / 抽屉 / 格子 / 顶栏）
    · **数量**（三个 / 唯一 / 全部 / 至少）· **限定**（「只在…时」「永远不会」「只有在…之后」）

    ⚠️ **数量词一律先 `grep -c` 再写** —— 它是唯一能机械判定的一类，**零借口**。
    🔴 **但更常见的是反过来的错**：数词与清单对不上时，**先假设清单漏了，去查源材料** ——
    **不要改数字**。改数字会让症状消失而问题加深：那个数字本身就是「还有一处你没列出来」的信号。
    （2026-09-24 实测两次、方向相反的同一处：有人把「五处」改成「四处」以对齐四条清单，
    删掉的正是第 5 处 `parseDraft` 的唯一信号；另一次是跑了一条**过滤过**的命令却按全量口吻写数字。）
    ⚠️ **旧文档里没有主语的句子，不许在新文档里被「补全」** —— 原样引用 + 标「源头无主语」，或去查。

    **本项目实测的 5 例**（每一例都是「源里没有、被补出来的」）：

    | 源材料 | 写出来的 | 补的是哪个槽 | 实际是 |
    |---|---|---|---|
    | 「顶栏警告」（**无主语**） | 「**学生端**顶栏给出警告」 | 主语 | 警告在**教师端编辑器**上；学生端 `grep` **零命中** |
    | 「半对档 = 0」 | 「那条提示**永远不会响**」 | 因果方向 | **反了** —— C3 之前它**到处都在响** |
    | §7.3 的图例 | 「只列了**那三个**」 | 数量 | 是**四个**（一条 `grep` 即可） |
    | `texts: []` | 「整列变空、**连框都不见了**」 | 后果 | 补位循环会补回来 ⇒ **不变** |
    | 反证跑完（凭推演） | 「红 **2** 条」 | 计数 | 是 **3** 条 |

    🔴 **命令与断言要一起被验。** **一条你没跑过的验证命令，本身就是一句假话** ——
    它比写错一个词更隐蔽：它让读者以为「这条已经核过了」。
    ⇒ 凡文档/注释里给出**可跑的命令**，写下它的人**必须跑过它、并逐字贴输出**。
    ⚠️ **复现命令同样算**（审查者给的命令也要被审查者自己跑一遍）：
    本项目实测过一次 —— 审查者给的 `'重新进入\|警告\|banner'` 是**三合一**的，
    而 `rg` 的 `\|` 与 `|` 语义不同，那样跑出的「零命中」**不可信**；逐 token 分开跑才发现 `警告` 有 2 条命中。

    🔴 **审查这类产出时的主镜头（交给审查者）**：把新文本与它的**源材料并排**，逐句**只问一件事** ——
    **「这个词源里有吗？没有的话它从哪来的？」** **不要泛读**，泛读会漏掉恰好「读起来对」的那些。

- [ ] **Step 3: 上限与采样 —— 本任务最要紧的两条判据**

```ts
/** 所有笔画加起来的点数。上限判据用的是**总数**，不是「每笔最多多少点」。 */
export function countPoints(strokes: readonly InkStroke[]): number {
  let total = 0;
  strokes.forEach((stroke) => { total += stroke.points.length; });
  return total;
}

/**
 * 还能不能落新的一笔。`null` = 可以。
 *
 * 🔴 **必须先说清这条判据在防什么**：值是 Json 列、要过 HTTP、还要进 `localStorage`
 * 离线队列（规格 §12 裁定 4）⇒ 没有上限时，学生按住不放画十分钟就是一个几十 MB 的值，
 * 它会（a）挤爆 `localStorage` 配额（`writeQueue` 的 `catch` 会**静默降级**成「这一次会话
 * 内还在、撑不过刷新」）、（b）让教师抽屉里那条渲染卡死。上限是**机械可判**的那条线。
 */
export function inkLimitReason(strokes: readonly InkStroke[]): string | null {
  if (strokes.length >= INK_MAX_STROKES) {
    return `笔迹已达上限（${INK_MAX_STROKES} 笔）—— 请撤销几笔，或点「清空」重画。`;
  }
  if (countPoints(strokes) >= INK_MAX_POINTS) {
    return `笔迹已达上限（${INK_MAX_POINTS} 个点）—— 请撤销几笔，或点「清空」重画。`;
  }
  return null;
}

/**
 * 加一笔。🔴 **超上限时原样返回**（同一个对象），**不抛、也不截断**。
 *
 * ⚠️ 为什么**不截断**：截断会把学生那一笔的后半段吃掉，而他看到的是「我的线怎么短了一截」——
 * 那比「这一笔没画上 + 一句上限提示」难懂得多。整笔丢掉时至少屏幕上少一条完整的线，
 * 配合 `inkLimitReason` 的那句话，学生知道发生了什么。
 * ⇒ 调用方（组件）**在落笔之前**先用 `inkLimitReason` 拦一次，所以这条分支正常走不到；
 *   它留着是因为「值可能来自手改过的行 / 上个版本」，而那时代码不该抛。
 */
export function appendStroke(value: InkValue, stroke: InkStroke): InkValue {
  if (stroke.points.length === 0) return value;
  if (inkLimitReason(value.strokes) !== null) return value;
  if (countPoints(value.strokes) + stroke.points.length > INK_MAX_POINTS) return value;
  return { ...value, strokes: [...value.strokes, stroke] };
}

/**
 * 两个归一化点之间的**像素**距离够不够远 —— 采样过滤。
 *
 * 🔴 **不加这条过滤，上限就是形同虚设**：`pointermove` 在 iPad 上按屏幕刷新率派发，
 * 一次 3 秒的涂鸦轻松产生 600~1000 个点，学生**几乎一落笔就撞上 2000 点的上限**，
 * 而提示说的是「笔迹已达上限」—— 他会以为是自己画得太多，不会想到是采样的问题。
 * 阈值 1.5px 是「手指抖动」与「有效位移」之间的经验值（与 M4a 的 `DRAG_THRESHOLD_PX`
 * 同一个由来，但**不是同一个数**：那个判「点选还是拖拽」，这个判「这个采样点要不要记」）。
 */
export function isFarEnough(from: InkPoint, to: InkPoint, box: InkCanvas, minPx: number): boolean {
  const a = toPixel(from, box);
  const b = toPixel(to, box);
  const dx = b[0] - a[0];
  const dy = b[1] - a[1];
  return dx * dx + dy * dy >= minPx * minPx;
}

/** 客户端坐标 → 归一化，**越界夹到 0..1**。`size <= 0` 时回 0（框还没量出来，别产生 NaN）。 */
export function normalizeAxis(offset: number, size: number): number {
  if (!Number.isFinite(offset) || !Number.isFinite(size) || size <= 0) return 0;
  const ratio = offset / size;
  return ratio < 0 ? 0 : ratio > 1 ? 1 : ratio;
}
```

- [ ] **Step 5: 换算与 SVG path（两处渲染的唯一入口）**

```ts
/**
 * 归一化 → 像素。★ **学生端 canvas 与教师端 SVG 都只走这一个函数。**
 *
 * 🔴 各写一份的后果是**两边画出来的形状不一样**（基准不同 / 少乘一个 `canvas.h`），
 * 而两处都「看起来正常」：学生在自己的 iPad 上看到的是他对的那一份，
 * 教师在抽屉里看到的是错的那一份，**没有任何报错、没有一条用例会红**。
 */
export function toPixel(point: InkPoint, box: InkCanvas): InkPoint {
  return [point[0] * box.w, point[1] * box.h];
}

/** 笔记在 `box` 坐标系里的线宽。下限 1：老 iPad 上一个 0.4px 的线画不出来。 */
export function strokeWidthPx(stroke: InkStroke, box: InkCanvas): number {
  const base = Math.min(box.w, box.h);
  const width = stroke.width * base;
  return width > 1 ? width : 1;
}

/**
 * SVG 的 `d`（教师端抽屉）。
 *
 * 🔴 **单点笔画必须画出一个点**：学生在屏幕上点一下就是一个只有 1 个点的笔画，
 * 而 `M x y` 后面什么都不接的路径在 Safari 上**不渲染任何东西**（round linecap 对
 * 零长度子路径的处理各家不同）⇒ 用一个极短的线段代替（`l 0.01 0`）。
 * 「点了一下没反应」正是那种没人会报的缺陷。
 */
export function strokePath(points: readonly InkPoint[], box: InkCanvas): string {
  if (points.length === 0) return '';
  const parts: string[] = [];
  points.forEach((point, index) => {
    const [x, y] = toPixel(point, box);
    parts.push(`${index === 0 ? 'M' : 'L'}${round2(x)} ${round2(y)}`);
  });
  if (points.length === 1) parts.push('l0.01 0');
  return parts.join(' ');
}
```
（`round2` 是一个本地的小助手：`Math.round(value * 100) / 100` —— 只为了别让 `d` 串里出现
17 位小数；它是**内部函数**，不导出。）

- [ ] **Step 6: `readInkValue` 的容错边界**

```ts
/**
 * 读一份笔迹值。**容错到底**（值可能来自手改过的行 / 上一个版本），坏形状回 `null`。
 *
 * 🔴 与 `readEntries` / `readLinks` 同一条纪律，但**判据的粒度是逐笔画的**：
 * 一条笔画坏掉只丢那一条（屏幕上少一条线），整份不是数组才回 `null`。
 * 反过来（一条坏笔画作废整幅画）会让**学生画的所有东西在屏幕上消失**，
 * 而那是渲染路径 —— 学生会以为老师把题撤了。
 *
 * ⚠️ 数量**不在这里截断**：这里是读的一侧，截断会让「库里有什么」与「屏幕上画什么」
 * 变成两件事。上限只在写入口（`appendStroke` 与服务端的 400）。
 *
 * ⚠️ `canvas` 读不出来时回落 **`{ w: 0, h: 0 }`**（不是 `null`、也不是编一个默认框）——
 * 渲染那一侧（E1 的 `InkPreview`）把 0 当成「用一个最小可渲染的框」，
 * 而编一个默认框会**把学生的图按错误的宽高比画出来**（那是一条看起来正常、但形状是错的线）。
 */
export function readInkValue(raw: unknown): InkValue | null {
  if (!raw || typeof raw !== 'object' || Array.isArray(raw)) return null;
  const row = raw as Record<string, unknown>;
  if (!isInkFormat(row.format)) return null;
  if (!Array.isArray(row.strokes)) return null;
  const strokes: InkStroke[] = [];
  row.strokes.forEach((item) => {
    const stroke = readStroke(item);
    if (stroke) strokes.push(stroke);
  });
  return { format: row.format, canvas: readCanvas(row.canvas), strokes };
}
```
（`readStroke` / `readCanvas` / `readPoint` 是**内部**助手，不导出：逐层「先判类型再取」，
坏的那一层丢掉 —— 与 `readLinks` 同一条手法。`readPoint` 只收**两个都是有限数**的
二元数组，并把两个数**夹到 0..1**（手改过的行可能写着 `x: 7`）。）

```ts
/**
 * 作答值里**笔迹**的体积与形状校验 —— 规格 §12 裁定 4 的后半句
 * 「**服务端也要校验**（前端拦不住手搓请求）」。
 *
 * 🔴 为什么必须有：`express.json({ limit: '10mb' })` 是服务器唯一的上限。
 * 一个 8MB 的笔迹值会进 Json 列，再经两条读端点与一次广播送到**教师那台机器**上
 * （抽屉要把它画出来）⇒ 看板卡死，而**服务端不会报任何错**。
 *
 * ⚠️ 只对 ink 值生效。**别把它写成一道格式门**：认不出的 `format` 一律放行 ——
 * `format` 在服务端从来不是判据（`worksheet-answer-value.ts:42-52`），
 * 加一道格式校验会让库里已有的行与旧客户端**静默不判分**。
 */
export function findInkValueError(value: unknown): string | null {
  if (!value || typeof value !== 'object' || Array.isArray(value)) return null;
  const row = value as Record<string, unknown>;
  if (!isInkFormat(row.format)) return null;
  const strokes = row.strokes;
  if (!Array.isArray(strokes)) return '笔迹的形状不对（strokes 必须是数组）';
  if (strokes.length > INK_MAX_STROKES) {
    return `笔迹太多：最多 ${INK_MAX_STROKES} 笔，请撤销几笔或清空后重画`;
  }
  let total = 0;
  for (const stroke of strokes) {
    if (!stroke || typeof stroke !== 'object' || Array.isArray(stroke)) {
      return '笔迹的形状不对（每一条笔画都必须是对象）';
    }
    const points = (stroke as Record<string, unknown>).points;
    if (!Array.isArray(points)) return '笔迹的形状不对（每条笔画的 points 必须是数组）';
    total += points.length;
  }
  if (total > INK_MAX_POINTS) {
    return `笔迹太多：最多 ${INK_MAX_POINTS} 个点，请撤销几笔或清空后重画`;
  }
  return null;
}
```

⚠️ 量框**只能**用 `getBoundingClientRect()`，**不许**用 `event.offsetX/offsetY`：
`offsetX` 在滚动 / 页面缩放 / 键盘弹起后的老 WebKit 上会错位，而它的表现是
「整幅画偏移一个固定的量」—— 只在某些设备上出现（**未验证**），本机复现不了。

```tsx
/** 学生笔迹的只读渲染。宽高比用**值自己记的** `canvas.w/h`（裁定 2），容器不足时按它留白。 */
function InkPreview({ value }: { value: InkValue }) {
  const { w, h } = value.canvas;
  // `w`/`h` 可能是 0（手改过的值）—— 那时给一个最小可渲染的框，别让 SVG 的 viewBox 变成 "0 0 0 0"。
  const box = { w: w > 0 ? w : 1, h: h > 0 ? h : 1 };
  return (
    <svg
      viewBox={`0 0 ${box.w} ${box.h}`}
      width="100%"
      style={{ display: 'block', background: '#fff', border: '1px solid #e2e8f0', borderRadius: 4 }}
      role="img"
      aria-label="学生的手写作答"
    >
      {value.strokes.map((stroke, index) => (
        <path
          key={index}
          d={strokePath(stroke.points, box)}
          fill="none"
          stroke={stroke.color}
          strokeWidth={strokeWidthPx(stroke, box)}
          strokeLinecap="round"
          strokeLinejoin="round"
        />
      ))}
    </svg>
  );
}
```
⚠️ **SVG 的坐标系就是 `box`**（`canvas.w × canvas.h`），线宽也在这个坐标系里
（`strokeWidthPx` 已经乘过 `min(w,h)`）—— 浏览器按 `width: 100%` 等比缩放，
**留白由 `viewBox` 自己给出**。这就是裁定 2 的「宽高比不匹配时按 `canvas.w/h` 留白」
落在代码里的样子。
⚠️ `key={index}` 在这里可以接受（静态列表、不重排）—— 但**要写一句注释说明它为什么可以**，
否则下一个人会照着抄到别处。
