# API Token 共享与有效期倒计时

> 日期：2026-09-25 · 状态：**设计，未动代码** · 来源：教师口头需求

---

## 一句话

Coze 低代码的 **API Token 属于扣子账号、不属于 Bot** —— 同一个号做出来的多个智能体现在各存一份、
换一次要改 N 遍，而且**没有任何地方记着它 30 天后会过期**。
把 Token 提出来做成**可命名的多份凭据**，智能体各选一份，并给每份记一个有效期、按天倒计时提醒。

## 目标 / 不做什么

**做**：多份 Token（带备注）· 智能体按份引用 · 有效期与倒计时 · 临期/过期的提醒。

**不做**（写在这里是为了让下一个人知道它们是**决定**，不是漏掉）：
- **不做自动续期**：扣子没有续期 API。
- **不对 `coze-agent` / 文心 / 智谱做同样的事**。它们的凭据是不是账号级，我**没有证据**；
  按平台通用建表，但今天只接 `coze`。
- **过期不改变智能体的可用性**（教师裁定 2026-09-25）：只提醒。理由见 §风险。

### 🔴 一条必须先说清的限制

**系统无法知道两个智能体是不是同一个扣子账号** —— 只能看出「Token 字符串一样」。
⇒ 实现里「同账号」**只能是「同一个 Token」**，靠教师自己确认。**不做任何自动判定**，
也不假装能做（比如「自动合并相同 Token 的智能体」——那会把两个恰好填了同一个 Token
的、本该独立的智能体悄悄绑在一起）。

## 一、数据

### 新表 `PlatformToken`

| 列 | 说明 |
|---|---|
| `id` | uuid |
| `platform` | `'coze'`。**留通用**是为了将来别的平台要挂时不用再迁一次表；今天只写这一个值 |
| `label` | **备注：这是谁的账号**（「张老师的号」「学校公用号」）。必填 —— 一份没有名字的凭据，在一份列表里等于没有 |
| `token` | AES 加密（同一个 `services/crypto.ts`），**响应里一律掩码**（复用 `maskAgentSecret`） |
| `expiresAt` | 有效期（DateTime），**可空**。🔴 空 = 「没设置」，是一个**要被催促的状态**，不是沉默的默认 —— 见 §迁移第 2 条：迁移时**不猜**日期，界面上显示「未设置有效期」并催教师去填。新建时界面**必填**（不填就没有倒计时，那这个功能整个不存在） |
| `createdAt` / `updatedAt` | |

**不存「账号」字段**：我们不知道账号是什么，也没有地方去问。`label` 是教师写的自由文本。

### `Agent` 增一列

`credentialId String?`（可空，外键到 `PlatformToken`）。

判据：**`platform === 'coze'` 且 `credentialId` 非空 ⇒ 用那份共享 Token，忽略自带的 `apiKey`。**

⚠️ 空值是一条**真路**，不是「还没有」：老数据全是空 ⇒ 沿用自带的 `apiKey`，
行为与今天**逐字相同**。这也是回滚的路：把 `credentialId` 全部置空，系统就回到今天。

### 删除守卫

一份还被 N 个智能体用着的 Token **删不掉**，要说清「N 个智能体正在用它」并列出名字。
照本仓既有的三处先例（`checkAgentUsage` / `checkClassroomUsage` / 学习单的 usage 端点）。
⚠️ 外键的默认行为是 `RESTRICT`，所以**必须先有守卫**，否则界面会给出「可以删」的假信号、
然后删除失败 —— 一个说谎的文案。

## 二、收口：`toAgentConfig`

今天 7 处各写一遍：

```ts
apiKey: (() => { try { return decrypt(agent.apiKey); } catch { return agent.apiKey; } })(),
```

新增一个 `toAgentConfig(agent, token)`（住在 `server/src/services/`），7 处改调它。

🔴 **这才是这次改造真正的价值，不只是顺手清理**：今天 7 处是复制粘贴出来的，
将来加第 8 个调用点、或者只改了其中 6 处，**没有任何东西会红** ——
表现是「**某一条链路还在用旧 Token**」。
而这次的 7 处里**已经有 4 处不在对话链路上**（测试连接 / 开场白 / 信息预览 / 定时检查）
—— 漏掉它们的症状是：**对话已经用上新 Token 了，而「测试连接」还在报旧 Token 的错**，
教师会去查一个根本不存在的问题。

⇒ 收口之后，「哪里用哪份 Token」**只有一个答案**。

## 三、界面（三处）

### ① Token 管理（智能体页的一个弹窗）

工具栏加一个「API Token」按钮 → 弹窗列表：

```
备注              平台          有效期
张老师的号        Coze 低代码    还剩 12 天        [改] [删]
学校公用号        Coze 低代码    还剩 3 天   ⚠     [改] [删]
```

录入一份时：**Token**（掩码回显）+ **备注** + **有效期**（默认 `今天 + 30 天`，可手改）。
「30 天」是**扣子平台当前的最长有效期**（教师提供），所以它是默认值、不是硬上限 ——
扣子改了策略时教师自己改这个日期即可，我们不去猜。

### ② 智能体表单

Token 字段从「一个输入框」变成「**下拉选一份凭据** + 一个『管理』链接」。

- 默认选中**已有的那份**（今天大多数老师只有一份 —— 这才是常见路径）。
- 下拉里只列**本平台**的凭据（`coze` 的智能体不该看见将来的智谱凭据）。
- 保留「**自带 Token**」这一项（= `credentialId` 为空），给「这个 Bot 用的不是我的号」那种情况。

### ③ 提醒（两个落点）

- **智能体页顶部一条横幅** —— 只在**有临期或过期**时出现，否则完全不占位置。
- **侧栏「AI智能体」那一项上的小圆点** —— 教师不进那一页也能看见。
  ⚠️ 侧栏在 `src/app/teacher/layout.tsx`，它现在只读 `navItems`，**没有取数的能力**；
  这一条要么给侧栏加一次轻量请求，要么把状态放进已有的轮询。
  **这是本设计里唯一一处「要动外壳」的地方，单独算一步。**

## 四、倒计时规则

| 剩余 | 颜色 | 文案 |
|---|---|---|
| > 7 天 | 灰 | `还剩 N 天` |
| ≤ 7 天 | 黄 | `还剩 N 天` |
| ≤ 3 天 | 红 | `还剩 N 天` |
| ≤ 0 | 红 | `已过期 N 天`（当天写 `今天到期`） |

**只提醒，不动智能体**（见下）。「天」按**自然日**算，不按 24 小时 ——
教师看的是「还有几天」，不是「还有几小时」。

## 五、风险（三条，都在设计里，不是待办）

### 🔴 日期是教师手工填的，不是扣子告诉我们的

扣子没有「查 Token 有效期」的 API。⇒ **教师换了 Token 却忘改日期，倒计时就是假的**。

这是本设计的固有弱点。缓解手段只有一个：**「新建凭据」这个动作顺便重置日期**，
并让「改 Token」和「改日期」在同一个表单里、彼此挨着。
⚠️ 也正因为如此 —— **绝不能让它去停用智能体**（教师裁定：过期后只提醒）。
日期填错时，最坏的结果只是「一条假的提醒」；如果它会停用，最坏的结果是
**课堂上静默地停掉一个能用的智能体**，而教师只会看到「学生用不了」。
**「只提醒」不是为了温和，是为了让这个功能的失败模式停在提醒这一层。**

### 🔴 一处改、多处生效 —— 也意味着一处改错、全班崩

改一份 Token 的值会影响 N 个智能体。⇒ 提交前必须说清「会影响这 N 个：……」。
（删除有守卫，**改值也要有影响面提示** —— 前者是「删不掉」，后者是「删得掉但要说清」。）

### ⚠️ 迁移必须幂等且可回滚

见下。

## 六、迁移

一次性：把现有 `coze` 智能体的 Token 解密、**按 Token 值去重**、抽成 `PlatformToken` 记录，
再给这些智能体写上 `credentialId`。

🔴 三条纪律：
1. **原 `apiKey` 一个字不动。** 它既是回滚的路，也是「自带 Token」那条路的数据。
2. **`expiresAt` 迁移时给什么值？** —— **迁移不猜**。不写 `now + 30d`（那是一个我们没有依据的
   断言，而且会在迁移当天就给所有老用户造出一批假倒计时）。
   迁移时**不给有效期的记录**，界面上显示「**未设置有效期**」并催教师去填。
   ⇒ 换句话说：列**可空**，但**「空」是一个要被催促的状态**，不是沉默的默认。
   **新建时界面必填、迁移来的可空** —— 两者不矛盾：一条是录入时的要求，一条是既有数据的现实。
3. **幂等**：重复跑不会造出第二份同样的凭据。

---

## 七、验收槽位（都能手工验）

1. 把两个 `coze` 智能体指向同一份 Token ⇒ 改那份 Token ⇒ **两个都变**（且「测试连接」也跟着变）。
2. 改一份 Token 的值 ⇒ 提交前看到「会影响 2 个智能体」。
3. 删一份还被用着的 Token ⇒ **被拦住**，并列出是哪几个。
4. 造一份 `expiresAt` = 3 天后的凭据 ⇒ 变黄/变红、侧栏出小圆点、横幅出现。
5. 造一份已过期的 ⇒ 写「已过期 N 天」，**而指向它的智能体照旧能用**（这条是裁定的验收）。
6. 迁移后：老 `coze` 智能体的对话行为**逐字不变**，且原 `apiKey` 仍在库里。
7. 迁移来的凭据显示「未设置有效期」，不是「还剩 0 天」、也不是随便一个 30 天。

## 八、施工顺序（每步可独立验、可独立停）

1. **表 + 列 + 迁移脚本**（含幂等与回滚路径）—— 此时界面还没变，跑一次门禁即可。
2. **`toAgentConfig` 收口**（7 处改调它）—— 行为应逐字不变，**这一步本身就是一次有价值的重构**。
3. **Token 管理弹窗**（增删改查 + 删除守卫）。
4. **智能体表单的下拉**。
5. **倒计时与提醒**（横幅 + 侧栏圆点）。
