# 学习单「任务制」+ 编辑页重设计 — 设计

> 日期：2026-09-25 · 状态：**设计，未动代码** · 来源：教师「学习单要以『任务』为单位…每一个任务里可以包含若干小题」+「不满意，你推翻重来」

---

## 一句话

给学习单加**一层「任务」容器**（任务一：说明 + 若干小题），题号变两级，
**编辑页的 UI 重设计与它一起做** —— 不要分两次。

## 教师的四条裁定（2026-09-25，逐条已定）

| # | 问题 | 裁定 | 含义 |
|---|---|---|---|
| ① | 任务能不能作答 | **(a) 不能** | 任务 = **分组 + 一段说明**，作答全在小题上。任务自己**没有**作答值、不判分 |
| ② | 题号怎么排 | **(b) 每个任务内重排** | 任务一 1/2/3 · 任务二 1/2。**会渗到四处**，见 §四 |
| ③ | 分值 | **小题之和** | 任务的分 = 它的小题之和（**不单独存**，算出来即可） |
| ④ | 老数据 | **(a) 自动包一层「任务一」** | 迁移时把现有平铺的题包进一个任务里 |

## 一、数据模型

### 任务是一个**新的容器类型**，不是新字段

`QuestionNode` 已有 `children: QuestionNode[]`（嵌套在数据里**早就存在**，
只是从没有容器编辑 UI —— 见 `specs` 里 §4.3 的注释）。所以任务**复用这棵树**：

```jsonc
{ "id": "t1", "type": "task", "prompt": "任务一：读下面的材料，回答 1–3 题", "children": [ /* 小题 */ ] }
```

### 🔴 为什么把 `task` 放进 `QUESTION_TYPES`（而不是另开一个 node kind）

服务端的 `VALIDATORS` 与 `JUDGES` 都是 **`Record<QuestionType, …>`** ——
类型联合里加一项，**每一处都必须回答它，漏一处是编译错误**。
这正是我们要的：任务在判分、校验、选项、题号这四处都必须被表态，
而「另开一个 kind」会让它们**静默地漏掉**（那是本仓反复栽的那一类）。

代价是要**显式处理**它：

- `VALIDATORS['task']`：要求有 `prompt`（任务说明可以留空吗？见 §八 待定）、`children` 非空？
- `JUDGES['task']`：**永远不该被调到**（任务没有作答值）。⚠️ 写成 `throw` 还是返回 `null`？
  推荐 **`throw`** —— 走到那里说明上游（作答值、看板行）出了错，静默返回 null
  会让「任务被当成一道题」这件事一路滑到界面上。
- `QUESTION_TYPE_OPTIONS`（**前端**，加题弹窗的清单）：**必须排除 `task`** ——
  它是「添加任务」那个按钮加的，不该出现在「添加题目」的九宫格里。
  ⚠️ 两份清单不同步的症状是：教师在加题弹窗里选中「任务」，保存被服务端 400 拒。
  （那个窗口**真实发生过一次**：`drawing` 加进前端却没加进服务端。）

## 二、题号：两级

`任务一 · 1` / `任务一 · 2` / `任务二 · 1`。

🔴 **规则必须只有一份**。当前题号是「一律由题目树算」（`worksheet-drawer-state.ts` 里
有一条用例专门钉着「**绝不**拿 `answerRows` 的下标当题号」）—— 那条纪律继续用，
只是算出来的东西从「第 N 题」变成「任务 X · 第 M 题」。

⚠️ **`flattenQuestions` 的返回值不再等于「题号」**：它拍平之后，父任务与小题混在一个数组里。
**凡是用它的下标当题号的地方都会静默错位**。⇒ 拍平函数要么带出 `{ node, taskIndex, subIndex }`，
要么另给一个「只算可作答题」的纯函数。**这是这次改动最容易出错的一处。**

---

## 三、分值：任务的 = 小题之和

**不新增存储**。任务节点没有 `points`，需要时对 `children` 求和。

⚠️ 与既有口径对齐：M4a 的分数是**逐题两个绝对数**（全对给几 / 半对给几，规格 §12）。
「任务的分」因此是**两个数各自的求和**，不是一个数。别把两档压成一个。

## 五、迁移（④a）

把现有学习单的平铺题**包进一个任务**，`prompt` 给什么？

- 推荐 **`"任务一"`**（不编说明）—— 迁移**不猜内容**，与「有效期不猜」是同一条纪律。
- 幂等：重复跑不套两层。判据是「根节点里还有没有非 `task` 的节点」。
- 🔴 **原 `content` 的每个节点一个字不动**，只是外面包一层 ⇒ 回滚 = 把那层剥掉。
- `schemaVersion` 要不要 +1？见 §八 待定。

## 六、编辑页重设计：**与任务结构一起做**

前面已经做过 5 步（刻度归并 / 立主次 / 四段结构 / 蓝竖条焦点态），教师说「**不满意，推翻重来**」。

🔴 **那些不白做，但也不要往上叠**：它们是**层级更低**的一层（刻度、主次），
与「任务」不冲突。做法是**保留结论、重做布局**：

- 保留：间距刻度 4/8/12/16/24 · 圆角三档 12/8/6 · 题干是主角 ·
  字段标签退灰 · 只有一张卡亮（焦点态）。
- 重做：**整页的信息架构** —— 现在要同时表达「任务」与「题」两级。

**方向（教师原话）**：「类似『问卷星』那样漂亮，**主要是操作起来要更直观**」。
问卷星那种整齐来自**重复**，不是装饰。落到两级结构上：

1. **任务的边界一眼可见**：任务是一个**明显更大的容器**，里面装着小题卡。
2. **两级各有自己的操作**：任务的（加小题 / 改名 / 上移下移 / 删除）与小题的
   （题型 / 上移下移 / 复制 / 删除）**不能挤在同一排**。
3. **加东西的入口醒目且分层**：「+ 添加任务」在页面级，「+ 添加小题」在**任务内**。
4. 反面清单（教师明确要的是「直观」，不是热闹）：不加图标装饰 / 渐变 / 彩色标签。

## 七、硬约束

1. 🔴 **服务端 `VALIDATORS` / `JUDGES` 都是 `Record<QuestionType, …>`** ——
   加 `'task'` 会让它们在编译期全部报错。**逐处回答，不要用 `as any` 糊过去**。
2. 🔴 **前端与后端的题型清单是两份**（`QUESTION_TYPE_OPTIONS` / `QUESTION_TYPES`）——
   加容器时两边语义不同（后端**有**、前端加题弹窗**没有**），要各自说清理由。
3. ⚠️ **`worksheet-schema.ts` 的手写 DDL 与 prisma 必须逐字一致**（本次**不动 schema** ——
   树本来就在 `content` 这个 Json 列里）。
4. ⚠️ Safari 15 门禁扫 `src/lib`：题号函数若落在那里，不得用 lookbehind / `.at(` / `findLast` 等。
5. ⚠️ **答卷与判分的历史数据不许被这次改动读错**：库里已有的作答按 `questionId` 存，
   而包一层任务**不改任何 `questionId`** ⇒ 老作答仍然对得上。**这一点要在用例里钉住。**

## 八、待定（动手前问一句）

1. **任务的「说明」允许留空吗？** 允许 ⇒ 「任务一」这种纯分组是合法的；
   不允许 ⇒ 迁移时必须编一段文案（而那违反「迁移不猜」）。
   **推荐允许留空。**
2. **`schemaVersion` 要不要 +1？** 树结构本来就在，本次只是**开始用它** ——
   但如果将来有别的读者按 version 分支，这里得表态。
3. **任务能不能嵌套任务？**（任务 → 子任务 → 小题）。**推荐禁止**（校验器拦住），
   否则题号会成为三级，而 UI 的「重复」优势立刻消失。

## 十一、✅ 已核：`flattenQuestions` 的消费者（**这是本次改动真正的爆炸半径**）

跑过 `grep -rn "flattenQuestions" src server/src --include="*.ts" --include="*.tsx" | grep -v test`
—— **11 处**，而且其中**至少四处会静默算错**：

| 处 | 现状 | 加了任务节点之后会怎样 |
|---|---|---|
| 🔴 `server/src/routes/worksheets.ts:2077` | `flattenQuestions(content).length` = **「几道题」** | **每有一个任务就多算一道**。而它多半是校验/统计用的 |
| 🔴 `src/app/teacher/classroom/worksheet-matrix.ts:103` | `flattenQuestions(nodes).map((node, index) => …)` —— **下标即题号** | 任务节点会**占掉一行**，而所有小题的题号**整体后移** |
| 🔴 `src/app/teacher/classroom/worksheet-tile-state.ts:159` | 「整卷交齐」的判据 | 任务节点没有作答行 ⇒ 判据**永远不成立**（或永远成立，取决于写法） |
| 🔴 `src/app/classroom/worksheet/worksheet-panel.tsx:433` | 学生端要渲染的题列表 | **会把任务节点当成一道题渲染** |
| ⚠️ `src/app/teacher/classroom/worksheet-drawer-state.ts:574` | 抽屉的题列表 | 同上 |
| ⚠️ `src/app/teacher/worksheets/edit/preview-modal.tsx:61` | 「屏幕上有几道题」 | 计数偏大 |
| ⚠️ `server/src/services/export-service.ts:1133` · `routes/worksheets.ts:968/1519/2037` | 按 id 找题 / 遍历 | 任务节点会被当成题遍历 |

⇒ **结论：改 `flattenQuestions` 的返回值是错的做法**（11 处消费者，每一处都要自己判断要不要任务）。
**正确做法是让「拍平」与「题号」分家**：

- `flattenQuestions` 保持**原样**（它就是「递归展开这棵树」，与题无关）；
- 新增一个 **`flattenAnswerable(nodes)`**：**跳过 `type === 'task'`**，并带上 `{ node, heading }`
  ——`heading` 就是两级题号（`任务一 · 1`）。**所有「一道题一条」的消费者改调它**；
- 每个消费者**都要单独判断**：它要的是「树里所有节点」（校验、按 id 找题）
  还是「可作答的题」（学生端渲染、矩阵行、计数）。

🔴 **这一条推翻了我 §二 里「改拍平函数的返回值」的写法** —— 那是错的方向，
11 处消费者会因为「改了返回值」而**各自静默地错**。
