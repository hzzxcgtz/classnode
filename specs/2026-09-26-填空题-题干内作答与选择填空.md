# 填空题：题干内就地作答 + 新题型「选择填空」

> 日期：2026-09-26 · 状态：**设计，未动代码** · 来源：教师两条
>
> 1.「学生在作答区域作答这个功能，我想现在就实现……填空题：填空是在**题目文字中间**输入，
> 一道题可以包含**多个**填空区域。」
> 2.「还要增加一个新的题型，叫**选择填空**……题干下方会出现几个待选词，学生可以**拖拽**
> 它们到正确的填空区域来完成答题。」
>
> ⚠️ 这是本批**最大**的一次改动：它**改了填空题的内容形状**（要迁移老数据），
> 又**加了一个题型**（本仓加题型 = 碰到一张表就要改一串地方）。

## 现状（已核，别拿推断当依据）

- 填空题今天是**两种形状**，判据是 `Array.isArray(data.blanks)`（在 = 多空、不在 = 单空）：
  - 作答值 `{ text: string }`（单空）/ `{ texts: string[] }`（多空，与 `data.blanks` 逐位对应）；
  - 判据三处**逐字相同**：`src/lib/worksheet-answer-value.ts` 的 `isMultiBlank` /
    `blankCount`、服务端 `services/worksheet-questions.ts` 的 `judgeFillBlank` / `VALIDATORS`。
  - ⚠️ 学生端**已经**有「单空 / 多空」两套版面（`questions/fill-body.tsx`）。
- **加题型要碰的表**（`Record<QuestionType, …>` ⇒ 加一个类型，编译器会逐个点出来）：
  `server/src/services/worksheet-questions.ts` 的 `QUESTION_TYPES` / `VALIDATORS` / `JUDGES`；
  客户端 `QUESTION_TYPE_OPTIONS`（教师端的题型下拉）、`QUESTION_TYPE_ICONS`、
  `questions/index.tsx` 的分派器、教师端 `bodies/`、分析载荷、Word 导出。
- **拖拽那一套已经有了**：`src/lib/worksheet-drag.ts`（纯逻辑，有用例）+
  `use-pointer-drag.ts`（指针拖拽）+ 三个既有拖拽源的手感约定（点选为主、拖拽增强）。
- 「判断题」是**先例**：它没有自己的判分器，与单选**共用一支**（`VALIDATORS` 注释里写着）。
  ⇒ 「选择填空」的判分应当**复用填空那一支**（见下），而不是新写一份。

## 数据模型

### 空 = `promptRuns` 里**带 `blank` 标记的那一段**

```ts
interface PromptRun {
  start: number; end: number;
  bold: boolean; italic: boolean; underline: boolean; emphasis: boolean;
  color: string;
  blank: boolean;        // ★ 新增：这一段是一个填空区域
}
```

- 🔴 **不存「第几个空」这个编号**：空在第几格**由它在题干里出现的先后决定**。
  存编号就会多出一种「编号与顺序不一致」的坏数据，而那种坏数据的表现是
  **学生填对了却判错**（答案按位置取）。**顺序即编号**，这一条没有第二种可能。
- 那一段的**文字是可见的占位**（一串下划线）—— 于是导出 Word、发给 AI 的分析载荷、
  任务名那些**读纯文本 `prompt` 的地方一个字节都不用改**，它们看到的仍是一句读得通的话。
- `data.blanks`（空的数量）**删掉**：数量就是「有几个 `blank` 分段」，两处真源必须合成一处。
- 🔴 `sameStyle` / `pushRun` 必须把 `blank` 算进「同款」判据 —— 否则一个空会和它左右
  同款的普通文字**合并**，空就没了（而且没有任何报错）。

### 答案

- 教师侧：`data.answers: string[]`（每空一个，**顺序与题干里空的顺序一致**）。今天就有。
- 学生侧：作答值一律用**多空那一份** `{ texts: string[] }`（长度 = 空数）。
  ⚠️ **老作答值 `{ text }` 必须继续读得出来** —— `draftFromValue` 今天已经容错两种，
  这条不能动（改它 = 学生做了一半的题答案读不回来）。
- 校验：空数与 `answers` 长度必须一致，否则**拒绝保存**（照 `partialCredit` 那条：
  认不出就响亮地拒，不静默回落）。

### 新题型「选择填空」`choice-blank`

- `data.choices: string[]`（待选词）· `data.answers: string[]`（每空的答案）· 题干里的空同上。
- **判分复用填空那一支**（先例：判断题复用单选）：`texts[i] === answers[i]` 逐空比对，
  全对满分、部分对走容错档。⇒ **不新写判分器**。
- 🔴 校验：`choices.length >= answers.length`（每个词只能用一次 ⇒ 词不够时这道题**无解**，
  而那种题在屏幕上看不出任何异常）。
- 「用过的词从待选区消失」**是派生出来的，不是新状态**：某个待选词被用掉 ⟺ 某个空的
  `texts` 里已经有它。存一份「已用」就是第二份真源（撤销、跨设备读回都会与它对不上）。
  ⚠️ 于是「同一个词能不能占两个空」在**数据上**是允许的（判分只看每空对不对）——
  界面上不允许（拖走就消失），这是刻意的：数据宽松、界面严格，比反过来安全。

## 学生端：一个渲染器，两种题型

题干里的空**只有一处渲染实现**：走题干那套（`PromptText` 的同一份分段），
遇到 `blank` 的分段改画一个 `<input>`（键盘）或一个落点（选择填空）。

- 填空题：空就是一个输入框，**就地**在题干文字中间 ✓ 正好是教师说的那个定位。
- 选择填空：空是一个落点（`data-drop-id`），题干下方一条待选词。
  两条路都要有（本仓裁定 3「点选为主 + 拖拽增强」）：**点一个词 → 点一个空**能做完，
  拖拽是叠上去的增强。⚠️ 待选词那一层要 `touch-action: none`（三个拖拽源的教训：
  少了它老 iPad 上一按就变成滚动，学生看到的是「拖不动」）。
- 🔴 **手写作答这一档取消**（裁定 ③）：填空题不再出现「作答方式」那一行，
  `inkFormatOf` 对填空题恒为键盘。

## 教师端：编辑器要能让空**像一块整体**那样编辑

今天是 contenteditable（`prompt-editor.tsx`）+「填空区域」按钮（插一段下划线）。
本次要把那段下划线升级成**真的空**（带 `blank` 标记的分段），于是：

- 插入 = 在光标处插一个 `blank` 分段（今天那个按钮的 `insertBlank` 换个实现）。
- 🔴 **它必须是一块整体**：删一格不该把空拆成两半。
  - `Backspace` 在空的右边界 ⇒ **整个空一次删掉**（不是删一个下划线字符）；
  - 在空内部打字 ⇒ **不拆开**（`beforeinput` 拦掉，或把插入点挪到空外面）。
  - ⚠️ 这一条是本步最容易出错的地方：漏了它，空会**碎成普通文字**，
    而屏幕上看只是一个空短了一点 —— 直到学生端再也画不出那个框。
- 空格上的格式按钮（B/I/U/着重号/颜色）**照常生效**（空也是一段文字）。
- 空在题干里显示成下划线（与今天插的那串一样），教师一眼看得出空在哪。

## 迁移（老数据）

一次内容迁移，照 `worksheet-points-migration.ts` 那一套（备份 + 完成标记 + 幂等判据 + 不猜）：

1. 按老形状算出空数 `N`（单空 = 1、多空 = `data.blanks.length`）；
2. 在题干**末尾**追加 `N` 个 `blank` 分段（文字 = 占位下划线）；
3. **删掉 `data.blanks`**（形状从此只有一种）；
4. 填空题若被设成 `handwriting` ⇒ 改成 `keyboard`（裁定 ③）；一并清掉那个键。
5. ⚠️ **幂等判据**是「这道填空题的题干里一个 `blank` 都没有且它带 `data.blanks` 或需要改
   `inputMode`」—— 已经是新形状的题一个字不动。
6. 🔴 **「不猜」**：追加的位置（题干末尾）与空的数量都**照原样推出来**，不是新编的。

## 施工顺序（每步可独立验、可独立停）

1. **纯逻辑**：`PromptRun.blank` 进 `worksheet-prompt-marks.ts`（`sameStyle` 算上它、
   `readPromptRuns` 校验它、加 `blankRuns(runs)` / `blankCount(runs)` / `insertBlankRun(...)`）
   + 用例 + 变异检验。**唯一能自动验的一步，先做。**
2. **迁移**（服务端）：追加空 + 删 `data.blanks` + 手写改键盘。真库副本上核过。
3. **学生端填空题**：题干内就地输入（一个渲染器）+ 单/多空两套版面合一。
4. **教师端编辑器**：那个按钮插真空 + 空的整体性（Backspace / 打字 / 删）。
5. **新题型「选择填空」**：三张表 + 标签 + 图标 + 编辑体 + 作答体（含拖拽）+ 校验。
6. 🔴 **真机走查**。
