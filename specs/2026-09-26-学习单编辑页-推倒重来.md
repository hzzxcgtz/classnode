## 第一部分：去掉学习单级的默认给分（**与重设计解耦，先做**）

### 现状（已核）

`settings.rewardStep` / `halfStep` 今天有**三个**用途，而不是一个：

1. **老题的分值回落** —— 服务端 `resolvePoints(node, pointsFromSettings(settings))`，
   `points` 为空的题吃它们；这才是判分真正读的那条路。
2. **新题分值的种子** —— `use-worksheet-editor.ts` 的 `addQuestion` 用它们预填
   （2026-09-26 加的）。
3. 历史上是**学生奖励**的数字来源 —— ✅ **已核：学生端显示层现在不读它们**
   （服务端早把分折算进 `score` 了；`worksheet-panel.tsx` 那句注释就是这么写的）。

⇒ 教师说得对：它们已经**只是**默认值。但「只是默认值」仍然在**决定一部分题的分**
（老题），所以不能只删界面。

### 要做

1. **迁移**：`points` 为空的题 ⇒ 按它当时继承到的值写显式分值
   （`{ full: pointsFromSettings(settings).full, half: … }`）。
   ⚠️ 纪律照 `worksheet-task-migration.ts` 那一套：备份 + 幂等判据（「还有没有 `points` 为空的题」）
   + 「迁移不猜」（写的是**已经生效的那个值**，不是新编的）+ 「空学习单不造东西」。
2. **拆掉回落**：`pointsFromSettings` 与 `resolvePoints` 的第二参**一路删掉** ——
   迁完之后分值的来源从**两个**变成一个（逐题），这是这一改真正的收益。
3. **界面**：设置面板里那两行（「每答对一题得几个」「每答对一部分得几个」）删掉。
   注意 `rewardStyle`（星星 / 花朵 / 分数）**留着** —— 那是**形式**，与分数无关。
4. 新题的种子改用 `DEFAULT_POINTS`（1 / 0）。
5. `settings` 里那两个键**留在 JSON 里但不再被读**（老行还带着它们；删类型会让读旧行出错）。

⚠️ **未核**：`DEFAULT_SETTINGS` / `normalizeSettings` 里那两个键的归一化今天还有谁在用，
动手前跑一次 `grep -rn "rewardStep\|halfStep" src server/src --include='*.ts' --include='*.tsx'`。

## 第二部分：折叠（②）

### 折叠态（一题一行）

```
▸ 1  单选题   光合作用的产物是？                      1 / 0 分   ▲▼⧉🗑
▸ 2  填空题   水的化学式是____                        1 / 0 分   ▲▼⧉🗑
▾ 3  问答题   说说你对光合作用的理解                  2 / 0 分   ▲▼⧉🗑
   ┌ 展开后 = 今天的整张卡（题干 / 作答方式 / 分值 / 开关 / 判分依据 / 编辑体）
```

- **只有一张展开**（点另一张 ⇒ 前一张收起）。理由与焦点态同源：两张都展开就都没有重点。
- **折叠态必须够看**：题号 · 题型 · **题干一行**（长了省略号）· 分值 · 工具。
  教师靠它扫一遍全卷、也是他校对的地方。
- ⚠️ `QuestionCard` 的 `showInputModeRow` / 分值行 / 自动评分开关 / 判分依据
  **全部只在展开时渲染** —— 这也是「太长」的主要来源（一个可判分的题现在有 4 行设置）。
- ⚠️ **未核**：折叠要不要持久化（刷新后展开哪一张）。若不持久化，刷新回到全折叠 ——
  对 20 题的页面是**可接受**的默认，但改完一道题刷新会丢失焦点，先按「不持久化」做。

### 与既有结构的关系

`editorRenderBlocks`（内核里、有用例）已经把「任务 + 它的小题」切好了，折叠态是**它的渲染**，
不是新的结构 ⇒ **不要**再写一份遍历。

## 第三部分：专业工具感（③ 的第一条）

按**收益 / 成本**排序，前三条建议本次做：

| # | 做什么 | 为什么它属于「专业工具」 |
|---|---|---|
| 1 | **键盘快捷键**：`⌘Z/⇧⌘Z` 撤销重做（**已有 reducer，只差接线**）· `↑/↓` 在题间移动焦点 · `Enter` 加题 · `⌘S` 保存 | 问卷星那种「顺手」的一大半来自这里 |
| 2 | **拖拽排序**（任务级与小题级），落点用一条线而不是整块高亮 | 今天只有 ▲▼，20 题时点 19 次 |
| 3 | **左侧题号栏 / 题号跳转**：一屏看全局，点号直达 | 「一屏看全局」是工具与表单的分界 |
| 4 | 批量操作（选中多题一起删 / 移动 / 改题型） | 收益真实但成本高，**建议往后放** |

⚠️ 拖拽要用**指针事件**（不是 HTML5 DnD）：学生端的拖拽（`use-pointer-drag.ts`）已经踩过
一遍坑（老 iPad 上 HTML5 DnD 不可用），教师端虽然桌面为主，但这一页也可能在触屏笔记本上开。

## 第四部分：视觉（③ 的后两条）

### 保留（第一轮的结论，别推翻）

间距刻度 4/8/12/16/24 · 圆角三档 12/8/6 · **题干是主角** · 只有一张亮（焦点态）·
投影只给浮层 · 强调色只给「可点的、当前生效的」。

### 要补的（第一轮没做到的）

1. **页面头**：今天只有一个标题输入框 + 一排按钮。要有**这一页自己的样子** ——
   标题、题数、总分、保存状态在同一处，且与下面的卡片**明显分层**。
2. **任务容器要有自己的身份**：今天它是「底色 `#f8fafc` + 边框」的朴素盒子。
   一个任务的**编号/名称/小题数/分值合计**应当在折叠态就看得见。
3. **节奏**：折叠之后，**行与行之间用 4 或 8**（它们是同一个列表的项），
   而**任务与任务之间用 24**。今天的 16 是「卡片」的间距，折叠之后不再适用。

### 反面清单（沿用第一轮，仍然有效）

❌ 不加图标装饰 / 渐变 / 彩色标签 · ❌ 不动作答控件的语义 · ❌ 不把分数提到与题干同级。
