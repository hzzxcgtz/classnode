## 动手前核到的现状（别拿推断当依据）

- **连线题已经有指针拖拽**：`match-body.tsx` 引 `usePointerDrag`，按住左项拖到右项即可连；
  另有「点一下右项」也能连/取消（走同一份 `links`）。
- **线只在连上之后才画**：`match-body.tsx` 量两端元素的坐标画 SVG 线（`key: leftId:rightId`）。
  ⇒ **拖动过程中没有任何反馈**，这正是教师第 1 条要的。
- **删除已有**：~~点一下**已连的**右项会走 `clearPair` 取消~~ ——
  🔴 **2026-09-26 施工时核出这句话是错的**：`match-body.tsx` 的 `onTap` 第一句就是
  `if (!leftId) { … return }`，**没选左项时点右项什么都不做**。删一条线当时的真实路径是
  「先点左项 → 再点右项」**两步** —— 所以教师说它「很不起眼」，比这句话描述的更严重：
  屏幕上根本没有任何东西告诉学生第一步该点哪儿。已按裁定 ② 改成**一步**。
- **排序题的拖动**：同一个 `usePointerDrag`，拖起来的那一项今天只有位置变化，
  没有跟手、也没有让位。
- **纯逻辑在 `src/lib/worksheet-drag.ts`**（`setPair` / `clearPair` / `reorder` /
  `moveInOrder` / `tapSource`…），它是**可测的那一半**（`worksheet-drag.test.ts`）。

## 教师已答的三条（本次裁定）

| # | 问题 | 裁定 |
|---|---|---|
| ① | 跟手的线做到什么程度 | **一条跟随的线 + 可落的右项高亮** |
| ② | 「提交上要可以删除」指哪一件 | **已连的线点一下就能删，且要更明显**（行为不变，仍是 `clearPair`；纯学生端，**不碰服务端**） |
| ③ | 排序题的动画 | **拖起来的那一项跟手 + 其余项让位**（transform 平滑） |

## 三条硬约束（本仓对 `/classroom/` 的既定纪律）

1. 🔴 **动效只碰 `transform` 与 `opacity`**，并在 `prefers-reduced-motion` 下**降级**
   （先例：`shell.module.css` 的降级块）。**不要**动 `width/top/left/margin`。
2. 🔴 **`scripts/check-classroom-browser-compat.mjs` 扫 `src/app/classroom` 与 `src/lib`**：
   禁 lookbehind / `:has()` / `@container` / `content-visibility` / `color-mix(` /
   `Object.hasOwn` / `structuredClone` / `.at(` / `findLast`。**改完必须跑一次**（不是 `pnpm build`
   —— 那个会把跑着的 dev 弄崩，见那一条记忆）。
3. ⚠️ **触屏优先**：老 iPad 上没有 hover、指针事件要 `touch-action` 配合
   （教师端的拖拽把手已经踩过这一次：不写 `touch-action: none` 就会被当成滚动）。
   **每帧的重算要限量**（跟手的线每帧都在动 —— 只改 `transform` / SVG 的 `x2 y2`，
   不要去读一堆元素的 `getBoundingClientRect`）。

## 施工顺序（每步可独立验、可独立停）

1. **跟手的线 + 右项高亮**（连线）—— 教师第 1 条。拖动中画一条从起点到手指的线；
   指针进入某个右项时给它一个「可落」的样子。落点判据**复用** `use-pointer-drag` 现成的
   `data-drop-id` 命中（与其它题型同一条路）。
2. **删线的可见入口**（连线）—— 教师第 2 条。已连的右项上给一个看得见的删除提示
   （仍是 `clearPair`）。⚠️ 别新加一套状态：**同一个 `links` 数组**是唯一的真相。
3. **排序的拖动动画**（排序）—— 教师第 3 条。拖起来那项跟手 + 其余项 `transform` 让位；
   `prefers-reduced-motion` 下**不做**过渡（直接换位）。

## 做完之后（2026-09-26）

三步都做了。**机器能验的全绿**：两端 `tsc` 0 · `eslint` 0 error · 客户端 475/475 ·
服务端 691/691 · 兼容门禁过。新增的纯函数都做过**变异检验**（改坏实现 ⇒ 对应用例变红）：

| 新增（`src/lib/worksheet-drag.ts`） | 钉住什么 |
|---|---|
| `tapTarget(links, leftId, rightId)` | 点右项那一下的三条规则（断开 / 改连 / 连上） |
| `slotIndexAt(centers, y)` | 落第几格；等距时取更靠前的（不许抖）；空表 ⇒ -1 |
| `dragShifts(centers, from, to)` | 让位挪几像素；**一格多高由那一格自己决定**（条目会折行） |

**施工中改了三处 spec 没写、但不动就做不成的地方**（细节见
`.superpowers/sdd/2026-09-26-学生端-连线与排序的交互/progress.md`）：

1. `usePointerDrag` 加了每帧的 `onDragMove`（命令式，回调里**不许** setState）；
2. `onDrop` 的契约改成「移动过就调，`targetId` 可以是 `null`」——
   排序题的落点由让位算出来，而让位之后**被拖那一项的原槽位是空的**；
3. 序号在拖动中由 JS 改写（让位之后第 3 条跑到第 2 格，数字还写着 3 就是错的）。

⚠️ 顺带**删掉**了排序题的「落点高亮」（`orderItemOver`）：让位之后它是同一件事的
第二份真相，会与落点对不上。
