### 三条数据腿（这一节是第 1 条的根因）

| 来源 | 有什么 | 谁在用 | 历史 |
|---|---|---|---|
| `GET /api/worksheets/:id` | `content.nodes` + `settings`（含 `rewardStyle`） | 格子数格数、抽屉画题号 | 只有题目 |
| `GET /api/worksheets/classroom/:id/answers` | 全班作答行**快照**：`status`/`gradeState`/`score`/`value`/`reviewedAt` | **只在**打开抽屉（`page.tsx:890`）与矩阵开着时 30 秒轮询（`page.tsx:917`） | ✅ |

- 学生端的 `GET /:id/answers`（`use-worksheet-answers.ts` 的水合）**不发广播** —— 服务端只有两处 emit：`worksheets.ts:2073`（PUT）与 `:2212`（submit）。

## 5. 协议与数据模型改动

### 5.1 `WorksheetAnswer` 加三列（都可空、都不带默认值 ⇒ ALTER 安全）

```prisma
  createdAt DateTime? // 这一题**第一次**落库的时刻（首次 insert 时写）
  updatedAt DateTime? // 最近一次落库的时刻（每次 PUT / submit 都写）
  saveCount Int?      // 落库次数（每次 PUT / submit 都 +1）
```

加在 `server/src/services/worksheet-schema.ts` 的 `ensureWorksheetAnswerColumns`（`:197`）里，
照 `gradeState` / `score` 那两行的写法（`:205` / `:209`）——那里已经有 `PRAGMA table_info` 守卫。
⚠️ **不要**用 `@updatedAt` / `@default(now())`：SQLite 的 `ALTER TABLE ADD COLUMN` 不接受非常量默认值，
而本项目的升级路径是启动期 `ALTER`（`schema.prisma` 里写 `@default(now())` 只在**新建库**时生效，
两条路会长成两种样子）。写入侧显式赋值，与 `submittedAt` 同一条做法。

**旧行一律是 `NULL`**，含义是「不知道」——读的一侧**不许**把 `null` 当成「刚刚」或「很久以前」，
只能不显示那一项（见 §6.4）。

### 5.2 广播加两个字段（`worksheets.ts:1704` 的 `broadcastAnswerUpdate`）

```ts
    // 学生此刻这一题的内容（乙档）。⚠️ 超过上限时**不发**，同时置 valueOmitted，
    // 看板据此说「内容较大，打开详情查看」——**不许静默截断**（截断的答案读起来是学生的原文）。
    value: omitted ? undefined : answer.value,
    valueOmitted: omitted,
    // 本次落库的时刻（丙档）。看板「距上次保存」的实时依据。
    savedAt: <ISO 字符串>,
    // 这一题至今落库了几次（丙档）。**必须进广播**：抽屉在教师眼前开着时，
    // 「已保存 N 次」也要跟着学生一起涨 —— 只靠 30 秒快照会跳着涨，读起来像丢了数据。
    saveCount: answer.saveCount,
```

- 上限取 `MAX_BROADCAST_VALUE_CHARS = 8192`（`JSON.stringify(answer.value)` 的长度）。理由：笔迹的
  `strokes` 数组会长；文本作答远在其下。**超限只挡 `value`，`savedAt` / `saveCount` 照发。**
- ⚠️ 首次落库（insert）时 `saveCount` 必须是 `1` 而不是 `null` —— 写入侧若漏了这一步，
  新答的题会显示成「不知道保存过几次」，而它与旧行长得一模一样。
- `src/lib/socket-events.ts:111` 的事件类型要一起加（那里写着「协议字段，只增不改」）。
- ⚠️ `broadcastAnswerUpdate` 的注释里有一段「哪些地方引用过这个事件」的实测清单（`:1713-1725`），
  改完要**重跑那条 grep 并把数字改掉** —— 那是一句会过期的话。

### 5.3 读端点的答案行加三列（`worksheets.ts:920-935` 的 `select`）

`createdAt` / `updatedAt` / `saveCount` 三个都要进 `select`。
⚠️ 漏 select 一列的表现是**那一项永远不显示**，而响应里没有任何东西缺一块 —— 与那里已有的
`gradeState` / `score` 那段警告同源。`src/lib/types.ts` 的 `WorksheetBoardAnswerRow` 同步加。

### 5.4 新事件 `worksheet-answers-cleared`（第 4 条）

```ts
'worksheet-answers-cleared': (data: {
  classroomId: string;
  participantId: string;
  worksheetId: string;
  /** 只清一题时带；整张清除时是 null。 */
  questionId: string | null;
}) => void;
```

**两个房间都要发**（这是第 4 条最容易漏的一处）：

- `teacher:${classroomId}` —— 看板刷新那一格 / 矩阵那一列 / 抽屉那一行；
- `student:${studentId}` —— 学生端重置本地状态（房间名见 `socket/index.ts:1145`）。
  ⚠️ 事件发给的是 `studentId`，而 `participantId` 是 `ClassroomStudent.id`；小组 / 高级模式下
  一个组一块设备、`ClassroomStudent.studentId` 可能为 null ⇒ **发不出去就只发教师那一侧**，
  不要为了凑一个 id 去猜（学生端下次水合会自然对齐）。

### 5.5 新端点（第 4 条）

```
DELETE /api/worksheets/classroom/:classroomId/answers
  body: { participantId, worksheetId, questionId?: string | null }
```

- **教师专用**。路径是**四段**，落在 `worksheetAccessGate`（`worksheets.ts:104` 那三条正则）之外 ——
  但**必须**在那里补一条用例正面断言它对学生是 403：那三条正则都是「恰好两段 / 三段」的形状，
  将来有人挪动路径就可能顺手放行（`:95-97` 已经为同类风险留过一段警告）。
- 删的是 `WorksheetAnswer` 行（按 `responseId` + 可选 `questionId`）；**删完若 `WorksheetResponse`
  一行答案都不剩，把那个 response 也删掉** —— 留着它就是一行「这个人开了这份单但什么都没做」，
  而看板「已交 N/M」的分母是参与者数、不受影响，真正的问题是它会挡住「首次作答」的判定。
- 🔴 **奖励不用单独清**：它派生自 `score`，答案行删了奖励自然归零。这是这个设计的优点，
  §8 的确认文案里要说出来（教师会问「奖励清不清」）。
- 清完调 `broadcastAnswerUpdate` 的**兄弟**：`worksheet-answers-cleared`（§5.4）。
- 返回 `{ success: true, removed: <删掉几行> }` —— 确认文案里的「7 题」就是它。

## 6. 统一数据层（第 1 条，本次最大的一块）

### 6.1 目标形状

一个 hook **`src/app/teacher/classroom/use-worksheet-board.ts`**，拥有全部学习单数据：

```ts
export function useWorksheetBoard(classroomId: string | null): {
  /** REST 快照（原 `worksheetBoard`）。`null` = 一次都还没到。 */
  board: WorksheetBoard | null;
  loading: boolean;
  /** 学习单 id → 题目树（原 `worksheetNodes`）。 */
  nodesByWorksheet: Record<string, WorksheetQuestionNode[]>;
  /** 学习单 id → settings（**新增**，奖励换算要用；原来只留了 nodes）。 */
  settingsByWorksheet: Record<string, WorksheetSettings>;
  /** 参与者 id → 合并后的进度（**新**，格子与矩阵都吃它）。 */
  progress: Record<string, ParticipantWorksheetProgress>;
  /** ★ 快照发起的时刻 —— 广播陈旧下界（矩阵原来那个 `matrixSnapshotAtRef` 的替身）。 */
  snapshotAt: number;
  /** 立刻重拉一次（教师点了清除之后调它）。 */
  refresh: () => void;
};
```

### 6.2 合并规则（照抄矩阵，理由在 `worksheet-matrix.ts:74-98`）

- **底**：`GET /classroom/:id/answers` 的快照 → 逐参与者的 `cells`（`status`）；
- **增量**：`worksheet-answer-updated` 广播 → 覆盖快照里那一格；
- **下界**：`progress[p].lastAt > snapshotAt` 才信广播。**方向只会丢陈旧数据，不会丢新数据。**

⚠️ 矩阵今天自己拿 `live` + `liveTrustedAfter` 两个入参（`buildWorksheetMatrix` 的签名），
统一之后这两个改从 hook 出 —— **矩阵的签名与它的用例不动**（那是已验证过的纯函数，别顺手改）。

### 6.3 节拍（本次唯一新增的运行成本）

| 什么 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 作答行快照 | 只在**矩阵开着**时 30 秒轮询 | **常开** 30 秒轮询 | 这是第 1 条的修法本体：格子必须也在拉 |
| 题目树 | 60 秒 | 60 秒（不变） | 教师课上加题不广播，这条另有理由 |

⚠️ 两个闸，缺一个就是白烧电：

- `worksheetIds.length === 0` 时不轮询（课堂上没配学习单）；
- `document.visibilityState !== 'visible'` 时跳过这一拍（教师切到别的标签页）。

### 6.4 ★ 「停住了」的时钟账（本次必须处理，否则是静默错）

「停住了」的判据是「距最后一次保存 > 5 分钟」（`worksheet-tile-state.ts:185`），
它今天吃 `lastAt` + `nowMs`，**两个都是浏览器时钟**（矩阵的注释 `:93-94` 专门解释过为什么这样选：
偏差相消）。接了 REST 之后，历史那一侧的保存时刻是**服务端时间** —— 两边不同源，直接比会静默算错。

**改法：把判据从「两个时刻」换成「一个时长」。**

```ts
export interface WorksheetTileInput {
  // 旧：  lastAt: number（进度里）+ now: number（入参）
  // 新：
  /** 距最后一次保存过了多久（ms）。`null` = **不知道**（历史行没有 updatedAt，或快照里那一格是空的）。 */
  idleMs: number | null;
  …
}
```

- 时长在**收集侧**算好，两边各自用同源的两个时刻相减：
  - 历史那一侧：服务端下发 `updatedAt` 与一个顶层 `serverNow`，**在浏览器里相减** —— 服务端时钟偏差相消；
  - 广播那一侧：浏览器时钟 `Date.now() - savedAt`。
- `idleMs === null` ⇒ **不算「停住了」**，落 `working`（保守的一侧：宁可不报，也不把「不知道」说成「他卡了 5 分钟」）。
- `worksheet-tile-state.test.ts` 里「停住了」那几条用例的入参要跟着换。**换的是入参形状，不是判据阈值**（仍是 5 分钟）。

### 6.5 三处消费方怎么改

| 消费方 | 今天 | 改成 |
|---|---|---|
| 格子（`page.tsx` `worksheetTileState` 调用处） | `worksheetProgress[cs.id]` | `progress[cs.id]` + `idleMs` |
| 矩阵（`buildWorksheetMatrix` 调用处） | `worksheetBoard` + `worksheetProgress` + `matrixSnapshotAtRef` | `board` + `progress` + `snapshotAt`。**纯函数的签名一个字节都不改** |
| 抽屉 | `worksheetBoard`（每次打开重拉） | `board`（来自 hook）。⚠️ `entry.token` **保留** —— 它管的是下钻栈重置（`worksheet-drawer.tsx:78`），与数据新鲜度是两件事，别一起删 |

⚠️ `reviewWorksheetAnswer`（`page.tsx:931`）今天就地改 `worksheetBoard` 那一行的 `reviewedAt`。
统一之后那个 setter 在 hook 里 ⇒ 它要变成一个 hook 暴露的动作（**不能**让调用方直接改快照）。
理由不变：教师的动作是逐题点的，每点一次重拉整堂课会让滚动位置跳。

## 7. 抽屉形态 A 的新长相（第 2 条 + 第 3 条）

### 7.1 顶层总览（新增）

```
┌─ 花荣 · 学习单《秋天的雨》 ─────────────┐
│ ✓4 ½2 ✗1 ─3                 奖励 ⭐ 6 │
├──────────────────────────────────────────┤
```

- 四个计数**逐题数出来**，判据进 `worksheet-drawer-state.ts` 的新纯函数
  `participantOverview(nodes, rows, rewardScale)`（有测试的那一侧 —— JSX 里没有回归网）。
- 「─3」= 未作答（`status === 'unanswered'`）。主观题**不计入** ✓/✗，它们各自落哪一档要在函数注释里写死：
  主观题没有判分结论 ⇒ 落「已提交（无对错）」那一档，**不进 ✓ 也不进 ✗**。
- 奖励：`resolveRewardScale(settings)` + 逐行 `rewardAmount(scale, row.score)` 求和。
  `settings` 缺（还没加载到）时**显示「—」而不是 0** —— 0 是一句假话（学生会以为他一分没得）。
- 奖励为 0 时显示 `奖励 ⭐ 0`（不是隐藏）：「他答了 4 题拿 0 个」和「他还没答」是两件事。

### 7.2 逐题行（现有 `questionOutcome` 的输出，加两样）

保留今天的：题号 · 题型 · 状态词 · ✓/½/✗ · 学生原答案 · 「标记已查看」按钮。
**新增**：

- **进行中的那一题默认展开**（其余折叠）—— 判据是 `status === 'draft'`；多题同时 draft 时展开**最后保存的那一题**（`updatedAt` 最大的那一条），没有则全部展开。这条判据也进纯函数。
- **进行中那一题的过程区**（§7.3）。

### 7.3 过程区（第 3 条，乙 + 丙）

```
│ ▾ 任务二 · 1 · 判断题        ◐ 作答中 │
│   ┌──────────────────────────────┐ │
│   │ 首次作答 12 分钟前 · 已保存 3 次 · 最近 40 秒前 │
│   │ 当前答：对                              │
│   └──────────────────────────────┘ │
```

三段的**诚实边界**（每一段都要能对「不知道」说不出来，而不是编）：

| 段 | 来源 | 不知道时 |
|---|---|---|
| 首次作答 | `createdAt` | 整段省略 |
| 已保存 N 次 | `saveCount` | 整段省略 |
| 最近 Y 前 | `updatedAt`（历史）/ `savedAt`（广播） | 整段省略 |
| 当前答 | `value` → `formatAnswer` | 显示「（这一题的内容较大，打开详情查看）」当 `valueOmitted` |
| 笔迹 | `value` 是 ink ⇒ 画 `InkPreview` 缩略图 | 与「什么都没画」区分：只有 `value` 在场才画 |

🔴 **`saveCount` 是从这次改动之后才开始数的**：旧行的 `saveCount` 是 `null`，显示成「已保存 3 次」
会把一个从零开始的计数说成他的历史。所以 `null` 时**整段省略**（上表那一列）。

## 8. 清除数据（第 4 条）

### 8.1 两个入口

| 粒度 | 位置 | 文案 |
|---|---|---|
| 整张 | 格子的按钮组里（与学伴那个垃圾桶同一排） | 「清除学习单数据」 |
| 单题 | 抽屉逐题行右侧 | 「清除这一题」 |

⚠️ 学伴那个垃圾桶**只在内容区真的显示学伴对话时才出现**（`page.tsx:2625` 的注释）。
同理，学习单这个按钮**只在 `tileModule === 'worksheet'` 时才出现** —— 判据与 `tileShowsClear` 同源。

### 8.2 确认文案（裁定 ④）

```
确定清除「花荣」在《秋天的雨》上的全部作答？
共 5 题有作答记录：3 题已提交、2 题作答中。
奖励（⭐ 6）由判分派生，会一并归零。
此操作不可撤销。
```

- 那个 **5 是这一份学习单上**有作答记录的行数（`participant.answerRows.length`），
  而 `answerRows` **只含有动作的题** ⇒ 文案逐字写「共 N 题**有作答记录**」，**不是**「共 N 题」。
  ⚠️ 它**小于**学习单的总题数，所以**不要**写成「3 题已提交、2 题作答中、2 题未作答」那种
  加起来等于总题数的形状 —— 那会让教师以为清掉了 7 题、其实只清了 5 题。
  这里的「未作答」不是清的对象（没有行可清），列出来只会让他困惑。
- 「奖励（⭐ 6）」那一段**只在奖励不为 0 时才出现**：0 的时候说一句「奖励会一并归零」是废话，
  而且会让教师以为他刚才有过奖励。
- 三段计数与抽屉总览**走同一个纯函数**（不许在确认框里自己再数一遍 —— 与 `rowTally` 那条
  「组件不许自己再数一遍」的教训同源，见 `worksheet-matrix.ts:183`）。

### 8.3 清完必须做的三件事

1. `refresh()` 重拉快照（别就地改，跨多处状态）；
2. 广播 `worksheet-answers-cleared`（§5.4）；
3. toast：「已清除 花荣 的 7 题作答」（数字取自端点返回的 `removed`）。

### 8.4 🔴 学生端必须真的重置（否则会被写回去）

学生端收到 `worksheet-answers-cleared` 后：

- **丢掉本地队列里那个 scope 的待保存项**（`use-worksheet-answers.ts` 的 `pendingRef`）——
  不丢的话，那一次防抖保存会把内容原样写回，教师会看到「清了又回来了」；
- **清掉本地 `savedAnswers` 里那个 scope 的内容**，再按服务端现状重水合；
- 若被清的正是他当前打开的那一题 ⇒ 面板回到空输入态。

⚠️ 这一条要在 `use-worksheet-answers.ts` 里挂一个 `on(...)` 订阅；**该文件今天零 socket 订阅**，
是这个组件第一次直接听广播 —— 订阅的挂载/卸载要与既有的 effect 结构对齐（别在渲染里 `on`）。
