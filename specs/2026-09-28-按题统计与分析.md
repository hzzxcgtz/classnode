## 1. 现状（已核，别拿推断当依据）

### 1.1 这个功能**已经建了一半**（最重要的一条）

M7a/M7b 就是「把全班这份数据交给一个 `purpose: 'analysis'` 的智能体、把解读呈现在看板上」：

| 已有的 | 在哪 |

| 分析载荷（全班文字聚合 `text`、绘图题的**联系表** `sheetLayouts`、**逐生匿名标签** `entries`、`covered/total`） | `server/src/routes/worksheets.ts` 的 `/:id/analysis/:questionId` |

## 3. 🔴 判据的硬线：本地**只计数，不判分**

这一节是本 spec 最容易做错的地方，而做错了**不报错**。

| | 谁算 | 例子 |
|---|---|---|
| **判分档**（全对 / 部分 / 错 / 未判） | **只读行里的 `gradeState`**（服务端判过的） | 页头那四格、堆叠条、正确率 |
| **分布计数** | 本地算 | 多少人选了 B、多少人把「水」连到「CO2」、第 2 空有几种写法 |

**为什么判分档一律不本地算**：排序带**容差**（服务端 `judgeOrder` 的 `meetsTolerance`）、
填空有**多个可接受答案** —— 本地重算就是**第二份判分实现**：服务端改了规则它不会跟着变，
而两边都不报错。本仓被这个形状咬过不止一次。

**为什么分布计数可以本地算**：它**没有规则可写错** —— 「谁选了什么」「谁连了哪一对」
是纯粹的**数数**，不涉及任何判据。

> ⚠️ 顺带澄清一处**看起来矛盾、其实不矛盾**的地方：教师上一轮说过看板格子那块
> 「只显示学生的作答，不需要判对错、不需要给答案」。那说的是**格子里的实时预览**
> （「他此刻在写什么」）；**这一屏要的正是对错统计**（教师原话「全面的了解……答题情况
> 统计和分析」）。两处用途不同，不冲突。

## 4. 逐题型的图与文字

**页头（所有题型共有）**：一句话结论 + 四格数字（已交 / 全对 / 部分 / 错）+ 一条堆叠条。
🔴 **每一个百分比都要写清分母**（本仓反复栽在分母口径上）：文字一律写
「**已交的 9 人中**，63% 选了 B」，而不是裸的「63%」。

**统计只数 `status === 'submitted'` 的行**：草稿还在变，混进去会让分布一直跳。
分母写在页头（`已交 N/M`），每一句文字都从它出发。

| 题型 | 图（手写） | 文字（**只陈述算得出来的事实**） |
|---|---|---|
| **单选 / 判断** | 选项分布横条（正确项标绿） | `已交 8 人中，5 人选了 B（正确答案），2 人选了 A` |
| **多选** | 横条 + **选答组合 Top 3** | `12 人漏选 C；5 人多选 D` |
| **填空** | **每空高频答案 Top 5**（带人数） | `第 2 空：40% 写了「O2」（共 6 种写法）` |
| **表格填空** | 逐格答案频次（行×列小格） | `第 3 行第 2 格有 6 种写法` |
| **排序** | **「排对了几位」分布** + 错误顺序 Top 3 | `3 人完全正确；12 人把「合成有机物」排在第 1 位` |
| **连线** | **左 × 右 热力矩阵**（每条线多少人连） | `12 人把「水」连到了「CO2」` |
| **归类** | **条目 × 框 矩阵**（每格多少人） | `「麻雀」15 人放进了哺乳类` |
| **问答题** | ⏸ 预留（§6）+ 字数分布 | ⏸ 智能体 |
| **绘图题** | ⏸ 预留（§6）+ 缩略图墙 | ⏸ 智能体 |

### 4.1 计数键（每一型各是什么，写清楚免得实现时自己发明）

| 题型 | 计数键 | 判据 |
|---|---|---|
| 单选 / 判断 | 选项 `key` | 只认**提交过**的行为「选了」 |
| 多选 | 选项 `key` **逐个**计 + **组合**（选中集合排序后 join）另计 | 组合的 key 必须**排序**，否则 `AB` 与 `BA` 会算成两组 |
| 填空 / 表格 | `文本`（**trim 前后空白**，不合并大小写） | ⚠️ 「H2O」与「h2o」算**两种** —— 不合并是有意的：合并需要「什么是同一个答案」的规则，而那正是本 §3 拒绝的那类判据 |
| 排序 | 位置 `index` → 有多少人排对 | 「排对」= 该位与学生答案逐字相同 |
| 连线 | `(leftId, rightId)` **对** | 一对一行，**多对多**也照数（本批已支持） |
| 归类 | `(itemId, zoneId)` | 放进了**不存在的框**时不计（教师改题删了那个框） |

### 4.2 跨题型都有的「过程统计」

用本批刚加的 `createdAt` / `savedAt` / `saveCount`（**今天已经在库里、一处都没用上**）：

- **作答用时分布**（`savedAt - createdAt`）；
- **修改次数分布**（`saveCount`）；
- **还没交的名单**（点名字跳到那个学生的那一题）。

⚠️ 这三项的**诚实边界**（与抽屉「过程区」同一条纪律）：旧行这三列是 `NULL`，
含义是**「不知道」**——那时**整段不显示**，而不是显示 0。

## 5. 图表：手写 SVG / div（裁定 ④）

需要的图只有三种，全是矩形拼的：

1. **横条**（选项分布、每空频次、排对了几位）—— 一个 `div` 宽度按比例；
2. **矩阵热力**（连线左×右、归类条目×框）—— CSS grid + 背景深浅；
3. **堆叠条**（页头那条、题列表的迷你条）—— flex + 百分比宽度。

🔴 **两条纪律**：
- **不引 recharts**（裁定 ④）。本屏的图不需要坐标轴/图例/交互，而 `ResponsiveContainer`
  在一个宽度可变的容器里要额外调；手写反而更短、更贴。
- **颜色不承载唯一信息**：矩阵与横条都要**同时给出数字**。红绿对色觉障碍教师不友好 ——
  这在本仓是有先例的（看板格子的配色刻意选了明度差大的那一组，而不是红绿）。

## 11. 我没核过的

- **`analysis-overlay.tsx` 抽 `AnalysisBody` 的代价**：我只读了它的行为（载荷/生成/stale/
  narrative），**没有逐行读它**。若它内部的 state 与整屏外壳耦合得紧，第 5 步会比预计大。
- **矩阵那条路对「题」的依赖**：`openMatrixQuestion` 把 `{kind:'question'}` 交给抽屉
  ⇒ 第 3 步搬走抽屉第三层时，**矩阵那条路会经过一个空层**。要在第 3 步里一并处理
  （要么保留第三层，要么把矩阵那条路也改到新浮层）。
- **排序题的「错误顺序 Top 3」**：我核到 `judgeOrder` 的 `correct` 那一支是**纯等式**
  （长度相同 + 每位相同，在容差之前返回）⇒ 本地算「完全正确」与服务端逐字一致。
  但「错误顺序」这个说法本身是**描述**、不是判分，我没有核过教师在屏幕上会不会把它
  读成一个判分结论。若会，改成「最常见的顺序（不是答案）：…」。
- **820px 这个宽度**：我按「矩阵 250 / 分析 270 那两屏的观感」估的，**没有量过**
  教师那台设备的实际视口（iPad 横屏是 1024px 宽，820 放得下；竖屏 768 就满了）。
