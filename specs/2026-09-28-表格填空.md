# 表格填空（结构化网格）

> 日期：2026-09-28 · 状态：**设计，未动代码** · 来源：教师一条
>
> 「我想增加一个表格填空的功能，就是学生可在教师提供的表格中在指定的位置填空答题。」
>
> 教师先问「升级原来的填空题，还是新增加一个题型」，分析之后裁定：**升级填空题**
> （不新增题型），表格用**结构化网格**（不是题干里的管道文本），教师端有**自己的网格面板**。

---

## 教师已定的四条（本次全部依据）

| # | 问题 | 裁定 |
|---|---|---|
| ① | 升级填空题还是新增题型 | **升级填空题** —— 题型仍是 `fill-blank`，表格挂在 `data.table` 上 |
| ② | 表格在题干里的位置 | **固定渲染在题干文字之后** —— 题干里**不留任何标记**，表格插不进文字中间 |
| ③ | 教师端怎么编表格 | **乙-1**：网格面板（所见即所得）+ 题目卡里一份**常显的只读「卷子样子」**；题干文字区不碰 contenteditable |
| ④ | 表格题的分数口径 | **甲**：沿用既有语义（逐空得分），**不改判分**，只把「本空几分 × 几个空」算给教师看 |

**为什么 ① 不是「新增题型」**（这一段是本次最重要的一个决定，别被下一个人改回去）：

- `choice-blank`（选择填空）是先例：它加题型时**判分器是复用的**（`JUDGES` 表里
  `'fill-blank'` 与 `'choice-blank'` 指向同一个 `judgeFillBlank`），它新增的只有
  `data.choices`（待选词）与「学生怎么答」这个交互。⇒ 本仓加题型的正当理由是
  **「学生怎么答」变了**，不是「题干长什么样」变了。
- 表格填空里，学生**怎么答**没变（还是第 i 个空填一个字符串，作答值仍是
  `fill/v1` / `fill-multi/v1`），判分逐字相同；变的只有**空排在哪儿**。
- ⚠️ 加一个 `QuestionType` 会牵动一串表：服务端的 `QUESTION_TYPES` / `VALIDATORS` /
  `JUDGES`（三张 `Record<QuestionType, …>`，漏一个是编译错），客户端
  `QUESTION_TYPE_OPTIONS` / 题型图标 / `questions/index.tsx` 的分派器 / `bodies/` /
  分析载荷 / Word 导出 —— 而它们**全都是填空那一套的复制**。一份逻辑摊成两份，
  正是本仓反复栽的那类分叉。

## 现状（已核，别拿推断当依据）

### 空今天是什么

- 空 = `node.prompt` 里**字面的 `{填空域}`**（**5 个普通字符**，`prompt-editor.tsx:128`），
  外加 `data.promptRuns` 上一条带 `blank` 标识的分段。判据在
  `worksheet-prompt-marks.ts:414` 的 `recognizeBlanks` —— 教师 2026-09-27 裁定：
  **「是不是空」完全由文本决定**（理由逐字记在那一段：这件事本来在 DOM 那层，
  而那一层**本机一行都跑不到**）。
- `PromptRun.blank` 是**空的身份**（`worksheet-prompt-marks.ts:41-66`），**不是答案序号**。
  答案序号 = `blankRuns(runs)` 的顺序（从左到右）。
- ⚠️ **编辑区里空不是原子对象**：`prompt-rich-text.ts:44-51` 明写「只负责画成灰底，
  **不再** `contenteditable=false`、不再接管光标与删除键」，原子化那一整套已删。
  ⇒ 教师今天看到的是**灰底的 5 个字符**，不是成品。**这是表格这次可以做得更好的地方。**

### 答案的形状（两处真源，各有各的口径）

| 存的东西 | 键 | 口径 |
|---|---|---|
| 答案 | `data.answers: string[][]` | **按位置**：`answers[i]` = 左到右第 i 个空的可接受答案列表 |
| 每空的作答方式 | `data.fillBlankSettings[blankId]` | **按身份**：`{ mode: 'text'\|'pool'\|'inline', choices }` |

- 写一律写「每空一份」的新形状（`worksheet-editor-core.ts:946-950` 的 `fillShape` 读三种老形状）。
- 今天**只有一条路**会 splice 答案：工具栏那个插空按钮（`prompt-editor.tsx:485-491`），
  理由逐字写着「不 splice 的话，在中间插一个空会让**后面所有答案整体错位一格**：
  教师看着答案还在，而学生答对的被判错」。

### 🔴 服务端根本不读题干

`answerSlotCount`（`server/src/services/worksheet-questions.ts:728-732`）是判分唯一的空数来源，
它的注释明写：

> ⚠️ **不是「题干里画了几个框」**：那是客户端的事（它读题干里的空分段）。
> 这里数的是**教师配了几个答案**，而它才是判分该用的分母。

⇒ **判分只认 `data.answers[i]` 的位置。** 这是本次「升级而非新增」路线的最大红利：
表格填空**不改判分**。反过来说也是最大的风险：答案错位一格 = 学生答对被判错，
而屏幕上什么都看不出来。

### 客户端数空只有一处

## 数据模型

### `data.table`（可选键；没有它 = 普通填空题，一个字不变）

```ts
export interface WorksheetTableCell {
  text: string;
  /**
   * ★ 空的身份（空串 = 不是空）。与 `PromptRun.blank` **同一个命名空间、同一种造法**
   * —— 都是 `blank_<6 位 base36>`，由编辑器那一侧造（`prompt-editor.tsx:123` 的
   * `blankIdSuffix`）。纯逻辑层不许有随机性（`recognizeBlanks` 那条注释写着理由：
   * 自己造标识的话用例就不确定了）⇒ 造 id 的能力一律由调用方传进来。
   */
  blank: string;
}

export interface WorksheetTable {
  rows: WorksheetTableCell[][];   // 行优先；v1 是方正网格（每行等长）
  headerRow: boolean;             // 第一行当表头（只影响加粗与底色）
}
```

四条刻意的选择：

1. **格子只存「空的身份」，绝不存答案。** 答案仍在 `data.answers`。
   ⇒ `stripAnswers` 的 `ANSWER_KEYS` 黑名单**一个字都不用改** —— `table` 不是答案键，
   它整份发给学生，因为**它本来就是题面**（今天 `promptRuns` 连 `blank` 标识一起发给学生，
   同一条先例）。
2. **表格里的空只有「手工填写」一档**（v1）：不给表格开 `fillBlankSettings` 的
   `pool` / `inline`（选词）。那是组合爆炸，等真有人要再说。
3. **不变式：一个空的身份在整道题里唯一**（表格与题干共用同一个命名空间）。
   同一个 `blank` id 出现在两处 ⇒ 编辑期就拒绝保存。
4. **上限**（`worksheet-table.ts` 导出常量，服务端校验同一组数）：
   - `MAX_TABLE_ROWS = 10` / `MAX_TABLE_COLS = 10`（iPad 竖屏是这套 UI 的下限），
   - `MAX_TABLE_BLANKS = 30`。
   ⚠️ 这三个数是**产品数**（照 `MAX_OPTIONS = 26` 的先例），教师觉得不合适就改；
   但**必须先有**，否则一张 100×100 的表会把学生端和答案数组一起撑爆。
   超过上限一律**响亮地拒**（不静默截断 —— 静默截断的症状是「我明明标了 31 个空」）。

### 空的编号（一条直路，没有第二种可能）

裁定 ②「表格固定在后」把顺序上的歧义消掉了：

```
第 0..k-1 个空 = 题干文字里的空（从左到右）
第 k..    个空 = 表格里的空（**行优先**：第 0 行从左到右，然后第 1 行……）
```

⇒ 客户端只留一个真源，`readBlankCount` 扩成：

```ts
// src/lib/worksheet-table.ts
export function tableBlankCount(table: WorksheetTable | undefined): number;
export function blankLayout(node): { textCount: number; tableCount: number; total: number; tableBase: number };
```

`readBlankCount(node)` 改成 `blankLayout(node).total`，**四处调用点一行都不用改**
（它们要的就是「一共几个空」）。学生端表格里第 i 格绑的是 `draft.texts[tableBase + i]`。

### 结构操作与答案对齐（本次最难的一块，测试堆这里）

每个会动到结构的操作都**同时吐出新的 rows 与新的 answers** —— 照 `insertBlank`
「返回文本与分段两样」那条先例（理由逐字：只返回一样的话调用方得自己再算一遍，
**那是第二处会算错的地方**）：

```ts
// src/lib/worksheet-table.ts —— 全部纯函数，零 import，node --test 直接跑
insertTableRow(table, answers, at)          => { table, answers }
removeTableRow(table, answers, at)          => { table, answers }
insertTableColumn(table, answers, at)       => { table, answers }
removeTableColumn(table, answers, at)       => { table, answers }
setCellBlank(table, answers, r, c, id|null) => { table, answers }
blankSlotIndex(table, r, c)                 => number   // 那格是第几个空；不是空 = -1
cellLabel(r, c)                             => string   // 「第 2 行第 1 格」（教师与学生共用一句话）
parseTablePaste(text)                       => string[][]  // TSV / 换行 → 行列表（**可砍**，见施工顺序 1 的注）
```

两个有用的推论，写进注释免得下一个人重新推：

- **插行 / 插列不改变任何答案**（新格子没有空）⇒ 这两条是零风险的。
- 风险全在**标空 / 取消标空 / 删行 / 删列**四条上：
  - 标空 ⇒ 在 `blankSlotIndex` 那个位置 splice 一个 `[]`；
  - 取消标空 ⇒ 删掉那个位置的一份答案；
  - 删行 / 删列 ⇒ 删掉落在里面的那几份答案（**按行优先顺序逐个删，从后往前删**，
    否则下标会随着删除而漂 —— 这是最容易写错的一处）。
- 「把空从这格挪到那格」= 取消 + 标空两次组合，**不另写一条移动**。

⚠️ **纪律：网格面板里不许有任何自己的算术。** 面板只负责画与收集点击，
所有数组操作走上面这几个函数 —— 因为面板那一层**本机一行都跑不到**，
而纯逻辑层有用例、能做变异检验。

### 🔴 落点在哪里（★ 施工前预检抓出来的，第一版 spec 写错了）

**第一版写的是「`questions/fill-body.tsx` 加一支」—— 那是错的，那个文件是死代码。**
预检核到的实际结构：

- 面板 `worksheet-panel.tsx:442` 有一支**提前返回**：
  `(node.type === 'choice-blank' || node.type === 'fill-blank')` ⇒ 渲染
  **`ChoiceBlankAnswer`**，并**跳过**下面通用的「题干 + 配图 + 作答体」两块
  （注释逐字：「🔴 所以这里要**跳过**下面那两块 —— 否则题干会画两遍」）。
- 分派器 `questions/index.tsx:145` 对这两个题型 **`return null`**（注释写明理由：
  整块由 `ChoiceBlankAnswer` 接管，这里再画一份会让待选词出现两组）。
- ⇒ **`fill-body.tsx` 没有任何 import**（全仓只有两处注释提到它），它的「临时桥」走不到。
  **它是死代码**（迁移之后被架空的，与那三处过期注释同源）。

**所以表格画在 `questions/choice-blank-answer.tsx` 里** —— 那个组件（名字叫 choice-blank，
但面板把它同时用于 fill-blank 与 choice-blank）今天就是**填空题题干的所有者**：
它自己渲染 `<PromptText>`、待选词区、以及那块「正确答案」。表格接在它的 `<PromptText>` 之后。

⚠️ **不要顺手删掉 `fill-body.tsx`**：它与本次功能无关，而在建工作不替别人决定；
但要在本次提交里**记一笔**（它已经没有任何引用者）。

### 画什么

- 表格画在题干**之后**（裁定 ②），复用 `worksheet.module.css` 那套外观；
  空的那几格画 `<input>`，复用今天 `PromptText` 里那个空的样式与
  `globals.css` 的 `.worksheet-blank-input`（焦点态、自适应宽度都在那儿）。
  ⚠️ **不许另写一份空的样式**：`blankAnswerStyle` 那条规则（字重、颜色）今天只有一处实现，
  两处各写一份的症状是「题干里的空与表格里的空长得不一样」，而两边都不报错。
- 红叉与「正确答案」两块**照旧复用**（`@/components/worksheet-wrong-mark` /
  `questions/correct-answer-note.tsx`）。
- 🔴 **措辞要改**：表格里的空不能再说「第 N 空」—— 学生在一张表里找不到「第 3 空是什么」。
  表格空与题干空**各自说自己**的位置：题干空说「第 N 空」，表格空说「**第 2 行第 1 格**」
  （`cellLabel`）。⚠️ 两种空同时存在时，两句话必须能区分开，否则学生拿到答案也找不到地方。
- ⚠️ **表格在 iPad 竖屏上会超出宽度**：外面套一层可横向滚动的容器
  （`overflow-x: auto` + `-webkit-overflow-scrolling: touch`），
  **不许**把表格压成挤在一起的字。横屏与竖屏都要走一遍（验收里列着）。
- 老规矩：学生端在 Safari 15 上跑 ⇒ 不加 `:has()` / `content-visibility` / `@container` /
  `color-mix()`，不写正则 lookbehind（`scripts/check-classroom-browser-compat.mjs` 会把门）。

### ⚠️ 教师端的「卷子样子」不能走 `QuestionInput`

`question-card.tsx:717` 那份折叠预览用的是 `<QuestionInput node={node} draft={undefined} disabled />`，
而分派器对 fill-blank **`return null`** ⇒ 那份预览今天**根本不画填空的输入框**
（它只有自己那次 `PromptText` 调用，连 `blanks` 都没传，所以空显示成下划线）。
⇒ **常显的「卷子样子」必须直接渲染表格那份组件（带 `disabled`）**，不能指望 `QuestionInput`
把它带出来。⚠️ 这也意味着「教师看到的就是学生看到的」这条规格 §6.3 在填空题上**今天就不成立**
—— 本次**不修**它（超范围），但要在注释里记明，别让下一个人以为它成立。

## 教师端（裁定 ③ = 乙-1）

题目卡展开后的形状：

```
┌ 题干 ─────────────────────────────────┐
│ 请根据下表填写：                       │  ← 今天那个 contenteditable，一行不碰
│ [B][I][U][着重][色] [{填空域}]         │     表格在这里**不留任何痕迹**
└───────────────────────────────────────┘
┌ 表格 ─────────────────────────────────┐
│ [+行] [+列] [☑ 第一行是表头] [从剪贴板粘贴] │  ← 新面板
│  ┌──────┬──────┬──────┐               │
│  │ 姓名 │ 年龄 │ 城市 │               │  ← 每格一个输入框，直接打字
│  │ 张三 │[填空]│ 北京 │               │  ← 标为空的那格画成灰底 chip
│  └──────┴──────┴──────┘               │
└───────────────────────────────────────┘
┌ 第 N 空的答案 ─────────────────────────┐
│ 第 1 空（第 2 行第 1 格）              │  ← 位置说实话：表格空写「第 R 行第 C 格」，
│ [一行一个可接受答案]                   │     题干空照旧写「题干中第 N 个填空域」。
│                                        │     （表格空写「题干中」就是假话）
│                                        │     顺手把 ④ 那笔账算给教师看：
│                                        │     「本空 1 分 × 6 空 ⇒ 全对最多 6 分」
└───────────────────────────────────────┘
┌ 卷子样子（只读，**编辑时也常显**）────────┐
│ 请根据下表填写：                       │
│  ┌──────┬──────┬──────┐               │  ← 学生在屏幕上看到的样子
│  │ 张三 │ [__] │ 北京 │               │
│  └──────┴──────┴──────┘               │
└───────────────────────────────────────┘
```

四个决定记在这里：

1. **表格在题干文字区里不留痕迹** —— 既然固定在后（裁定 ②），连标记都不需要
   ⇒ 题库里不可能出现「文本说有一个表格、`data.table` 里没有」这种漂移。
2. **「卷子样子」只在带表格的填空题上常显**，不给所有题型开。理由具体：
   折叠预览那一份复用 `QuestionInput disabled`（`question-card.tsx:693` 那条注释解释了
   为什么复用 —— 复用才不会有第二份渲染实现），而**选择题的 radio 用
   `name={worksheet-choice-${node.id}}`** ⇒ 同一道题画两遍就是两份同名 radio 在同一个文档里。
   填空题没有 name 冲突，所以只给它开。⚠️ 注释里要写清「为什么不是所有题型」，
   否则下一个人会顺手推广过去。
   - ⚠️ 今天那一份在 `question-card.tsx:699` 是 `{!expanded && (…)}`（展开时不渲染，
     注释写着「否则题面会画两遍」）。那句话担心的不是视觉重复，是**同一个 draft 绑在两处**；
     只读那一份是 `disabled`、不绑 draft，所以安全 —— 但要在注释里把这条区分写明。
3. **网格面板里「格子」与「空」是两件事**：格子永远能打字；**点「设为填空」才把它变成空**。
4. `blankIdSuffix`（`prompt-editor.tsx:123`）**提到一处共用**，网格面板与题干编辑器引同一个
   —— 两份随机器不会撞（36^6），但会有两个地方要改 id 格式。
