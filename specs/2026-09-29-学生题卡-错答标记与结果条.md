## 0. 现状（已核）

### 0.1 ① 那枚红叉有**四个**渲染点，而且它们必须一起改

`.resultGlyph` 那一枚不是它 —— 填空的错答标记是 `WrongMark`
（`src/components/worksheet-wrong-mark.tsx`，一枚红色 SVG 叉），四个消费者：

| 渲染点 | 在哪 |
|---|---|
| 题干里的**输入框** | `src/lib/worksheet-prompt-text.tsx`（`<input/>` + `{wrong && <WrongMark/>}`） |
| 题干里的**落点槽** | `src/lib/worksheet-blank-slot.tsx`（`BlankSlot`） |
| 表格里的**输入框** | `src/lib/worksheet-table-view.tsx` |
| 表格里的**槽** | 同上（也是 `BlankSlot`） |

⚠️ 第五个消费者是**选择题的选项**（`questions/choice-body.tsx`）—— 教师这次只说了填空题，
所以**它不动**。理由不只是「照原话办」：那个 ✗ 标的是**教师写的选项**，而删除线在别人写的
字上有「把老师的话划掉」的读法；填空划掉的是**学生自己写的那几个字**。
⇒ 这一处分叉是**有意的**，写进注释，别当成漏改。

### 0.2 ③④⑤ 三件事都挤在结果条那一行

`worksheet-panel.tsx` 的 `questionMeta`：`✓ 已完成 / ◐ 正在写` ｜ `✓ / ½ / −` 判定 ｜ 火箭。

- ③ 今天奖励**只在 `gradeState === 'correct'` 时渲染**（`{gradeState === 'correct' && reward && …}`）；
- ④ 判定的三枚记号是**字符**（`✓` / `½` / `−`）；
- ⑤ 奖励今天是框**右边**的一个兄弟（`.resultReward`）。

⚠️ **⑤ 与 2026-09-28 的一次决定相反**，那次的原话逐字记在代码里：

> ★ 2026-09-28（教师，图 56）：「火箭和 ×1 **不需要框在圆角矩形里**，这样可以保证左边的
> 两个框的高度和其他框的高度保持一致。」⇒ 它从那个框里搬出来，成了框**右边**的一个兄弟。

这次是「叠加在框的右上角」。**两次都成立**：那次要的是「框高一致」，做成**绝对定位的角标**
同样不改框高（它不占据行内空间）⇒ 实现时把这条顾虑一并保住。

### 0.3 ④ 顺带修掉一个**已经记在案**的缺陷

`worksheet.module.css` 的 `.resultGlyph` 底下逐字记着：

> ⊘ 2026-09-28 删掉：那一档减号的「往上提 1px」……**它换一个浏览器就偏高了**（教师实测）。
> 原因很实在：那 1px 是在补**某一个浏览器的字体度量的账**……而那个差值每个浏览器的
> 默认字体栈都不一样。……真要根治得换做法（比如不画字符、用一条 2px 的 CSS 横线当减号
> —— 那就不吃字体度量了），而那是个更大的改动，要单独评估。

④ 选「画出来的圆环」= **字符全部退场** ⇒ 那一类缺陷（居中靠字体度量）**从结构上消失**。
这就是那次说的「单独评估」。

## 1. ① 暗红 + 删除线

判据进 `src/lib/worksheet-prompt-marks.ts`（`blankAnswerStyle` 就住那里 —— 同一类东西）：

```ts
export const WRONG_ANSWER_STYLE: Record<string, string>;   // { color: '#b91c1c', textDecoration: 'line-through' }
export function blankValueStyle(run, wrong): Record<string, string | number>;
export function blankAriaLabel(label: string, wrong: boolean): string;
```

🔴 **`blankValueStyle` 存在的理由**：那个样式必须**展开在 `blankAnswerStyle` 之后** ——
后者含 `promptRunStyle` 的 `color`，写在它前面会被整个盖掉（`BlankSlot` 有一条同样的旧账：
教师看到「打字那条红了、待选区那条没红」）。把顺序定在一个**有测试的函数**里，
比写一句注释可靠。

🔴 **`blankAriaLabel` 是必需的，不是修饰**：原来那枚红叉自带 `role="img" aria-label="答错了"`，
换成删除线之后**视觉信息还在、读屏信息没有了**（删除线对读屏是无声的）。本仓立过
「图标化只减视觉宽度、不减无障碍信息」⇒ 把「答错了」并进那一格的名字里。

四个渲染点改成 `blankValueStyle(run, wrong)` + `blankAriaLabel(label, wrong)`，删掉 `WrongMark`。

## 2. ② 行内候选词之间加斜杠

`choice-blank-answer.tsx` 的 `.inlineChoices`：`（唐 唐代）` → `（唐 / 唐代）`。
分隔符是**装饰**（`aria-hidden`）：两个词各自是带名字的按钮，读屏再念一个「斜杠」是噪音。
⚠️ 只加在**行内**那一串；下方待选词区不加（那些是分开的胶囊，本来就不连在一起）。

## 3. ③⑤ 奖励：角标 + 只画一枚 + ×N

- 渲染条件从 `gradeState === 'correct'` 放宽到 `correct | partial`（教师原话）。
  ⚠️ `incorrect` 仍然不画 —— 那一档 `score` 恒 0，没有任何东西可显示。
- **只画一枚图标**（缩到 22px），`N > 1` 时补一个 `×N` —— 教师 ⑤-③ 的原话。
  ⚠️ 这**反转了** 2026-09-28 的两条（「一个就是一枚图标，不写 ×1」「得到两个就直接画两个」）。
  反转的理由就是 ⑤-① 本身：角标只有那么大，画不下五个。
- 位置：`position: absolute` 在**判定那一格**的右上角（`right: -6px; top: -7px`）。
  父级要 `position: relative` —— 加在 `.resultCell` 上而不是整条 `.questionResult` 上，
  否则角标会跑到「已完成」那一格的右上角去。
- `amount <= 0` ⇒ **不画**（角标放不下「暂未获得」那句话，而 `QuestionReward` 今天那句
  `暂未获得` 由构造不可达：`full >= 1` ⇒ 全对的分恒 > 0）。

## 4. ④ 三枚记号改成「画出来的圆环 + 填充比例」

```
全对       ●   整圆填满
部分答对   ◐   左半边填满（垂直平边）
不对       ○   不填，只留描边
```

🔴 **容器翻过来**：`.resultGlyph` 从「彩色圆底 + 白色字符」变成「描边圆环 + `currentColor` 填充」
—— 否则「填满」会画成一个**空心环**（满=空，正好反了）。
副作用是好的：那三条 `[data-tone] .resultGlyph { background }` 连同
「白底白字，记号完全看不见」那段注释一起退休 —— **没有底色，就没有白底白字**。

新组件 `src/app/classroom/worksheet/result-glyph.tsx`（`questionTypeIcon` 的邻居）。
⚠️ 三档**只有一个组件**：三处各画一个 SVG 的症状是「同一个状态，两处长得不一样」。

⚠️ 残留（已告知教师）：`◐ 正在写`（进度那一格）也是半圆，两者**可以同时出现在一行**
（交过之后又改 ⇒ `state` 回到 draft，而判分结果还在）。判据是
`state !== 'submitted' && gradeState`。这次的画法是描边+填充、颜色也不同，
能分开；要根治得把「正在写」也画一遍 —— 那是另一件事，本次不做。

## 6. 施工记录

1. **① 判据**：`worksheet-prompt-marks.ts` += `WRONG_ANSWER_STYLE` / `blankValueStyle` /
   `blankAriaLabel` + 6 条用例。🔴 其中 `blankValueStyle` 存在的**全部**理由是**顺序**
   （答错那层要盖过 `blankAnswerStyle` 里的 `color`），用例把那条顺序钉住了。
2. **① 四个渲染点**：题干输入框、`BlankSlot`、表格输入框、表格槽。
   · 题干输入框那一支**顺带去掉了一个包裹用的 `<span inline-block>`** —— 它是为「框 + 叉」
     整体换行加的，叉没了它就没用了。
   · `WrongMark` 只剩**选择题**一个消费者（有意的分叉，注释写明了理由）。
   · 表格输入框那一支没有 `blankAnswerStyle` 打底 ⇒ 直接叠 `WRONG_ANSWER_STYLE`
     （不必过 `blankValueStyle`），**样式本身仍然只有一份**。
3. **②** 行内候选词之间加 `/`（`aria-hidden` 的装饰）。
4. **④** 新组件 `result-glyph.tsx`（三档一个组件），`.resultGlyph` 的 CSS 从
   「彩色圆底 + 白色字符」翻成「无底色 + `currentColor`」；三条 `[data-tone]` 底色规则
   与「白底白字」那段注释一起退休。
5. **③⑤** `QuestionReward` 改成角标内容（一枚 22px 图标 + `amount > 1` 时补 `×N`，
   `amount <= 0` ⇒ 不画）；`.questionResult` 外面加了一层 `.resultRewardAnchor`
   （角标必须是它的**兄弟**才不被 `overflow: hidden` 裁掉）；`margin-left: auto` 跟着搬家。
6. **顺带修掉三处过时注释**：它们拿「学生端显示『暂未获得』」当论据解释「`full = 0` 为什么坏」。
   论点仍然成立，但那条具体症状已经不存在了 ⇒ 换成新症状（「看到『全部答对』却一枚图标都没有」）。

### 施工中抓到的两件事（都不是我原计划里的）

**甲、两条源码网被这次改动弄红了，而「把 1 改成 0」是不够的。**
`worksheet-prompt-text.test.ts` 与 `worksheet-table-view.test.ts` 各有一条**阳性对照**，
数的是「这两处各画了一枚 `<WrongMark />`」——正是这次删掉的东西。红得对，但改法有讲究：
把 `1` 改成 `0` 之后，那一条就什么也证明不了了，而且**「哪天有人把标记整个删掉」会让
上面那条『不许定位』的网变得更绿**。⇒ 换成断言**标记仍然在，只是换成了样式**。

**乙、上面那个改法第一版是假绿的 —— 变异检验抓出来的。**
断言写的是「源码里出现过 `blankValueStyle`」，而那个名字**还留在 import 行里** ⇒
把调用点整个删掉、只留一行 import，断言照样绿（实测：变异了但网没红）。
⇒ 加了一层 `stripImports`（先剥 import 行再查），并**重新变异验证**两条网都咬得住。
