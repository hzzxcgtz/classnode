## 1. 判据层（本次的主体）

新文件 `src/app/teacher/classroom/header-controls.ts`（零运行时 import，`node --test` 可跑）：

```ts
export type HeaderControlKind = 'state' | 'action' | 'view' | 'setting';
export type HeaderControlId =
  | 'pause' | 'lock' | 'sync-groups' | 'notify'
  | 'worksheet' | 'matrix' | 'fullscreen'
  | 'permissions' | 'module-state';

export interface HeaderControl {
  id: HeaderControlId;
  label: string;            // 含忙态与状态翻转（「暂停课堂」/「恢复课堂」/「更新中...」）
  title: string;            // 悬浮说明（'' = 不画 title 属性）
  active: boolean;          // 已激活的状态开关（画主色）；非开关恒 false
  disabled: boolean;
  kind: HeaderControlKind;
  startsGroup: boolean;     // 这一格之前画一条分隔线（第一项恒 false）
  popup: 'dialog' | 'menu' | null;   // 打开的是哪种浮层
  expanded: boolean;        // 那种浮层的开合态
}

export const HEADER_BUSY_KEYS = { syncGroups: 'sync-groups', pause: 'questions', lock: 'answers-lock' } as const;

export function headerLayout(input: {
  mode: string; status: string;
  paused: boolean; answersLocked: boolean;
  boardMode: 'follow' | 'assign';
  gridFullscreen: boolean;
  busy: string | null;
  permissionsOpen: boolean; modulesOpen: boolean;
}): {
  controls: HeaderControl[];
  /** 看板模式那一段（跟随 / 指定）显不显示。 */
  showsBoardMode: boolean;
  /** 模块筛选那一段显不显示（只在跟随模式有意义）。 */
  showsModuleFilter: boolean;
}
```

**顺序按性质排**：`状态 ｜ 动作 ｜ 看数据 ｜ 设置`。

```
[暂停课堂][锁定作答] │ [同步分组][通知全体] │ [学习单][矩阵][全屏] │ [课堂权限▾][模块状态▾]
```

⚠️ **与现状的差别只有一处**：`矩阵` 从最右挪到 `学习单` 旁边（原来两者被「课堂权限 / 模块状态」
隔开，而它们是同一件事的两面）。`暂停课堂 / 锁定作答` 同时从第 2 位挪到第 1 位。

### 1.1 `HEADER_BUSY_KEYS` 为什么是一个导出常量

三个忙态键（`'sync-groups'` / `'questions'` / `'answers-lock'`）今天是**字面量写在两处**：
`runControlAction('answers-lock', …)` 那三个调用点，与读它们的那三个 JSX 三元。
判据层读、调用点写 —— 两处各写一份字面量时，改一处会让**忙态标签永远不出现**（不报错）。
⇒ 常量只留这一份，两边都从这里取。

## 2. 那一行「对不上账」

`board-module-counts.ts` 加一个纯函数（它的兄弟函数都在那里）：

```ts
/** 三个模块之外还剩几个**在线**的人（首页 / 位置未知）。0 ⇒ null（那句话不出现）。 */
export function unplacedNote(distribution: Record<FocusModule, number>, unit: string): string | null;
```

筛选行改成**两段**，各自的分母写在段首：

```
[全部 40][需关注 0][离线 39]   ｜   此刻在线：[学习单 0][探究空间 0][智能学伴 0]  · 另有 1 人在首页或位置未定
```

- **两段的分母不同，这是有意的**：左段是**参与者**，右段是**此刻在线**。段标签「此刻在线」
  就是那句话；`另有 N 人…` 让 `三个模块 + 另有 = 在线`、`在线 + 离线 = 全部` 都对得上。
- **`另有 N 人…` 不是按钮**（灰色小字）：它答的是「还差的那几个在哪」，而不是一个筛选项
  —— 一个点下去只为了看「在首页和不知道在哪的人」的筛选器没有用处。
- ⚠️ **不把「首页 / 未知」两格补回成 chip**：那是教师 2026-09-25 圈定的六格清单，
  取消它属于另一个决定。这一句只承担「让这一行能对账」这一件事。

## 4. 两处**不按原话做**的决定（连同理由）

### 4.1 不把整块头部搬进新组件（「乙」的原话说「头部抽成一个组件」）

**决定**：渲染改成**遍历判据表**，但 JSX 留在 `page.tsx`。
**理由**：那块 JSX 直接引用约 25 个绑定（`classroom` / `paused` / `answersLocked` / 八个 handler /
两个 ref / 筛选 state / `moduleDistribution` …）。搬出去就是一份 25 个 prop 的签名 ——
换来的只有「文件短一点」，而**正确性上的收益为零**（判据已经抽出去了）。
代价是「头部仍住在 260k 的文件里」；那件事值得在某个安静的时刻单独做，不该混在这次里。
**错了的代价**：如果教师真的想要那个文件，这是一次独立的、可以慢慢做的搬迁。

### 4.2 不把「课堂权限 / 模块状态」合并成一个入口（「甲」的原话）

**决定**：两个都留在这一行，只是被分隔线归到「设置」那一段。
**理由**：`模块状态` 是**课中会按**的（暂停/开放一个模块），藏到二级菜单里等于每次多一次点击；
而 `课堂权限` 是**课前设一次**的。两者使用频率差一个数量级，合并是按低频那个的待遇对待高频那个。
**错了的代价**：如果教师觉得那一行还是挤，合并入口是独立的一小步。

## 6. 施工记录

1. **`header-controls.ts` + 25 条用例** —— `headerControls` / `headerLayout` / `HEADER_BUSY_KEYS`。
   ⚠️ 施工中**抓到一个真问题**：用例第一版按「忙态只禁用正在忙的那一个」写，实测红了；
   去核原码才发现 `runControlAction` 开头是 `if (controlBusyRef.current) return;` ——
   任何控制动作在飞时另外两个**点了没反应**。⇒ 正确的是「**文案**逐个、**禁用**整排」，
   而判据还得放宽到 `busy !== null`（探究空间的 `'capture-*'` 也占同一个守卫）。
   这一条连同理由写进了代码注释与用例。
2. **`board-module-counts.ts` += `onlineTotal` / `unplacedNote` + 6 条用例**。
3. **`page.tsx`** ——
   · 头部控件块整段换成 `header.controls.map(...)`（判据表驱动），只留两个 id 分支：`permissions`
     的按钮 ref、`module-state` 的包裹层（菜单的锚点）。

   · `矩阵` 挪到 `学习单` 旁边；按性质分四段、段间一条竖线。
   · 三处 `runControlAction('…')` 的字面量改成 `HEADER_BUSY_KEYS.*`（与判据层同一份）。
   · 筛选行拆成两段（左：参与者口径；右：此刻在线），右段带段标签与 `unplaced` 那句。
   · 副标题进 `h2` 的 `title`；跟随/指定那句解释并进 `SegmentedButton` 的 `hint`。
4. **`ModuleStateMenu`** 从头部 JSX 里提成局部组件（4 个入参）—— 这样
   `header.controls.map` 才能在原地渲染它（它的锚点是包住按钮与菜单的那一层）。
   行为与样式**一个字没改**。

### 施工中一处与规格的偏离

- §1 原写 `showsBoardMode`，实施时改成 **`showsHeader`**：那三处（标题行 / 看板模式 / 筛选行）
  用的是**同一个** `!gridFullscreen`，按「看板模式」命名会让另外两处读起来在借用别人的条件。

### 一处**发现但没动**的既有问题（留给教师定）

`studentStatuses` 的键集是「**连过**这张看板的学生」（`loadClassroom` 只把 HTTP 查到的在线 id
写进去），与名册不是同一个集合。⇒ 屏幕上方那块统计卡的**在线人数 / 离线**（走
`Object.values(studentStatuses)`）与这一行的**离线**（走 `getDisplayCardStatus`，缺状态一律算离线）
**可以差几个**，而它们在**同一屏上**。本次没动那块卡（它是另一屏的事），
但判据层新增的那个数**逐名册**数，与它左边的模块格同源 —— 两个数名字相近而口径不同这件事，
已经写进 `page.tsx` 的注释，别把其中一处换成另一处。
