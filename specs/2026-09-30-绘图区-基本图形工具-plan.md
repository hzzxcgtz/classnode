# 绘图区基本图形工具 · 施工计划

> **给执行者：** 用 `superpowers:executing-plans` 逐任务执行。步骤用 `- [ ]` 勾选跟踪。

**Goal:** 学生画布上能拖出 9 种基本图形，并且能选中、移动、改大小、删除。

**Architecture:** 几何全部落在**纯逻辑层**（`src/lib/worksheet-ink.ts`，零 import、`node --test` 直接跑），
渲染层只消费它的折线输出。数据模型只加一个可选字段 `shape`，老数据零改动、零迁移。

**Tech Stack:** TypeScript / React（Next 15 静态导出）/ Canvas 2D / SVG / Prisma + SQLite。

**Spec:** `specs/2026-09-30-绘图区-基本图形工具.md`（本计划的**唯一依据**；冲突以 spec 为准）

## Global Constraints

- 🔴 **不许 lookbehind**（`src/lib` 在 `scripts/check-classroom-browser-compat.mjs` 的扫描根内）。
  同时不许：`Object.hasOwn` / `structuredClone` / `findLast` / `.at(` / `:has(` / `@container` /
  `content-visibility` / `color-mix(`（学生端跑在 Safari 15 的老 iPad 上）。
- 🔴 `src/lib/worksheet-ink.ts` **零运行时 import**（Node 的类型擦除要能直接加载它）；
  只许 `import type`。
- 🔴 `server/src/services/ink-path.ts` 是 `src/lib/worksheet-ink.ts` 的**逐字镜像**
  （`worksheet-ink-parity.test.ts` 对拍）。改一边必须改另一边。
- 🔴 **不许跑 `pnpm build` / `./dev.sh build`**（dev 正在跑，会把 `.next` 搞坏）。
- 🔴 本仓前端**没有 jsdom、没有浏览器** ⇒ 组件与手感只能真机走查；能验的只有纯逻辑与源码。
  每条新断言**必须做变异检验**（改坏实现，确认网会红），并且**确认变异真的落到了文件上**。
- 🔴 **不许 `git add -A`**、**不许 `git checkout -- .`**（工作树与另一个 agent 共用）。
- 每条新增的界面文案都要有 `aria-label`（图标按钮的纪律）。

## Task 1: 形状的取值域与几何（折线）

**Files:**

- Test: `src/lib/worksheet-ink.test.ts`

**Interfaces:**
- Produces: `InkShapeKind`、`INK_SHAPE_KINDS`、`isInkShapeKind(raw)`、
  `ShapeOutline { closed: boolean; points: InkPoint[] }`、
  `shapeOutline(stroke: InkStroke, box: InkCanvas): ShapeOutline[]`
- 形状：`line | arrow | rect | ellipse | triangle | right-triangle | parallelogram | trapezoid | angle`

- [ ] **Step 1: 写失败用例**

```ts
test('🔴 shapeOutline：直线 / 矩形 / 椭圆（折线）', () => {
  const box = { w: 200, h: 100 };
  const at = (shape: string, pts: InkPoint[]) => shapeOutline({ color: '', width: 0, points: pts, shape } as InkStroke, box);

  // 直线：1 条开的折线
  assert.deepEqual(at('line', [[0.1, 0.2], [0.6, 0.8]]), [{ closed: false, points: [[0.1, 0.2], [0.6, 0.8]] }]);

  // 矩形：1 条闭折线，四角（外接框的两个对角推出另外两个角）
  const rect = at('rect', [[0.1, 0.2], [0.5, 0.6]]);
  assert.equal(rect.length, 1);
  assert.equal(rect[0].closed, true);
  assert.deepEqual(rect[0].points, [[0.1, 0.2], [0.5, 0.2], [0.5, 0.6], [0.1, 0.6]]);
});

test('🔴 shapeOutline：**归一化空间是各向异性的** —— 形状要在像素空间里算再转回来', () => {
  // 🔴 这条是本次最容易做错的地方：x 乘的是画布宽、y 乘的是画布高，两者不等。
  //    先在归一化空间里算「箭头头部」再直接用，宽高比一变箭头就是歪的
  //    —— 而屏幕上只是「箭头看着怪」，没有任何报错。
  // 用一个**很扁**的画布（400×50）与一个**很方**的（100×100），同一个 stroke，
  // 箭头头部在**像素空间**里必须一样长。
  const stroke = { color: '', width: 0, points: [[0.1, 0.5], [0.9, 0.5]], shape: 'arrow' } as InkStroke;
  const headPx = (box: InkCanvas) => {
    const parts = shapeOutline(stroke, box);
    assert.equal(parts.length, 2, '箭头应当是「杆 + 头部」两条折线');
    const [a, b, tip] = parts[1].points;                     // 头部是 3 点：左翼 → 尖端 → 右翼
    const px = (p: InkPoint) => [p[0] * box.w, p[1] * box.h];
    const dist = (p: InkPoint, q: InkPoint) => Math.hypot(px(p)[0] - px(q)[0], px(p)[1] - px(q)[1]);
    return { wing: dist(a, tip), tip: px(tip) };
  };
  const flat = headPx({ w: 400, h: 50 });
  const square = headPx({ w: 100, h: 100 });
  assert.ok(Math.abs(flat.wing - square.wing) < 1e-6, `两种画布下箭头翼长应当相同（像素空间），实际 ${flat.wing} vs ${square.wing}`);
  // 尖端落在杆的终点上
  assert.ok(Math.abs(flat.tip[0] - 0.9 * 400) < 1e-6);
});
```

- [ ] **Step 2: 跑，确认红**

Run: `node --test src/lib/worksheet-ink.test.ts`
Expected: FAIL —— `shapeOutline` is not a function / 不是 export

- [ ] **Step 3: 实现**

要点（**逐条都有理由**）：
- `INK_SHAPE_KINDS` 是一个 `as const` 数组 + 从它推出的类型；`isInkShapeKind` 用 `includes`。
- `shapeOutline` **先把归一化坐标换成像素**（`toPixel`），在像素空间算完再换回来
  （`normalizeAxis`）—— 上面那条用例钉的就是这个。
- 外接框先从两点求出 `x0=min, x1=max, y0=min, y1=max`（**允许学生从任何方向拖**）。
- `ellipse`：32 段折线（起点在 0 弧度，最后一**段**回到起点 ⇒ 不必再补一个点）。
- `angle`：三点 → 两条射线 + 一段弧（半径 = 两条边较短者的 1/4，16 段折线）。
- `arrow`：杆 + 头部（翼长 = `min(杆长 * 0.3, 12px)`，像素空间；两翼各张开 25°）。
- `right-triangle`：直角小方块（边长 `min(w,h)/6`，像素空间、夹取到不超过框的三分之一）。

- [ ] **Step 4: 跑，确认绿**

Run: `node --test src/lib/worksheet-ink.test.ts`
Expected: PASS
