# 绘图区的基本图形工具（学生画布上能拖出直线 / 矩形 / 圆…，并且能选中、移动、改大小）

★ 2026-09-30（教师）：「帮我解决绘图区支持基本图形工具」。

> ⚠️ 这篇 spec 由**一次穷尽的爆炸半径普查**（Explore 子代理）打底 —— 第「爆炸半径」一节
> 每一条都带文件路径与行号，**没有一条是推断**。这个功能的风险**不在新增的代码**，
> 而在「有 9 处各自读 / 画同一份笔迹数据，漏一处就静默不一致」。

## 教师已定的四条

1. **图形**：「都要」—— 直线 · 箭头 · 矩形 · 圆/椭圆 · 三角形 · 直角三角形（带直角标记）·

4. **手写笔留着**（图形是**加一档**，不是替换）。

### 体量与性能（用库里的真数据量的，不是估的）

库里 4 幅学生画的画：**7.4 / 13.9 / 8.6 / 7.7 KB**，笔数 1–13、总点数 185–341。
按采样阈值（1.5px）算，**一条 200px 的手写线 ≈ 133 点**。

| | 一笔的体积 |
|---|---|
| 手写（那 4 幅的平均，37 点/笔） | ~550 B |
| 手写（那幅 185 点的） | ~2.6 KB |
| **一个图形**（2 点 + 一个 `shape` 字段） | **~83 B** |

⇒ **图形让整幅画更小**（6～30 倍），不是更大。重绘、命中测试、导出、AI 联系表**全都更省**。

## 数据模型：**加一个可选字段，不用迁移**

```ts
type InkShapeKind = 'line' | 'arrow' | 'rect' | 'ellipse' | 'triangle'
                  | 'right-triangle' | 'parallelogram' | 'trapezoid' | 'angle';
interface InkStroke { color: string; width: number; points: InkPoint[]; shape?: InkShapeKind }
```

🔴 **`shape` 缺省 = 手写笔迹** ⇒ 库里所有老值**一个字节不用动**，也不需要迁移
（本项目从来没有迁移碰过作答值，这次也不开这个头）。

🔴 **图形的 `points` 就是它的定义几何**（不是「画出来的点」）：

| 形状 | `points` | 含义 |
|---|---|---|
| `line` `arrow` `rect` `ellipse` `triangle` `right-triangle` `parallelogram` `trapezoid` | **2 个** | 外接框的**两个对角**（`[x0,y0]` 是 min、`[x1,y1]` 是 max） |
| `angle` | **3 个** | 顶点 · 边一的端点 · 边二的端点 |

⇒ **撤销 / 清空 / 上限 / 归一化 / 离线队列 / 抽稀全都继续用**（它们只看「笔数与点数」，
而图形的点数恒是 2 或 3）。

⚠️ **`angle` 为什么是三个点**：一个永远 90° 的「角」在几何课上没用。它是**唯一一个
把手不是外接框的图形** —— 三个顶点各自可拖（见「交互」）。

## 判据层（`src/lib/worksheet-ink.ts`，零 import）

新增（**每一条都要有用例，并且做变异检验**）：

| 函数 | 干什么 |
|---|---|
| `INK_SHAPE_KINDS` / `InkShapeKind` / `isInkShapeKind` | 取值域 + 判据 |
| `shapeOutline(stroke, box)` | **几何的唯一来源**：形状 → **若干条折线**（见下面那一节） |
| `strokePath`（扩展） | SVG 的 `d`。手写那条路**一个字不改**；有 `shape` 时走 `shapeOutline` |
| `hitTestStroke(point, stroke, box, tolPx)` | 点选。**闭合图形内部也算命中**；线状（直线/箭头/角）只算轮廓附近 |
| `strokeHandles(stroke, box)` | 把手（控制点）的位置 |
| `moveStroke(stroke, dx, dy)` | 平移，**夹取到 0..1**（不许拖出画布外） |
| `resizeStroke(stroke, handleIndex, point)` | 把某个把手拖到新位置（再夹取） |

### 从外接框推出各形状（**写死在这里，用例逐条钉**）

设 `x0≤x1`、`y0≤y1`、`w=x1-x0`、`h=y1-y0`：

| 形状 | 顶点（画布坐标，y 向下） |
|---|---|
| `line` | `(x0,y0) → (x1,y1)` |
| `arrow` | 同 `line`，箭头头部在 `(x1,y1)` |
| `rect` | 四角 |
| `ellipse` | 内切椭圆，**折线逼近**（32 段）：`cx=(x0+x1)/2`、`cy=(y0+y1)/2`、`rx=w/2`、`ry=h/2` |
| `triangle` | `((x0+x1)/2, y0)`、`(x1,y1)`、`(x0,y1)` —— 等腰，尖朝上 |
| `right-triangle` | `(x0,y0)`、`(x0,y1)`、`(x1,y1)` —— **直角在左下角 `(x0,y1)`**，并画直角小方块 |
| `parallelogram` | `(x0+w/4, y0)`、`(x1, y0)`、`(x1-w/4, y1)`、`(x0, y1)` —— 上边右移 |
| `trapezoid` | `(x0+w/4, y0)`、`(x1-w/4, y0)`、`(x1,y1)`、`(x0,y1)` —— 上底 = 下底的一半、居中 |
| `angle` | 不在框内：三个自由点 |

⚠️ 直角小方块的边长取 `min(w,h)/6` 并夹取 —— 框很扁时方块不许比框还大。

### 🔴 路径只生成一次：**几何**是那一份，而且它**只有一种形态 —— 折线**

学生画布与教师端是**两个渲染器**（Canvas 2D vs SVG）。本仓最防的正是「两处各画一份」
（今天已经有一个现成的反例：AI 联系表 `analysis-render.ts:110` 自己另拼 `<path>`）。

**做法（★ 写计划时定下来的简化，比初版更好）**：`shapeOutline` 返回**一个折线数组**，
**所有形状都归结为折线** —— 椭圆与角的弧**用折线逼近**。

```ts
export interface ShapeOutline { closed: boolean; points: InkPoint[] }
export function shapeOutline(stroke: InkStroke, box: InkCanvas): ShapeOutline[]
```

| 形状 | 返回几条折线 |
|---|---|
| `line` | 1 条（开的，2 点） |
| `arrow` | 2 条：杆 + 箭头头部（开的，3 点） |
| `rect` `triangle` `right-triangle` `parallelogram` `trapezoid` | 1 条（**闭**的） |
| `ellipse` | 1 条（**闭**的，32 段折线逼近） |
| `angle` | 3 条：两条射线 + 一段弧（弧**折线逼近**） |

⇒ **三个好处，每一个都是实的**：
1. **两个渲染器都只需要「画一串折线」这一种能力** ⇒ 画法在**结构上**不可能分叉
   （SVG 只需要 `M`/`L`/`Z`，画布只需要 `moveTo`/`lineTo`/`closePath`）；
2. **命中测试与路径生成共用同一份折线** ⇒ 「点得中的地方」与「画出来的地方」是同一个东西；
3. **`ctx.ellipse` 这条「没核过」直接消失** —— 不再需要任何新的 Canvas API。

⚠️ **`Path2D(路径串)` 那条路考虑过、不走**：它能让两边字符串级同一，但要引一个在本机
核不了的 API。而**几何本来就是命中测试要用的那一份** —— 让它同时喂两个渲染器，
比多引一个 API 更少一处可漂移的地方。这不是否决 `Path2D`，是**没必要**。

## 交互（学生端，甲档）

### 工具栏（`questions/ink-body.tsx`）

```
✏️手写 │ ／直线 →箭头 ▭矩形 ◯圆 △三角形 ◺直角三角形 ▱平行四边形 ⏢梯形 ∠角 │ ↖选择 │ 撤销 清空
```

- **默认档恒是「手写」**（🔴 老习惯的学生一上手必须能直接画；默认成别的档，
  他会以为画布坏了）
- 当前档**高亮**，按钮带 `title` 与 `aria-label`（图标按钮的纪律）
- 允许**换行**；iPad 竖屏下预计两行（真机走查项）

### 画一个图形

选一个图形档 → **按下滑出一个框**（按下 = 起点 → 拖动 = 实时预览 → 松手 = 落定）。
松手时若**宽或高 < 8px** ⇒ **不成形，丢掉**（手指抖一下不该留下一个看不见的图形）。
⚠️ 是「**任一边**太小就丢」，不是「两边都小才丢」—— 一条水平的直线宽 200px、高 2px，
那是**合法的**（`line`/`arrow` 不经过这个判断，它们本来就是两点连线）。

### 选中 / 移动 / 改大小 / 删除（「选择」档）

- **点一下图形** = 选中：画一圈虚线框 + 控制点
- **框内拖动** = 移动；**拖控制点** = 改大小
- 选中时工具栏出现**删除**
- **点空白** = 取消选中
- 控制点：两点框图形 **4 个角**（不是 8 个 —— 手指比控制点粗，8 个会互相压住）；
  `line`/`arrow` 是 **2 个端点**；`angle` 是 **3 个顶点**
- 🔴 **只有图形能被选中**：手写笔迹不参与（否则学生一点就选中一条自己画的线，
  而他只是想继续画）

## 上限

- 图形**按 1 笔算**（`INK_MAX_STROKES` 不变）
- `countPoints` 里图形的点数**就是** 2 或 3 ⇒ 那 2000 点的上限对图形**几乎不构成约束**
- `downsampleInkValue` 抽的是 `points` —— 图形只有 2 点，抽到只剩首尾**恰好还行**，
  但要**加一条用例**把「图形不许被抽成 0 点」钉住（那是个隐式假设，今天没有任何网）

# 第二轮（★ 2026-09-30 教师）：把它做成**像一个专业的绘图工具**

教师原话：「绘图工具不够**紧凑**，图标不够**直观**，**分类**不够明确，还缺少**文本工具**、**颜色工具**。
也就是它应该像一个专业的绘图工具。」

## 三条已定（逐条）

| # | 决定 | 代价 |
|---|---|---|
| 1 | **工具栏：一行 + 弹出组**。7 个按钮，**每个按钮显示当前值**（当前图形 / 当前颜色 / 当前粗细）；点开是九宫格 / 色板 / 三档 | 纯 UI，**不动数据** |
| 2 | **文本工具**：点一下放文本框、打字、能选中/拖动/改大小/删除；**字号复用粗细三档** | ⚠️ **贵** —— 第二种元素，动 `InkValue` 的形状 |
| 3 | **颜色：八色固定色板**（黑/深灰/红/橙/黄/绿/蓝/紫）；选中元素后再点颜色 = **改那个元素的颜色** | **便宜** —— `color` 本来就是每个元素各自的字段 |

## 一行的形状（就是这一版要做的）

```
┌──────────────────────────────────────────┐
│ ✏  ▭▾   T   ↖  │  ●▾   ■▾  │  ↶   ⌦    │
└──────────────────────────────────────────┘
 工具              粗细  颜色    动作
```
点 `▭▾` ⇒ 九宫格；点 `■▾` ⇒ 八色板；点 `●▾` ⇒ 三档。**按钮上是当前值**。

## 🔴 文本工具：为什么它贵，以及必须一起改的地方

它是**第二种元素**（现在 `InkValue` 只有 `strokes`）⇒ **形状那一轮的 9 处爆炸半径再来一遍**：

```ts
interface InkText { text: string; at: InkPoint; color: string; size: number }
interface InkValue { format; canvas; strokes: InkStroke[]; texts?: InkText[] }
```
⚠️ `texts` **可选**（与 `shape` 同一招）⇒ 老数据零改动、零迁移。

必须同时改：`src/lib/worksheet-ink.ts` + `server/src/services/ink-path.ts`（镜像）+

## ⚠️ 颜色的一个硬约束

`server/src/services/ink-render.ts` 里有一道 `safeColor`。**我先前把它说成「固定色板才能过」——
那句是错的**（写下来之后去核了）：它是**格式**检查，`/^#([0-9a-f]{3}|[0-9a-f]{6})$/i`
—— 只认十六进制，`red` / `rgb(...)` 之类会被回落成常量色。⇒ **任意十六进制色都能活**，
自定义取色器其实也行。
⇒ 所以八色固定板是**产品选择**（够小学初中用、工具栏紧凑、不用教），**不是**被那道白名单逼的。
⚠️ 但这仍然是一条真约束：**颜色必须是十六进制字符串** —— 将来谁要加「按名字给色」，
先看这一行。
