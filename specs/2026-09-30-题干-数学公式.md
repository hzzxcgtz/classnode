## 判据层（`src/lib/worksheet-math.ts`，**零 import**）

与 `worksheet-prompt-marks.ts` 同一条纪律：零 import ⇒ `node --test` 能直接加载 `.ts`。

```
splitMath(text) → ({ kind: 'text', text } | { kind: 'math', tex })[]
```

**规则（按扫描优先级，已用原型逐条验过）**：

| # | 写法 | 判据 |
|---|------|------|
| 1 | `$$…$$` | 同一行内、内容非空 ⇒ 公式（**剥掉双层**，按行内渲染） |
| 2 | `$…$` | 开 `$` 后**不接空白**、不接 `$`；闭 `$` 前**不接空白**、后**不接数字或字母** |
| 3 | 认不出来 | **原样当普通文本**（绝不静默画成半截公式） |

第三条是**安全阀**：教师打「这本书 $5，另一本 $8」时，两个 `$` 都不成对 ⇒ 一个字都不
渲染，原样显示。这是本仓最防的那类缺陷（「屏幕上画的和存下的不是一个东西」）的反面。

🔴 **不许出现 lookbehind** —— 本文件在 compat 门禁的扫描根（`src/lib`）内。
原型已按捕获组 + lookahead 实现并验过（见下）。同时不许 `Object.hasOwn` /
`structuredClone` / `.at(` 等（那张清单在 `worksheet-prompt-marks.ts` 的文件头）。

**原型实测**（8 条边界全对）：

```
计算 $x^2+1=10$ 中 x 的值。   → 计算【公式:x^2+1=10】中 x 的值。
这本书 $5，另一本 $8          → 原样（闭 $ 前是空白）
价格 $5，另一本$8             → 原样（闭 $ 后是数字）
$$x^2$$ 的展开                → 【公式:x^2】的展开
求 $\frac{1}{2}$ 与 $\sqrt{y}$ → 两个公式
全班 $ 元的班费               → 原样（开 $ 后是空白）
只有一半的 $x^2 公式          → 原样（没闭合）
3*5=15 和 $a_1$               → 3*5=15 和【公式:a_1】
```

⚠️ **语法校验不放进这个文件**：它要调 KaTeX（有运行时 import），而 `node --test` 跑
`.ts` 靠类型擦除、被加载的文件不能有运行时 import。⇒ 校验放渲染那一侧
（KaTeX 自己 `throwOnError: false`，画成红色的错误标记）。

## 前端渲染：**一份实现**

🔴 现状是「题面文本」散在十几个组件里各渲染各的。本次要把它们**收敛到 `PromptText`**，
而不是新写一个组件给纯文本用 —— 两份渲染器就是本仓最防的那种分叉（`PromptText` 的文件头
记着一次同类的账：题干曾经有两份渲染实现，症状是「预览里画得出来、学生那里画不出来」）。

- 无 `runs`（选项 / 条目 / 左右项 / 框名 / 表格单元格 / 答案）⇒ 单段。

### 🔴 纯文本场景**不写行内样式**（交付当天复审抓出来的）

`runs` 缺省时**不许**给它套 `promptRunStyle` —— 那两个字段（`color` / `fontWeight`）会让
**行内样式赢过父容器继承下来的值**，把一批**教师已经做过的决定**静默取消：

| 位置 | 父容器给的 | 会被顶成 |
|------|-----------|---------|
| 学生端答错的选项 | `WRONG_ANSWER_STYLE` 的红字 | 深灰（删除线还在 —— `text-decoration` 会往下传，颜色不会） |
| 学生端「正确答案」那句 | `CorrectAnswerNote` 的深红 + `<strong>`（教师 2026-09-27 明确要求「答案文字加粗」） | 深灰 + 常规字重 |
| 学生端归类题框名 | `.zoneHead` 的 750 字重 + 深蓝 | 常规 + 深灰 |
| 教师看板 | 「未勾选=灰 / 勾选=粗」、标准答案那支专用蓝、框名与「未归类」的灰/橙 | 一律深灰常规 |

⇒ 判据收进 `promptTextStyle(run, plain)`（纯逻辑层，**有用例**）：`plain` 时返回 `undefined`。
⚠️ **题干仍然要写**（那是教师的行内格式，本来就该落在那段文字上）。

**公式切分接在现有的 `{表格域}` 切分旁边**（`PromptText` 里那段 `chunk.indexOf(TABLE_MARK_TEXT)`
的同一个位置、同一个模式）：先把 chunk 按 `splitMath` 切开，公式片段交给 KaTeX。
⇒ 公式与行内格式（粗/斜/下划线/着重号/颜色）可以共存：公式**本身**不继承选中格式
（KaTeX 自己画），它前后的文字照常继承。

组件里渲染 KaTeX 用 `dangerouslySetInnerHTML`（`rehype-katex` 也是这么干的）；
KaTeX 默认 `trust: false` ⇒ `\href` / `\htmlClass` 这类命令被禁用，输出是可信的。

### 判据层（`worksheet-paper.ts`）

`promptParts` 现在只切 `{表格域}`。**新增一种部件**：

PaperPromptPart = { kind:'text', text } | { kind:'table', rows } | { kind:'math', tex }

|------|------|-----------|
| `PaperQuestion.prompt` | `PaperPromptPart[]` | 已经有部件形状（要嵌表格）⇒ **只加一种 `math`** |

## 答案栏的公式与自动判分（裁定 ④ 把这里定死了 —— 已无待定项）

**已核**：填空题的判分是 `server/src/services/worksheet-questions.ts:804` `judgeFillBlank`，
逐一空比对：

```
acceptable.some((answer) => normalizeFillText(answer) === normalizeFillText(学生输入))
```

⇒ 教师在答案栏写 `$x=5$`，学生**必须原样输入 `$x=5$` 才算对**。学生打 `x=5` 判错。
而屏幕上一切正常：教师看到「正确答案：$x=5$」渲染得挺好看，**没有任何东西告诉他判分已经坏了**。
这是本仓最防的那一类缺陷（静默的错判），而且它会**印在教师用卷上发给全班**。

**裁定 ④ 的落地（这是定论，没有第二种做法）**：

- **显示**（教师用卷 / 看板 / 答错提示）：渲染成公式。
- **判分**：把答案文本里的公式**剥掉定界符**再用 —— `$x=5$` 的判分文本是 `x=5` ⇒
  学生打 `x=5` 判对 ✓。学生打 `$x=5$` 反而判错（学生端不解析公式，`$` 是普通字符）
  —— 这正是裁定 ④ 要的。
- 两边用**同一个 `splitMath`**（取 `math` 部件的 `tex` 拼回），不是两份实现 ⇒
  这与 `questionTextFor` 把 `{填空域}` 换成 `________` 是**同一种投影**，仓里有先例。

⚠️ 残留（要如实告诉教师）：`$\frac{1}{2}$` 的判分文本是 `\frac{1}{2}`，学生打不出来 ⇒
这种题本来就不该用自动判分（它是「看图说理」那类）。建议在编辑页答案栏旁边给一句提示。

### 🔴 选择填空是个例外：落词要按**判分口径**写进草稿（交付当天复审抓出来的）

上面那条推理（「学生打的 `$` 只是普通字符，所以剥掉定界符正好」）**对选择填空不成立** ——
**学生不打字**，他点的是**教师自己写的那个候选词**，`$` 是教师文本自带的。
判分侧剥了、学生侧没剥 ⇒ **他点对了却判错**，而「他点的那个词」与「正确答案」在屏幕上
渲染成**同一个公式**，看起来一模一样。

⇒ 落词（`place`）写进作答草稿的值必须是 `placedValue(word)`（= 剥掉定界符的那个口径），
判据住在 `src/lib/worksheet-fill-modes.ts`，**有用例**。
⚠️ 与「学生手打 `$x=5$` 要判错」**不矛盾**：那说的是学生**打**的字符，这里是**教师文本的引用**。

⚠️ **要动的判分入口不止一个**：`judgeFillBlank` 之外，**答错时发给学生看的正确答案**
（`correctBlanks`，消费者是 `match-body.tsx:366` / `choice-blank-answer.tsx:289` /
`choice-body.tsx:132`）与**教师端的标准答案显示**（`answer-view.tsx:115`）走的是**两套
投影**。判分那一套剥离定界符，显示那一套渲染公式 —— 这两套**必须都由 `splitMath` 派生**，
否则就是本仓最防的那种分叉。

## 🔴 施工时发现的一个**依赖库缺陷**（已绕行，但要知道它在那儿）

**`mathml2omml@0.5` 把文本原样塞进 `<m:t>`，一个字符都不转义。**

由「公式里的 `<` `&` 必须转义」那条用例抓出来的（它一开始就是红的）：

| LaTeX | `mathml2omml` 的输出 | 后果 |
|-------|---------------------|------|
| `$a<b$` | `<m:t xml:space="preserve">a<b</m:t>` | **非法 XML** |
| `$x \& y$` | `<m:t xml:space="preserve">&</m:t>` | **非法 XML** |
| `$a \le b$` | `<m:t>a≤b</m:t>` | 合法（走了 Unicode，没事） |

⚠️ **症状**：我们这一侧 `ImportedXmlComponent.fromXmlString` 用的是真 XML 解析器 ⇒ 它**抛** ⇒
`mathRun` catch 掉 ⇒ **那个公式在纸上降级成源码**（不是 Word 报「文件已损坏」——
那条路被 catch 挡住了，属于因祸得福）。
⇒ **教师在 Word 里看到某个公式变成 `$a<b$` 这样的源码时，根因在这里。**

**绕行**：`server/src/services/worksheet-paper-math.ts` 的 `escapeMathText()` —— 只动 `<m:t>`
（OMML 里唯一的**文本**节点，内容里没有嵌套标签 ⇒ 正则是安全的），`&` 用前瞻排除已有实体
（万一哪天上游开始转义，不会二次转义）。

## 明确**不做**（每一条都要让教师知道，否则他会以为「这里怎么没生效」）

- **原生 `<option>` 里的文本**（归类归属下拉、连线下拉的右项）：`<option>` 装不了元素，
  这是**物理上限**，不是取舍。
- **两行截断显示的地方**（编辑页左侧大纲 `page.tsx:523/547/571`、矩阵看板
  `matrix-overlay.tsx:302`）：截断一个公式比截断一句话更难看。
- **学生答案**：学生打的字里 `$` 没有公式语义（看板那一片两种文本混在同一组件里，
  见上面那条警告）。
- **任务标题 / 学习单标题 / 学习单描述**：它们是结构性的名字，不是题面内容。
  题号（`flattenAnswerable`）拿任务标题拼 `任务一 · 1`，让标题带公式会把题号也拖下水。
- **AI 分析载荷**（`analysis-payload.ts` / `analysis-agent.ts`）：题干以 **LaTeX 源码**
  发给 AI 是**好事**（模型读得懂），一个字都不用改。
- **`questionTextFor`**：它把 `{填空域}` 换成下划线给 Word / AI 用；公式**不在这里转**
  （它现在做的替换与本功能正交）。
