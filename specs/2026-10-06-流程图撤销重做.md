## 一、为什么是快照栈

三条路摆过：**A 快照**（每步存整份）· **B 命令栈**（每步存正+反向 patch）· **C 增量 patch**（引 immer 之类）。

选 **A**，理由是这仓里最容易出错的地方从来不是内存，而是**「有一处入口忘了接上」**：
B 要给十来种操作各写一对正反向，**漏掉任一种的表现是「撤销时那个动作被静默跳过」**；
A 天然免疫 —— 任何改动都体现在 `nodes`/`edges` 上，谁也漏不掉。

代价（每步存一份全量）对本场景可忽略：一个班的流程图也就几十个框，上限 50 步。
本仓已有对应物：手绘画板的撤销（`src/lib/worksheet-ink.ts:424` 的 `undoStroke`）本质上也是
「丢掉最后一笔」的快照思路，不是反向 patch。

## 二、纯逻辑单独成一个库

**新增** `src/lib/worksheet-flowchart-history.ts`（**纯函数**，不 import React、不 import `@xyflow/react`）。

对齐本仓既有的做法（`worksheet-ink.ts` 的撤销就是纯函数 + 用例）。导出：

```ts
export interface FlowSnapshot { nodes: FlowNode[]; edges: Edge[] }   // 结构类型，非 React Flow 的类
export interface FlowHistory { past: FlowSnapshot[]; future: FlowSnapshot[] }

export function emptyHistory(): FlowHistory
export function pushHistory(h: FlowHistory, prev: FlowSnapshot): FlowHistory   // 新操作：past 入栈、future 清空
export function undoHistory(h: FlowHistory, current: FlowSnapshot): { history: FlowHistory; snapshot: FlowSnapshot } | null
export function redoHistory(h: FlowHistory, current: FlowSnapshot): { history: FlowHistory; snapshot: FlowSnapshot } | null
export function canUndo(h: FlowHistory): boolean
export function canRedo(h: FlowHistory): boolean
export function flowchartSignature(nodes: FlowNode[], edges: Edge[]): string
```

- **`HISTORY_LIMIT = 50`**：超出丢**最老的**那一头。
- `undoHistory` / `redoHistory` 把「当前」推进另一侧栈 —— 这样撤销之后还能重做，且**新操作会清空 future**（标准行为）。
- ⚠️ 这些函数**必须返回新对象**（不改传进来的）—— 与仓里其他 lib 一致，也让测试能直接比。

## 三、`flowchartSignature`：什么算「一步」

**这是本次最容易做错的一处。** React Flow 的 `onNodesChange` 不只为「拖动」触发，
它**也为「选中」和「尺寸测量」触发**。不把这两类滤掉的话，学生**点一下框就等于做了一步** ——
撤销键会按空，而且按一次还看不出错（要按到第二次才发现「撤销的是刚才那次点击」）。

指纹**只取实质字段**：

| 取 | 不取 |
|---|---|
| 节点：`id` · `position.x/y` · `data.label` · `data.kind` · `data.locked` | `selected` · `measured` · `dragging` · `positionAbsolute` · `width/height` · `style` · `className` |
| 边：`id` · `source` · `target` · `sourceHandle` · `targetHandle` · `label` · `data.routeX/routeY` | `markerEnd` · `type`（这些是渲染时派生的，见 `visibleEdges`） |

⚠️ 指纹读的是**原始** `nodes`/`edges`，**不是** `visibleNodes`/`visibleEdges`
（后者被 `useMemo` 加工过 —— 加了 `locked`、`markerEnd`、高亮 `className`）。

## 四、组件里的三处接线（`flowchart-drawing.tsx`）

### 4.1 变化检测 —— 挂在已有的那条 effect 旁边

画板已有一条 effect 盯 `[nodes, edges]` 干汇报的活（`:622` 的 `const payload = toFlowPayload(...)`，
末尾调 `onChange`）。**紧挨着它**加一条同依赖的 effect：

```
指纹 == lastSigRef ? 什么都不做
: 拖动中(draggingRef) ? 什么都不做          // 拖动中**不更新** lastSig —— 见 4.2
: 否则 → pushHistory(lastSnapshotRef)      // 压的是**变化前**那一份
       更新 lastSigRef / lastSnapshotRef
```

⚠️ **顺序要紧**：`pushHistory` 必须在更新 `lastSnapshotRef` **之前**调用，压的才是上一份。

### 4.2 拖动合并成一步

`<ReactFlow>` 上**现在没有** `onNodeDragStart/Stop`（已核，`:1268` 起那段），要新挂：

- `onNodeDragStart` → `draggingRef.current = true`
- `onNodeDragStop` → `draggingRef.current = false`

拖动期间 effect 每次 `mousemove` 都会跑，但**只 return、不动 lastSig** ⇒
松手后那一次 effect 比的是「拖动前 vs 拖动后」，**恰好压一步** ✓

### 4.3 撤销 / 重做

```
undo():
  step = undoHistory(historyRef.current, { nodes, edges })
  step 为空 → return                       // 栈底，什么也不做
  historyRef.current = step.history
  setNodes(step.snapshot.nodes); setEdges(step.snapshot.edges)
  setSelected(null); setLabelingEdge(null)  // 清掉指向已消失元素的选择态
  🔴 同步 lastSigRef / lastSnapshotRef = 撤销后的值
```

🔴 **最后那一步是硬要求**：不同步的话，4.1 那条 effect 会把「撤销」本身当成一次**新操作**
⇒ 压栈 ⇒ 触发 effect ⇒ …… **死循环**，而且屏幕上表现为「撤销一下、图又弹回去」。

## 五、UI 与快捷键

- 工具条上两颗按钮：`撤销` / `重做`，**文案与思维导图逐字一致**（`mindmap-drawing.tsx:351-352`）。
- 位置：挨着「恢复初始图」（`:1238`）—— 同属「往回退」的语义。
- `disabled={disabled || !canUndo(history)}`（重做同理）。组件里另存一个 `historyVersion`
  自增来触发按钮重渲染（history 存在 ref 里，不进 state —— 它不参与渲染，只有按钮的可用性要看它）。
- 快捷键挂 `window` 的 `keydown`：
  - `(metaKey || ctrlKey) && key === 'z'` → 撤销；加 `shiftKey` → 重做。
  - 🔴 **焦点在输入框里时一律不管**：框内文字（`:185` 那个 input）与线上标注（`:1261` 那个 input）
    里，`Cmd+Z` 该走**浏览器原生的撤销打字**。抢过来会让学生在自己刚打的字里没法撤销。
    判据：`event.target` 是 `INPUT` / `TEXTAREA` / `isContentEditable` ⇒ 直接 return。
  - `disabled` 时整条不挂。

## 六、明确不做的事

  🔴 **2026-10-06 当天撤销了这条**：全屏必须走 `createPortal(content, document.body)`（见 §十一），
  而 portal 切换会让 React **重挂整棵子树** ⇒ 画板实例重建 ⇒ 住在 `useRef` 里的撤销历史归零。
  解法是把历史挪到**模块级的表**里、按一个**跨挂载稳定的 key** 索引 —— 那个 key 只能由宿主给
  （`drawing-tool-body` 手里才有题目 id）⇒ 接口**必须**加一个字段。
  落地：`historyKey?: string`（**可选**，不传就是组件内的一份，行为与从前完全一样）。
- **不动 `disabled` 的语义** —— 裁定 ② 选了「回顾态不能撤销」，而 `<ReactFlow>` 在 `disabled` 时
  本来就把 `onNodesChange`/`onEdgesChange` 全摘了（`:1273-1274`）⇒ 天然不可撤销，一个字都不用改。
- **不动快照与导出** —— 撤销后的内容经**已有的** `onChange`（`:622` 那条 effect）汇报出去，
  自动就是对的。`worksheet-flowchart-svg.ts` 读的是那一刻的 `lastFlow`，不必知道撤销的存在。
- **不持久化** —— 刷新页面历史清空。（要持久化是另一个话题，见 §十。）

## 十一、✅ 当天补的一条硬结论：**全屏必须走 portal**

（这条不在原设计里 —— 是施工中被教师在真机上逼出来的。**它与 §六 的接口结论直接相关**。）

**事实**：`drawing-tool-body.tsx` 的全屏本来是 `createPortal(content, document.body)`；而全屏态的
CSS `.thirdPartyWorkspaceMaximized` 又写着 `position: fixed; inset: 0`。施工中我曾判定「后者才是
干活的、portal 是冗余的」，删掉 portal 只用 CSS —— **真机当场打脸**：全屏那层只覆盖题目卡那么大、
根本没铺满，还盖住了旁边的画板（教师原话：「有点像一层层递归进去了」）。

**根因**：`position: fixed` 在祖先带 `transform` / `filter` / `backdrop-filter` / `contain` /
`will-change` **任一**属性时，会**退化成相对那个祖先**。我翻遍 `worksheet` / `shell` / `globals`
三个样式表也没定位到是哪个祖先干的 —— **但 portal 到 `body` 能绕开这一切**（body 之上没有祖先劫持它）。

**所以**：那两段代码**各干一半的活** —— CSS 给的是*定位基准*，portal 给的是*脱离祖先*。
它们**并存必需**，不是冗余。判据 `flowchart-history-wiring.test.ts` 钉着「必须 portal 到 body」。

**代价与解法**：portal 切换 ⇒ React **重挂**整棵子树 ⇒ `useRef` 里的历史归零。解法见 §六
（接口加 `historyKey`）与 `worksheet-flowchart-history.ts` 的 `loadHistory` / `saveHistory`。

🔴 **给下一个人的一句话**：看到「两段代码好像在做同一件事」时，**别假定有一段是冗余的** ——
先去真机上把它删掉试一次，再决定。
