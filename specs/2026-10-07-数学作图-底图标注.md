# 数学作图 · 底图标注

> 状态：**spec 待教师确认**（2026-10-07）。确认后才写实现计划。
> 起因（教师原话，2026-10-07）：
> 「我感觉目前这个组件所提供的绘图功能太专业了。其实对于中小学学生来讲，不需要绘制这么精准的
>  数学图形，他们更多的是用图形来思考问题，比如说，教师把某一道几何题的原图作为底图给他们，
>  他们可以方便地在这个图形上添加辅助线、标注角度、标注一些特殊的信息，便于他们思考就可以了。」
> 补充：「学生除了在底图上面加辅助线信息等需求外，也有可能在空白的画布上面自己做图，
>  但是这个图形不会做得非常的复杂。」

---

## 一、要解决什么

教师要走的是**底图路线**：教师上传几何题原图 → 学生在**位图**上标注。

核查后发现这条路的主链路**是断的**，而且断在一个看不见的地方：

1. 🔴 **底图进不了快照。** 抓图是 `host.current.querySelector('canvas').toDataURL('image/png')`
   （`math-drawing.tsx:99-103`）—— 只抓 jsxgraph 那块 canvas；而底图挂在**外层 div 的
   CSS `background-image`** 上（`:682`）。⇒ 学生画完，**教师看板那一格**与**发给 AI 的联系表**里
   是「一堆悬空的线，几何图不见了」。教师看不懂学生在说什么，模型更看不懂。
2. 🔴 **底图不跟着画板动。** 画板允许双指平移、滚轮缩放（`:154-155`），而 CSS 底图钉死不动。
   ⇒ 学生只要放大看一眼，「图」与「我画的线」就**错位** —— 而两边都不报错。
   ⚠️ 这一条对**教师那个用法是致命的**：在图上描辅助线，对齐是全部意义。
3. ⚠️ **底图被硬拉成 5:4。** `.thirdPartyCanvas { background-size: 100% 100% }`
   （`worksheet.module.css:2561`）⇒ 教师传的原图比例一变就**变形**。
4. **缺「几何记号」。** 学生要标直角、标相等、标平行、写度数，现在只有「铅笔」——
   手画的小方块歪了就不像记号，而方不正在几何里是**有含义的**（直角）。
5. ⚠️ **端点一直可见。** 每条线段两端都挂着一个白底蓝圈的点（`mkPoint`，`:158`）——
   学生只是画了条线，看起来却像"标了两个点"。而这条同时污染**快照**（教师与模型看到的是
   "一条线 + 两个点"）。

## 二、教师的决定（逐条照办，不再讨论）

| # | 决定 | 口径 / 代价 |
|---|---|---|
| 1 | **走底图路线** | 教师上传几何题原图当底图，学生在位图上标注。**不采用**「教师用画板把图画一遍当初始图」那条（那一档现在也只有流程图/思维导图接了底稿） |
| 2 | **保留五个图形工具** | 三角形 / 长方形 / 平行四边形 / 梯形 / 圆。教师：「学生还是有基本的作图需求的」（他们在**空白画布**上自己画时用） |
| 3 | **砍掉「平行线」「垂线」** | ⚠️ 代价：想作一条精确的平行线/垂线只能手画。理由见 §三-B |
| 4 | **砍掉「角」** | 它画「两条臂 + 一段弧」，而底图上那两条边**已经在图里**，再描一遍是多余的。由新的「角弧」顶替（**同形**：点三下，只画弧）。⚠️ 代价：在空白画布上要画一个完整的角，得用两次「线段」+ 一次「角弧」 |
| 5 | **「度数」不是独立按钮** | 做成「角弧」自带的输入框（像「文字」那样，可留空）。🔴 **不自动量角** —— 题目里的角度是**已知条件**，学生要写的是 30，不是让我们量出个 47 来 |
| 6 | **要一组几何记号** | 直角□ / 等号 / 平行∥ / 角弧 —— 教师的理由：「这是几何题的行话」 |
| 7 | **线段两端的点只在选中时出现** | 不选中时它就是一根看不见端点的线条 |
| 8 | **预设背景先不动** | 教师：「这个功能我可能在后期会砍掉」⇒ 保持现状（继续走 CSS 铺满），**只把「自定义」底图接进画板** |

**两处我自己提议、后来自己撤回的**（记在这里，免得以后有人当成漏了）：

- 我一度建议**把「点」并进「文字」**（点一下不输字 = 落一个点，输了 = 落字母）。撤回：那会让
  一个按钮有两种形态，而「文字」本来就带一个输入框，合并后形态更难说清。**「点」独立保留。**
- 我一度建议**砍掉五个图形工具**（理由："标准图形多给的是精确度，不是表达能力"）。教师纠正：
  「学生还是有基本的作图需求的」。我错在把"不复杂"读成了"不需要整洁"—— 学生手画的长方形
  **是歪的**，那不是"复杂"，是"画不成"。**保留。**

## 三、设计

### A. 工具条：删 3 个、加 4 个，净 +1

```
基础    [选择] [点] [线段] [射线] [圆]
多边形  [三角形] [长方形] [平行四边形] [梯形]
标注    [角弧] [直角□] [等号] [平行∥]        ← 「角与线」那一组整个换成这个
其他    [铅笔] [文字]          [撤销] [清空] [放大 缩小 复位]
```

- **删**：`parallel`（平行线）、`perpendicular`（垂线）、`angle`（角）
- **加**：`angleArc`（角弧）、`rightAngle`（直角记号）、`equalMark`（等号）、`parallelMark`（平行∥）
- 分组数据 `MATH_TOOL_GROUPS` 里 `{ value: 'angle', label: '角与线' }` → `{ value: 'mark', label: '标注' }`
- ⚠️ **「选择」从「其他」挪到「基础」第一位**（教师在这份设计里看到的排法就是这样）。
  目前它在 `other` 组（`worksheet-math-shapes.ts:70`）。挪的理由：它是**每一个工具的出口**
  （画错了要能选、能删），排在第一个比排在最后一行更好找。

⚠️ **删工具不许孤儿化存量作答**（已核，见 §五）：平行线/垂线产出的是 `kind: 'line'`，与「直线」
**同一种** entry；「角」产出的是 `kind: 'angle'`。**两者的渲染分支都留着**，只是不能再新画。
⇒ **不需要任何数据迁移。**

### B. 四个记号：全部「点 N 个位置」，不依赖画板里已有的对象

🔴 **这一节是整份设计的关键。** 我最初把「等号」「平行∥」设想成"点一下那条线段" ——
**那就犯了跟平行线/垂线一模一样的毛病**：底图上的边**不是画板对象**，学生点了 `AB` 什么都不会
发生。而这两个记号正是教师明确要的。

⇒ 四个记号**一律"点 N 个位置"**，与现有的 `clicks` 机制**完全一致**，一格新交互都不用发明：

| 记号 | `clicks` | 点在哪 | 出来什么 |
|---|---|---|---|
| **等号** | 2 | 沿那条边点两下 | 中点一道短斜线，**垂直于**这条边（两下就知道方向了） |
| **平行∥** | 2 | 沿那条边点两下 | 中点一个双箭头，沿这条边的方向 |
| **角弧** | 3 | 边1上一点 → **顶点** → 边2上一点 | 一段弧（**不画那两条臂**）；输入框填了就顺带写上度数 |
| **直角□** | 3 | 边1上一点 → **顶点** → 边2上一点 | 角内一个小方块（要两个方向才定得下来，所以是 3 下） |

🔴 **三个点的点击顺序统一为 `[a, vertex, b]`（顶点在第二下）**，两个 3 击记号**一模一样**。
理由：① 与现有「角」**同形**（`buildEntry` 的 `case 'angle'` 就是 `[ats[0], ats[1], ats[2]]` ⇒
`[a, vertex, b]`），学生不用学新的；② 两个 3 击记号若是**两种顺序**，学生一定会点错，
而点错的表现是"记号长到了错的地方"—— 不报错，只是不对。
⚠️ **数据形状里字段的书写顺序**（`vertex` 写在前面）与**点击顺序**是两件事，
别把它们混成一条 —— 点击顺序看的是 `ats` 的下标。

**这一改带来一个额外的好处**：改完之后这一档**所有工具都不再依赖"画板里已有什么"**
（唯一例外是「选择」，它本来就是干这个的）。⇒ **底图上与空白画布上行为完全一致**，
不需要任何"按有没有底图"的分叉。**平行线/垂线被砍掉，现在逻辑上是自洽的** ——
它是这一档唯一一个"要先有别的图形才能用"的工具。

⚠️ **退化输入必须挡住**（否则出一个 NaN，整张图就毁了）：学生两下点在同一处、
或三下里有两点重合 ⇒ 方向向量是 `[0,0]` ⇒ 短斜线/箭头/方块算出来是 `NaN`。
现有的**拖动类**工具有一道最近的先例：`Math.hypot(end - start) < 0.3` 就不成形（`:543`）。
四个记号走**同一条尺子**（纯函数里判断，回 `null` ⇒ 不成形、不落数据），
⚠️ 而不是各写一遍 —— 四份阈值迟早对不上。

**数据形状**（加进 `MathEntry`，`worksheet-math-shapes.ts`）：

```ts
| { kind: 'angleArc'; vertex: Pt; a: Pt; b: Pt; text?: string }
| { kind: 'rightAngle'; vertex: Pt; a: Pt; b: Pt }
| { kind: 'equalMark'; a: Pt; b: Pt }
| { kind: 'parallelMark'; a: Pt; b: Pt }
```

⚠️ **`angleArc` 是新 kind，不复用 `angle`。** 复用的话就分不出"老作答（含两条臂）"与
"新作答（只有弧）"，而老作答里的臂**必须照旧画出来**（那是学生当时画的东西）。

### C. 线段两端的点：只在选中时出现

- `mkPoint`（`:158`）**拆成两个工厂**：
  - `mkHandle` —— 图形的端点/圆心/角顶点。`visible: false`。
  - `mkMark` —— **一直可见**。给两种东西用：① 多击工具构造过程中的**待定点**
    （`:396`，它是"你已经点了两下"的反馈）；② 独立的 `kind: 'point'`（那个点**就是**作答本身）。
- `applySelection`（`:286`）重画之后，把**选中那一条**的 `points` 设 `visible: true`，并**放大**
  （它现在是唯一的抓手，iPad 上要抓得住；现在的 `size: 3` 太小）。
- 独立的「点」用 `mkMark` ⇒ 它永远可见，不受选中影响。

🔴 **为什么这个改法干净**：jsxgraph 把「看不见」和「抓不到」绑在一起了 ——
`Board.getAllObjectsUnderMouse` 的第一道判断就是 `visPropCalc.visible`
（`src/base/board.js`，产物 `jsxgraphcore.js` 里同名函数）。所以**不需要**额外写
「未选中时禁用拖动」那种第二套判断（两处各写一遍必然分叉）。
⚠️ 已核的是**命中测试**那一处；「不可见的点也拖不动」要在真机上确认一次（见 §六-5）。

**顺带**：画布因此与另外两处**终于一致**了 —— 教师预览 `MathPreview` 从来不画端点，
而快照会画（它抓的是画布位图）。改完：**学生看到的 = 教师看到的 = 模型看到的**。

### D. 底图进画板（最贵的一节）

**做法**：把「自定义」底图从 CSS `background-image` 改成**画板里的一个 image 对象**
（`board.create('image', [url, [x1,y1], [x2,y2]], attrs)`）。

**为什么必须是画板对象**（三条，缺一都不够）：

1. ✅ **进快照**：jsxgraph 的 canvas 渲染器真把 image 画进 2D context
   （`CanvasRenderer.updateImage` 里那句 `e.drawImage(t.rendNode, …)`，已核）⇒ 抓图自然带上它。
2. ✅ **跟着缩放平移**：它的矩形是**用户坐标**，画板动它就动 ⇒ 对齐在任何缩放下都成立。
   ⚠️ 这一条才是教师那个用法的**全部意义**（在图上描线）。
3. ✅ **不变形**：摆位由我们给的两个角决定，不再被 `background-size: 100% 100%` 硬拉。

**取图必须绕开跨域污染**：

- `fetch(worksheetAssetUrl(url))` → `blob()` → `URL.createObjectURL(blob)` → 把这个
  **同源 blob URL** 喂给画板（卸载时 `revokeObjectURL`）。
- 🔴 **不能直接把 URL 喂进去**：dev 下页面在 `:4000`、图片在 `:4001`（`worksheetAssetUrl`
  就是这么拼的，`api-base.ts`）⇒ 跨域图画进 canvas ⇒ canvas **被污染** ⇒
  `toDataURL()` **抛 SecurityError** ⇒ 被 `safeCapture` 吞掉 ⇒ **快照静默全废**，
  而屏幕上什么都不说（正是本仓最怕的形状）。
- ✅ 生产是同源，本来没这个问题 —— 但**教师是在 dev 里验的**，所以必须处理。
- ✅ 服务端 CORS 是 `origin: true`（`index.ts:102`，且排在 `/uploads` 静态挂载 `:120` 之前）
  ⇒ dev 下 `fetch` 能通。
- ⚠️ **预设背景不受影响**：它们由 Next 从 `public/` 发，**同源**。（这一版也不动它们。）

**摆位**：`contain` + 居中，放进**现有的单位框 `[-10, 8, 10, -8]`**（20×16 = 5:4）。

- 🔴 **单位框不许动**：`MathPreview` 的投影是**硬编码**的
  `((x + 10) / 20) * width, ((8 - y) / 16) * height`（`drawing-document-preview.tsx:67`）。
  改框就要改它，而存档里的坐标全是按这个框存的。
- ⚠️ 代价：教师传的图比例与 5:4 差得远时，两侧（或上下）**留白**。留白是可见、可理解的
  （"老师给的图比画布窄"），比**变形**好。
- 这个换算必须是**纯函数**（`backgroundRect(box, imageAspect)`，住 `worksheet-math-shapes.ts`）
  并有用例 —— 它是"图摆放得对不对"的唯一定义处。

**🔴 底图不进命中测试 —— 这是这份 spec 里最危险的一处。**

`Image.hasPoint` 是"**点在矩形里就算**"（`src/base/image.js:130-157`，逐字核过），而底图铺满
整块画布 ⇒ 它会被 `getAllObjectsUnderMouse` 返回，并且因为它在 `objectsList` 里排在**最前**
（创建顺序 = 绘制顺序），`hits[0]` **就是它**。后果两条，都是致命的：

- 「选择」工具：`hits[0]` 是底图 ⇒ `runtime.current.findIndex(…)` 回 `-1` ⇒
  **学生永远选不中自己画的线**；
- **所有绘图工具彻底失效**：`handleDown`（`:354`）与 `onDragDown`（`:505`）都有一句
  `if (board.getAllObjectsUnderMouse(event).length > 0) return;`（本意是"点到既有图形就让内核
  去拖它，别新建"）—— 底图在场时这句**恒为真** ⇒ **每一次点击都什么都不发生**。

⇒ **三处调用必须走同一个过滤器**（一个函数、一处定义），把底图按**对象身份**滤掉：

```ts
/** 底图不是学生能碰的东西 —— 理由与实测见上。三处命中判断共用它。 */
const studentHitsUnderMouse = (event: PointerEvent) =>
  board.getAllObjectsUnderMouse(event).filter((object) => object !== backgroundObject);
```

⚠️ **不依赖"库今天会不会返回它"**：将来库改了 `Image.hasPoint`，这条过滤照样成立
（与"思维导图那条工具条用库自己的 id、并对拍库产物"同一个纪律）。
**用例要钉住三处都走它**，而不只是其中一处。

**顺序：靠 `layer`，不靠创建先后**（★ 写计划时核实，推翻了我先前那句"必须最先建"）：

- 我原本担心"取图是异步的 ⇒ 底图建成时排在学生那些对象**后面** ⇒ 盖住学生的作答"。
- ✅ **实际不用管顺序**：canvas 渲染器绘制前会按 `layer` 排序 ——
  `board.js` 的 `objects_sorted = this.objectsList.filter(…).toSorted(_compareDepth)`，
  而 `_compareDepth` 的**第一句**就是 `a.visProp.layer - b.visProp.layer`（小的画在后面）。
  同一层内才回落到创建顺序（`a._pos - b._pos`）。
- 而 `layer` 是**公开属性**（`index.d.ts:1032-1034`：「Display layer which will contain the element.」
  `layer?: number`，默认 0）⇒ **给底图 `layer: -1` 即可**，与库内部实现无关。
- ✅ 于是 `renderAll(readEntries(data))` **照旧在挂载时立即执行**（学生已有的作答马上就看得见），
  底图等 blob 到了再建，**不需要二次 `renderAll`、也不会出现一块空白画板**。
- ⚠️ 学生自己那些对象全在默认层 0 ⇒ 彼此的先后**与今天完全一样**（同一层比 `_pos`）。
- ⚠️ 底图**不进 `runtime.current`** ⇒ 「清空」与撤销栈**碰不到它**（学生清不掉老师给的图）。

### E. 教师端的预览要跟上

- `MathPreview`（`drawing-document-preview.tsx:65-131`）要加**四个新记号**的渲染 ——
  少了它们，学生标的直角/等号/平行**在教师这里完全看不见**（而学生画板上明明有）。
  坐标口径与画板完全一致（`data.elements` 里就是普通坐标数组）。
- 它现在把底图画成 `<image … preserveAspectRatio="none">`（**铺满**，`:46`），而画板改成了
  **contain 居中** ⇒ 两处会不一致。**改成 `xMidYMid meet`**，一行的事。
  ⚠️ 这一支只在**快照缺席**时才用（`:181`），但"教师偶尔看到的是另一张图"正是本仓反复吃亏的形状。
- ⚠️ `MathPreview` 里那条硬编码投影**不动**（理由见 §三-D 的摆位）。

## 四、不动什么（防止顺手扩大范围）

- **不动预设背景**（点阵/小方格/田字格/横线/坐标纸/数轴）：继续走 CSS 铺满。教师说先不管，
  后期可能整个砍掉 —— 这一版**不碰**。（⇒ 今天快照里是什么样，改完还是什么样：预设本来就不进快照。）
- **不动 `drawingTool` / `drawingBackgroundPreset` / `drawingStarter` 这些字段的读写口径**，
  不给数学作图加「初始图」（教师这次选的是底图路线）。
- **不动服务端**：它不渲染数学作图（只发 `drawing.image` 那张位图，`analysis-payload.ts:131`）。
  ⇒ 快照一修好，服务端**一行都不用改**。
- **不动坐标框与存档格式**：`data.elements` 的六个老 kind 一个不改；新记号是**追加**。
- **不动教师端的底图上传入口**（`bodies/drawing-settings.tsx` 的「自定义」）—— 它已经在了。
- 不给数学作图做「按有没有底图决定显示哪些工具」的分叉（§三-B 之后**不需要**了）。

## 六、判据（每条都要变异验证）

1. **底图是画板对象，不再是 CSS**：源码级 —— 有 `board.create('image', …)` 且带 `layer: -1`
   （顺序不靠创建先后，见 §三-D），并且**没有** `backgroundImage` 那一条；
   反面对照：把其中任一条改回去 ⇒ 判据红。
   ⚠️ 再加一条：`renderAll(readEntries(data))` **仍在挂载时同步执行**（不许为了等底图把它挪到 `await` 后面
   —— 那会让"重新打开一道题"先看到一块空白画板）。
2. **三处命中判断都滤掉底图**：`handleDown` 的选择分支、`handleDown` 的早退守卫、
   `onDragDown` 的早退守卫 —— 三处**都用** `studentHitsUnderMouse`；
   反面对照：任一处改回 `board.getAllObjectsUnderMouse` ⇒ 红。（**三处分别钉**，合并成一条会漏。）
3. **摆位是纯函数且对**：`backgroundRect(box, aspect)` —— 4:3 的图放进 5:4 的框 ⇒
   **居中、左右留白、比例不变**；正方形、超宽、超高各一条。
4. **端点**：`mkHandle` 默认 `visible: false`（源码级）；`mkMark` 不带；
   `applySelection` 里把选中那一条的点设可见；反面对照：待定点若改用 `mkHandle` ⇒ 红
   （那会让"你已经点了两下"的反馈消失）。
5. **不可见的点拖不动**（真机走查项，交给教师）：画一条线段 → 不选中时端点看不见；
   点它一下 → 端点出现且能拖；「选择」能选中它（**这条钉的是 §三-D 那个过滤器的另一半**）。
6. **存量作答不许变空白**：喂一份含 `kind: 'angle'`（老「角」，带两条臂）与 `kind: 'line'`
   （老平行线）的作答 ⇒ 两样都照旧画出来。
7. **三个删掉的工具一处都不剩**：工具表、图标表、提示语、几何实现里都没有
   `parallel` / `perpendicular` / `angle`（工具）的入口；`lineThrough` 若还留着就是**死代码** ⇒ 红。
8. **四个新记号的换算**（纯函数单测）：等号中点+垂直方向；平行∥ 沿边方向；
   直角□ 从三个点定出两个方向；角弧的三点顺序固定为 `[a, vertex, b]`（与老 `angle` 同一约定）。
9. **记号的 `clicks` 与工具表一致**：`MATH_TOOLS` 里四个新工具的 `clicks` 与需求一致
   （等号/平行∥ 是 2，直角□/角弧 是 3），且每个都有非空图标。
10. **教师预览跟上**：`MathPreview` 有四个新 kind 的分支（逐个点名）；
    底图那处 `preserveAspectRatio` 是 `xMidYMid meet`。
