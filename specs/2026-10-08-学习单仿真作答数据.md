## 二、现有工具：`scripts/seed-worksheet-demo.mjs`（**复用它，别另写**）

用法（仓库根）：
```bash
npx tsx scripts/seed-worksheet-demo.mjs --classroom 5018 --dry      # 干跑
npx tsx scripts/seed-worksheet-demo.mjs --classroom 5018            # 写库
# 另有 --seed <n> 换随机数、--keep 追加不清旧、--python <path> 指定渲染照片的解释器
```

它的设计里**必须保留**的四条（文件头逐字写了，别推翻）：

1. **判分三列由服务端自己的 `grade()` 算**（`isCorrect` / `gradeState` / `score`），脚本一行判分都不写。
   自己写一遍 ⇒ 脚本算的对错与看板显示的不是同一个东西，**两边都不报错**。
2. **题干与正确答案从 `Worksheet.content` 现读**，不在脚本里抄一份题面。
3. **只写两张表**：`WorksheetResponse` + `WorksheetAnswer`。不碰 `Worksheet` / `Classroom` / `Student`。
4. **照片作答**（`inputMode: 'photo'`）必须渲染成**真 PNG** 落进上传目录 ——
   AI 分析会把那个 URL **真的读成图**（`analysis-render.ts` → `resolveLocalPath`）。
   渲染失败就**整体不写库**（宁可没数据，也不要一批指向空文件的照片作答）。
   ⚠️ 依赖 Pillow：本机 `python3 -c "import PIL"` 已确认 **12.2.0 可用**。

它支持 `--dry`、`--seed`、`--keep`；分级是 `high / mid / low` 三档。

## 三、三个拦路石（上一轮实际撞到的）

### ① 绘图生成器是**照演示单写死的**

`scripts/seed-worksheet-demo.mjs:479-482`
```js
function genDrawing(node, tier, ctx) {
  if (/折射|光路|入射|法线/.test(node.prompt ?? '')) return genLightPathAnswer(tier, ctx);
  return genBarChartAnswer(tier, ctx);   // ← 其余一律当条形统计图，数据还写死 [6,4,5,3]
}
```
⇒ 这份单的 7 道绘图题会被**全画成条形统计图**。那是假数据：AI 分析读到"学生画的长方形"
其实是一张柱状图，**分析结论会失真**，而这正是教师最看重的一项。

### ② 思维导图 / 流程图的作答**不是笔迹**

这两档的作答值是**结构化数据**（`{nodeData:{…}}` / `{nodes:[],edges:[]}`），不是 `ink` 笔画。
脚本没有这两档的生成器；硬塞笔迹进去，AI 分析读到的是格式不对的东西。
- 空底稿形状的唯一真源：`src/lib/worksheet-drawing-starter.ts` 的 `blankStarterFor`
  （`flowchart` / `mind-map` / `math` 各一份；`free` 返回 `null`）。
- 库里**有真实的 `drawingStarter` 样例**可抄形状：拿 `
  SELECT content FROM Worksheet WHERE title LIKE '%科学%'` 里 `type='drawing'` 的 `data.drawingStarter`。


- 脚本只在顶层 catch 打印一句（`scripts/seed-worksheet-demo.mjs:743`），**没有堆栈** ⇒
  先给它加一条 `console.error(error.stack)`（或临时改成 rethrow）再跑，这是第一步。
- 上一轮**已排除**两处（都有保护，不是它们）：

### 🔴 本轮新发现（原来不知道的）

1. **`math` / `free` / `mind-map` / `flowchart` 四档的 `strokes` 恒为 `[]`**，
   而服务端渲染不了 `drawing.data` ⇒ **AI 分析的唯一入口是 `drawing.image`**。
   没有它，联系表里那一格是**空的**，且生成载荷那一步**不报错**。
   ⇒ 新加 `scripts/lib/answer-snapshots.mjs`：把学生那幅图渲成真 PNG。
   （流程图**复用**产品的纯函数 `worksheet-flowchart-svg.ts`，不另写。）
2. **快照画的是「底稿 + 学生画的」，作答只存学生那份**（数学/流程图两档）。
   第一版把两者混为一谈 ⇒ 第 2、3 题的**坐标系（在底稿里）整块不见**，图上只剩悬空的柱子。
3. **底稿归属两档相反**：`math`/`flowchart` 要**剥掉**底稿（`publish()` / `subtractFlowchart`），
   `mind-map` **整棵树含底稿根**都是学生的（`mindMapOrStarter`）。
4. **导图没有"空白作答"这个值**：它不抓首帧快照 ⇒ 学生不动 ⇒ 提交按钮按不动。
   造一个空树出来是**学生交不上来的形状**。（流程图相反：有首帧快照，"只交底稿"是真实值。）
5. `ctx.blankInk` **只置真不复位**（`ctx` 是整个学生共用的）⇒ 第一道绘图题一旦掷中，
   这个学生**后面每道绘图题全交白卷**。看着像有意的，其实是漏了复位。已改成逐题判。
6. `done` 判的是 `limit` 而不是**实际答了几题** ⇒ 中途停下的人被标成「已交」，
   而教师看板那一列「已交 N/M」读的就是它。已改成按实际作答数判。
7. **联系表上的标签是学生真名**（`payloadLabels` → `participantLabel`），
   而 `anonymizer` 只作用于**文本**、洗不了图里烤进去的字。
   ⇒ 发给第三方平台的图**带着学生姓名**。这是产品既有行为，**没有动它**（隐私红线归教师定）。
